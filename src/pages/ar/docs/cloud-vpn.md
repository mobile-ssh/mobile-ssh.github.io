# الأجهزة الافتراضية السحابية وwg-easy

أنشئ جهازًا افتراضيًا يعمل بنظام Linux في حسابك السحابي وشغّل VPN من نوع WireGuard باستخدام wg-easy. في إصدارات Android المتوافقة، تستطيع الإضافة المنشورة **VPN Setup** إنشاء الجهاز وتثبيت wg-easy واستيراد عميل ضمن مسار إعداد إرشادي واحد. ويمكنك أيضًا إنشاء الجهاز من لوحة تحكم المزود وتثبيته عبر Mobile SSH، أو استخدام خادم عام موجود.

**التوفر — 19 نوفمبر 2026:** نُشرت **VPN Setup 1.0.7** في [كتالوج الإضافات الافتراضي](https://github.com/mobile-ssh/mobile-ssh-plugins/tree/main/plugins/vpnsetup). يتطلب الإعداد الأساسي جسر الإضافات **1.3.0**، وتحديث الخادم **1.4.0**، وحذف السجلات المكتملة المؤهلة **1.5.0**. يعتمد التوفر على إصدار Android المثبت وقناة النشر؛ نشر الإضافة لا يؤكد توفر إصدار معين من التطبيق لك. لم يثبت توفر أتمتة مماثلة على iOS. استخدم تعليمات لوحة التحكم والتثبيت اليدوي أدناه عند عدم توفر الإضافة.

## اختر مسار الإعداد الإرشادي أو اليدوي

- **الإنشاء عبر API السحابة:** تستخدم VPN Setup حسابك لدى المزود لإنشاء الجهاز وموارد الشبكة، وتحفظ اتصال SSH، وتثبّت wg-easy وتستورد عميلًا. وتحتفظ بمعرّفات الموارد وسجلات الملكية لتنظيفها لاحقًا.
- **الإنشاء في لوحة تحكم السحابة أو استخدام خادم موجود:** أنشئ الجهاز بنفسك ثم قدّم عنوان IPv4 العام واسم مستخدم SSH والمفتاح إلى VPN Setup، أو اتبع التثبيت اليدوي أدناه. لا تحتاج الإضافة إلى بيانات اعتماد API السحابة للتثبيت على خادمك.

تجمع الإضافة المنشورة بين إنشاء الموارد والتثبيت؛ وما زالت الإضافات المنفصلة لكل مهمة بنية مخططًا لها. تختلف طريقة حذف الموارد المنشأة عبر API عن الخوادم التي توفرها بنفسك، كما هو موضح أدناه. اجتاز اختبار فعلي موثّق على Hetzner مراحل الإعداد وحركة VPN وإدارة العملاء والإدارة الخاصة والتنظيف على محاكي Android. لا يثبت ذلك نجاح الاختبار الفعلي مع كل مزود أو سياسة حساب أو هاتف حقيقي.

## جهّز حسابك وإعدادات الخادم

1. فعّل حسابًا سحابيًا والفوترة، واختر منطقة، وتحقق من حصص الأجهزة والأقراص وعناوين IP العامة. راجع رسوم المزود الحالية للأجهزة وIPv4 والتخزين وحركة البيانات؛ لا نفترض توافر فئة مجانية.
2. لهذا الدليل، اختر جهازًا مخصصًا بنظام **Ubuntu 24.04 LTS** وبحد أدنى **1 GB من الذاكرة و20 GB من القرص**، بمعمارية **amd64 أو arm64**. هذه خيارات أساسية لهذا الإعداد، وليست حدًا أدنى عامًا لـwg-easy. استخدم حساب دخول بصلاحيات root أو sudo؛ فالتثبيت دون تدخل يتطلب رفع صلاحيات غير تفاعلي.
3. اختر مفتاح SSH أو ولّده، واحتفظ بالمفتاح الخاص داخل Mobile SSH. ارفع المفتاح العام فقط إلى السحابة. يتطلب مسار استيراد Lightsail مفتاح SSH من نوع RSA. للمزودين والصور الأخرى أنواع مفاتيح مقبولة خاصة بهم. يدعم عميل SSH الحالي على iOS مفاتيح Ed25519/ECDSA الخاصة بدلًا من مفاتيح RSA الخاصة. لاستخدام Lightsail على iOS، استخدم أولًا لوحة SSH في متصفح المزود لإضافة مفتاح عام يدعمه التطبيق إلى `authorized_keys`، ثم اتصل بذلك المفتاح.
4. اختر **IPv4 عامًا**، ويفضل عنوانًا محجوزًا أو ثابتًا إن كان المزود يتيحه. العنوان الخاص أو المثيل الذي يعمل بـIPv6 فقط أو بوابة NAT للخروج فقط لا يفي بمتطلبات نقطة الاتصال في هذا الدليل.
5. حدد CIDR مصدر SSH صراحة، مثل عنوان IPv4 العام الحالي متبوعًا بـ`/32`. لا تفترض أن القيمة الافتراضية للإضافة تقيد الوصول. قد يتطلب التنقل بين بيانات الهاتف وWi-Fi تحديث القاعدة عبر لوحة السحابة.

يدعم المسار اليدوي المعماريات المذكورة أعلاه. تختار VPN Setup حاليًا **Ubuntu 24.04 على amd64/x86-64**، وتتصل عبر **منفذ SSH 22**، وتقبل مفاتيح SSH من نوع **Ed25519 أو RSA**؛ ويتطلب مسار Lightsail مفاتيح RSA. لا يدعم هذا المسار مفاتيح ECDSA أو المضيفين الخاصين فقط أو نقاط اتصال IPv6 فقط. يجب أن يمتلك الخادم الموجود عنوان IPv4 عامًا وأن يسمح بوصول إداري غير تفاعلي.

تسمح بيانات اعتماد API السحابة بإدارة الموارد، وتسمح مفاتيح SSH بتسجيل الدخول إلى الخادم. أدخل أسرار API في نموذج بيانات الاعتماد الأصلي المحمي فقط، وليس في الطلبات الصوتية أو أوامر الطرفية أو ملفات الشيفرة. تتولى الشيفرة الأصلية المصادقة مع نقاط اتصال المزود المعتمدة؛ ولا تُرسل الأسرار إلى الجهاز الافتراضي أو منفّذ الإضافة. تُشفَّر بيانات الاعتماد المحفوظة باستخدام Android Keystore؛ وإن اخترت عدم حفظها، فإنها تبقى في الذاكرة وقد يلزم إدخالها مجددًا بعد انتهاء عملية التطبيق.

تستطيع عناصر التحكم الصوتية الإجابة عن الأسئلة المدعومة التي لا تتضمن أسرارًا والإبلاغ عن التقدم، لكن إدخال بيانات الاعتماد والموافقات يتطلب الشاشة. يتوقف التقاط الميكروفون عند فتح النماذج المحمية ويحتاج إلى إجراء صريح لاستئنافه. يتطلب الإعداد الصوتي تفعيله اختياريًا وتنزيل نموذج محلي وإذن الميكروفون. وجود نموذج صوتي دون اتصال لا يجعل استدعاءات API السحابة أو التنزيلات أو SSH تعمل دون إنترنت.

## اختر سحابة واحصل على عنوان عام

في **الإعداد عبر لوحة التحكم**، سجّل الدخول إلى المزود بنفسك؛ لا يحتاج Mobile SSH إلى بيانات اعتماد API الخاصة به. أما **إنشاء الموارد عبر API باستخدام VPN Setup** فيتطلب تجهيز بيانات الاعتماد المبينة أدناه مع صلاحيات عمليات الإنشاء والقراءة والشبكة والحذف المطلوبة. تدعم الإضافة المزودين العشرة في الجدول؛ أما AWS EC2 فهو خيار منفصل عبر لوحة التحكم فقط. قيّد الوصول بمشروع أو نشر مخصص حيثما كان ذلك مدعومًا. تظل سياسات الحساب سارية على الطريقتين.

## أنشئ الموارد واحفظ اتصال SSH

افتح **الإضافات** وثبّت **VPN Setup** من الكتالوج الافتراضي ثم افتح صفحتها المستقلة. اختر **إعداد VPN**، وحدد المزود، ثم **الإنشاء عبر API السحابة** أو **الإنشاء في لوحة تحكم السحابة**. لخادم تملكه بالفعل، اختر خيار الخادم العام الموجود. أدخل بيانات الاعتماد في النموذج الأصلي، واختر مفتاح SSH أو أنشئه، وراجع الموقع والحجم والصورة وCIDR مصدر SSH. تساعد الخيارات المستمدة من الحساب والفحوص المسبقة على اختيار العروض المدعومة؛ لكنها لا تحجز السعة ولا تضمن الحصة. راجع أسعار المزود الحالية ووافق على الإنشاء من الشاشة.

تابع العملية الموجودة حتى يصبح الجهاز وSSH جاهزين. إذا انتهت مهلة طلب أو أوقف Android العمل في الخلفية مؤقتًا، فاستأنف العملية نفسها أو راجعها بدلًا من إنشاء جهاز آخر تُحتسب عليه رسوم. قد يستلزم فقدان رد الإنشاء البحث في السحابة أو مراجعة لوحة التحكم. احتفظ بمعرّفات الجهاز والقرص والعنوان والجدار الناري؛ فقد تكون العملية المتوقفة قد أنشأت موارد بالفعل.

تطلب VPN Setup الموافقة على مفتاح مضيف SSH، وتحفظ الاتصال، وتثبّت wg-easy وتستورد أول عميل. قارن البصمة بلوحة تحكم المزود الموثوقة. للإعداد اليدوي، أضف الخادم ضمن **الخوادم** بعنوان IPv4 العام ومنفذ SSH `22` واسم مستخدم الصورة والمفتاح الخاص المطابق. يستخدم موصلا Google Cloud وAzure التلقائيان `ubuntu`؛ وتستخدم أدلة لوحة التحكم الأسماء التي تضبطها هناك. راجع [البدء](../getting-started/) للتحقق من الهويات وبيانات الاعتماد المحفوظة.

## اضبط طبقتَي الشبكة

يحتاج العنوان العام إلى مسار، وسماح في جدار السحابة الناري وجدار النظام الضيف، وخدمة تستمع. استخدم القواعد التالية في جدار المزود/مجموعة الأمان؛ واحتفظ بقواعد النظام الضيف الحالية المطلوبة.

- **TCP 22:** اسمح بـCIDR الإدارة الذي اخترته لاتصال SSH. اضبطه أثناء إنشاء الموارد.
- **UDP 51820:** اسمح بالشبكات التي ستستخدم VPN. قد يعني ذلك `0.0.0.0/0` للعملاء المتنقلين. تضبط VPN Setup هذا للنشر المنشأ عبر API؛ واستخدم لوحة تحكم السحابة للخادم الذي توفره بنفسك.
- **TCP 51821:** أبقه مغلقًا للعامة. انشر واجهة إدارة wg-easy على عنوان الاسترجاع المحلي للخادم فقط، وادخل إليها عبر نفق SSH.
- **الحركة الصادرة:** اسمح بتنزيل الحزم والحاويات وDNS وحركة الإنترنت التي ستنقلها VPN.

راجع [سلوك الجدار الناري في Docker](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations): قد تتجاوز منافذ الحاويات المنشورة قواعد UFW. لا تعتمد على UFW وحده لإخفاء واجهة الإدارة، ولا تمسح سلاسل جدار المزود، خصوصًا قواعد تخزين/iSCSI في OCI.

## ثبّت wg-easy على الجهاز المختار

بعد الموافقة، تثبّت VPN Setup إصدار wg-easy المحدد ببصمة عبر SSH، وتثبّت Docker عند الحاجة على Ubuntu 24.04، وتنشئ أول عميل. تُبقي واجهة الإدارة على عنوان الاسترجاع المحلي وتحافظ على سلاسل الجدار الناري للمزود. للخادم المنشأ من لوحة التحكم أو الموجود مسبقًا، اضبط جدار السحابة الناري بنفسك؛ يحتاج المثبّت إلى وصول SSH وصلاحيات إدارية، لا إلى سر API السحابة. استخدم خادمًا مخصصًا جديدًا بدل افتراض إمكانية تبني تثبيت VPN غير مرتبط.

تتطلب إضافة الكتالوج الأقدم **WireGuard (wg-easy)** جلسة SSH نشطة وDocker. وهي منفصلة عن **VPN Setup** ولا تضمن استيراد العملاء أصليًا. استخدم VPN Setup على إصدار Android متوافق، أو المسار اليدوي التالي من طرفية Mobile SSH على جهاز افتراضي مخصص جديد.

### التثبيت اليدوي عبر SSH

ثبّت Docker Engine وإضافة Compose وفق [تعليمات Ubuntu](https://docs.docker.com/engine/install/ubuntu/) الرسمية. ثم نزّل إعداد المشروع الأصلي المحدد الإصدار:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.5.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

حرر `/opt/wg-easy/compose.yaml` بمحرر طرفية ذي صلاحيات قبل التشغيل. ضمن `services.wg-easy`، استبدل الصورة، وأزل التعليق عن كتلة البيئة أو اضبطها، واستبدل تعيينات المنافذ بالقيم التالية. احتفظ ببقية الملف الأصلي، بما فيها وحدة التخزين الدائمة وربط الوحدات والقدرات والشبكات وإعدادات sysctls:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.5.0@sha256:071f79a639e9361123a5e57733107320207b844ddbbd92dfa6962f541fe8aac8
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

هذا جزء للاستبدال وليس ملف Compose كاملًا؛ حافظ على مسافات YAML البادئة تحت الخدمة. يسمح `INSECURE=true` بـHTTP لنفق SSH عبر الاسترجاع المحلي فقط. لا تنشر منفذ الإدارة على الإنترنت. مستمع الحاوية مختلف عن تعيين الاسترجاع المحلي على المضيف. راجع [إعداد HTTP](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) في المشروع الأصلي.

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

احتفظ ببيانات `/etc/wireguard` للحاوية في وحدة تخزينها الدائمة. لا تطبّق وصفات `PASSWORD` أو `PASSWORD_HASH` أو `WG_HOST` القديمة على v15؛ استخدم معالج الإعداد. الصورة مثبتة عمدًا: تتطلب الترقية مراجعة إصدار جديد وتغيير المرجع المثبت، لا مجرد تنفيذ `pull`.

## افتح واجهة الإدارة وأضف عميلًا

أنشئ [إعادة توجيه منفذ محلي](../port-forwarding/) في Mobile SSH بمنفذ محلي `51821` ومضيف بعيد `127.0.0.1` ومنفذ بعيد `51821`. أبقِ اتصال SSH نشطًا وافتح `http://127.0.0.1:51821` على الهاتف نفسه. إذا كان المنفذ المحلي مشغولًا، اختر منفذًا آخر واستخدمه في URL المتصفح.

في [معالج التشغيل الأول](https://wg-easy.github.io/wg-easy/latest/guides/setup/) لـwg-easy، أنشئ حساب مسؤول، واختر تثبيتًا جديدًا، واضبط نقطة اتصال VPN على IPv4 العام للجهاز أو اسم DNS مع المنفذ `51820`. نقطة VPN ليست عنوان الاسترجاع المحلي لواجهة الويب أو المنفذ `51821`.

أنشئ عميلًا لكل جهاز ونزّل ملف WireGuard بصيغة `.conf`. عندما يوفر إصدار Mobile SSH المثبت ذلك، افتح **VPN → WireGuard** وأضف ملفًا شخصيًا واستورد الملف ثم احفظه. يدعم المصدر الحالي لـAndroid وiOS استيراد الملفات؛ تحقق من إصدارك المثبت. تستورد VPN Setup أول عميل مباشرة على إصدارات Android المتوافقة. وتوفر صفحتها أيضًا **إضافة عميل** و**إلغاء عميل** و**تصدير عميل/QR** و**فتح الإدارة** عبر نفق SSH خاص. لا يثبت هذا توفر تلك القدرات في الإضافة الأقدم أو أتمتة مماثلة على iOS. تحتوي ملفات الإعداد ورموز QR على مفاتيح خاصة؛ حافظ على سريتها.

## تحقق من VPN وعالج الأعطال

ابدأ ملف التعريف ووافق على طلب VPN من نظام التشغيل. تحقق من مصافحة حديثة مع النظير وتزايد عدادات المرور، ثم اختبر DNS ومسارات الإنترنت أو الشبكة الخاصة المقصودة. لا يثبت استيراد ملف أو تشغيل حاوية وحده أن VPN يعمل.

- **رفض إنشاء الجهاز:** تحقق من الفوترة والحصة والسعة الإقليمية وانتهاء صلاحية بيانات الاعتماد وصلاحيات IAM الدقيقة. تتطلب كتابة قواعد جدار Google Cloud الناري صلاحيات تتجاوز Compute Network Admin؛ وإذا فرضت المؤسسة OS Login فاستخدم إعدادًا معتمدًا عبر لوحة التحكم.
- **انتهاء مهلة SSH:** تحقق من العنوان العام وتوجيه الشبكة الفرعية وقواعد TCP 22 وعنوان المصدر الحالي للهاتف. تحتاج أخطاء المصادقة عادةً إلى اسم مستخدم الصورة الصحيح ومفتاح SSH المطابق.
- **تعذر فتح الإدارة:** أبقِ إعادة توجيه SSH متصلة، وتحقق من حالة الحاوية وربط منافذ الاسترجاع المحلي، وتأكد من تمكين HTTP للنفق فقط.
- **عدم حدوث مصافحة WireGuard:** تحقق من نقطة اتصال العميل وUDP 51820 في طبقتي الجدار الناري ومفاتيح العميل وأن الخادم يستمع.
- **مصافحة دون حركة:** افحص التوجيه/NAT وDNS وتداخل المسارات و`AllowedIPs`. يستخدم نفق IPv4 الكامل `0.0.0.0/0`؛ قيّم IPv6 بصورة مستقلة. لا يستطيع جهاز بلا اتصال IPv6 صاعد توفير خروج IPv6 إلى الإنترنت، وقد تترك مسارات IPv4 فقط حركة IPv6 خارج VPN.

## تحديث الإضافة وخادم VPN

في **الإضافات**، استخدم إجراء **تحديث** المتاح لإصدار متوافق أحدث من الكتالوج نفسه. راجع الإمكانات الإضافية المطلوبة. تُحفظ الإعدادات وبيانات الاعتماد وسجلات النشر؛ وتتابع العملية غير المكتملة بالإصدار الذي بدأها من الإضافة. تحديث الإضافة وحده لا يحدّث حاوية wg-easy على الخادم.

مع جسر الإضافات 1.4.0 أو أحدث، يعرض **فحص الخادم** إصدار wg-easy الجاري ويعرض **تحديث WireGuard** الإصدار الذي تثبّته الإضافة. وافق على التحديث من الشاشة. تُنزَّل الصورة قبل تغيير الخدمة، مع الحفاظ على مفاتيح الخادم والعملاء والملفات الشخصية المحلية. إذا كان الهاتف يستخدم VPN هذه، يفصلها التطبيق قبل التحديث؛ أعد الاتصال بعده. يحدّث هذا الحاوية المُدارة، وليس نظام تشغيل المضيف.

يميّز فشل التحديث بين تعذر تنزيل الصورة، والرجوع الناجح إلى الإصدار السابق، وفشل الرجوع الذي يترك VPN متوقفة. اتبع فحص الاستعادة أو أعد المحاولة بدل افتراض عودة الخدمة. تحتاج التثبيتات اليدوية إلى تعديل مدروس للصورة المثبتة ونسخة احتياطية؛ خطوات التثبيت الجديد أعلاه ليست دليل ترحيل.

## أزل العملاء وأوقف الرسوم السحابية

ألغِ العميل في wg-easy قبل التخلص من ملفه المحلي. لا يحذف ملف التعريف في Mobile SSH مفتاح النظير من الخادم أو يلغيه. انسخ الإعداد المطلوب احتياطيًا بأمان قبل إزالة حاوية VPN أو بياناتها الدائمة.

للنشر المنشأ عبر API، يراجع **حذف النشر** موارده السحابية المملوكة ويحذفها عبر API المزود حتى إن تعذر SSH. تحقق من الموارد المذكورة بوصفها متبقية إذا توقف الحذف مؤقتًا أو فشل؛ استأنف التنظيف أو افحص لوحة التحكم. أبقِ الموارد غير المرتبطة خارج النشر الذي تديره الإضافة، وخصوصًا مجموعة موارد Azure المخصصة له.

للخادم المنشأ من لوحة التحكم أو الموجود مسبقًا، يزيل الحذف عبر الإضافة تثبيت VPN الذي تديره؛ لكنه **لا** يحذف جهازك الافتراضي أو عنوان IP العام. احذفهما من لوحة تحكم المزود عند انتفاء الحاجة، ثم تحقق من الأقراص واللقطات والعناوين وموارد الشبكة المحتفظ بها. إذا تغير الحساب أو الموقع أثناء الاستعادة، فافحص السابق أيضًا، بما في ذلك مشروع Scaleway أو حجرة Oracle Cloud السابقة.

يوقف **إيقاف سير العمل** العملية؛ ولا يحذف الموارد. مع الجسر 1.5.0 أو أحدث، لا يظهر **إزالة من القائمة** إلا عندما يتحقق التطبيق من أهلية نسيان السجل، دون عمليات غير مكتملة أو موارد مُدارة متبقية. يمسح السجل المحلي، لا موارد السحابة. إيقاف الجهاز الافتراضي أو إزالة الإضافة لا يضمن أيضًا توقف الرسوم. احتفظ بمعرّفات الموارد حتى تأكيد حذفها.
