# الأجهزة الافتراضية السحابية وwg-easy

أنشئ جهاز Linux افتراضيًا في حسابك السحابي، واتصل به عبر Mobile SSH، ثم ثبّت wg-easy لتشغيل WireGuard VPN. يتيح فصل إنشاء الموارد عن التثبيت استخدام الجهاز نفسه لخدمة أخرى، أو تثبيت VPN على خادم تملكه بالفعل.

**التوافر — 8 نوفمبر 2026:** تصف الخطوات التالية سير العمل المقصود لإضافات مستقلة تنشئ الأجهزة الافتراضية. يجمع تنفيذ Android المحلي الذي راجعناه، **VPN Setup**، إنشاء الموارد والتثبيت واستيراد العميل؛ تغييرات الإضافة والفهرس غير منشورة، ولم تُختبر عمليات نشر فعلية على السحابة. إدخالات AWS وGoogle Cloud وAzure المنفصلة حاليًا هياكل أولية لملفات التعريف والإعدادات فقط؛ لم تُنفذ عمليات سرد الأجهزة الافتراضية والتحكم بها، ولا تنشئ أجهزة. استخدم تعليمات لوحة التحكم والتثبيت اليدوي أدناه إذا لم يتضمن فهرسك مسار إنشاء. يتطلب سير العمل الأصلي الجديد نسخة Android متوافقة؛ ولم يثبت وجود أتمتة مماثلة على iOS.

## إضافتان بمسؤوليتين منفصلتين

- **إضافة إنشاء الموارد السحابية:** تستخدم API المزود لإنشاء الجهاز الافتراضي والعنوان العام وموارد الشبكة اللازمة، ثم تحفظ اتصال SSH. وتحتفظ بمعرّفات الموارد السحابية اللازمة لإدارتها أو حذفها لاحقًا.
- **مثبّت wg-easy:** يتصل بخادم محفوظ تختاره عبر SSH، ويثبّت خدمة VPN ويساعد في إنشاء إعداد العميل. يحتاج إلى الوصول للخادم وصلاحيات إدارية، لا إلى بيانات اعتماد API السحابة. ويمكن استخدام جهاز افتراضي أُنشئ يدويًا أيضًا.

ينبغي أن تشمل بيانات التسليم مرجع الخادم المحفوظ والعنوان العام ومنفذ SSH واسم المستخدم ومرجع بيانات اعتماد SSH ومعرّفات النشر والموارد. لا ينبغي نسخ أسرار السحابة أو مفاتيح SSH الخاصة إلى مخرجات الإضافة أو إلى الجهاز الافتراضي. إزالة VPN وحذف الجهاز السحابي عمليتان منفصلتان.

## جهّز حسابك وإعدادات الخادم

1. فعّل حسابًا سحابيًا والفوترة، واختر منطقة، وتحقق من حصص الأجهزة والأقراص وعناوين IP العامة. راجع رسوم المزود الحالية للأجهزة وIPv4 والتخزين وحركة البيانات؛ لا نفترض توافر فئة مجانية.
2. لهذا الدليل، اختر جهازًا مخصصًا بنظام **Ubuntu 24.04 LTS** وبحد أدنى **1 GB من الذاكرة و20 GB من القرص**، بمعمارية **amd64 أو arm64**. هذه خيارات أساسية لهذا الإعداد، وليست حدًا أدنى عامًا لـwg-easy. استخدم حساب دخول بصلاحيات root أو sudo؛ فالتثبيت دون تدخل يتطلب رفع صلاحيات غير تفاعلي.
3. اختر مفتاح SSH أو ولّده، واحتفظ بالمفتاح الخاص داخل Mobile SSH. ارفع المفتاح العام فقط إلى السحابة. يتطلب مسار استيراد Lightsail مفتاح SSH من نوع RSA. للمزودين والصور الأخرى أنواع مفاتيح مقبولة خاصة بهم. يدعم عميل SSH الحالي على iOS مفاتيح Ed25519/ECDSA الخاصة بدلًا من مفاتيح RSA الخاصة. لاستخدام Lightsail على iOS، استخدم أولًا لوحة SSH في متصفح المزود لإضافة مفتاح عام يدعمه التطبيق إلى `authorized_keys`، ثم اتصل بذلك المفتاح.
4. اختر **IPv4 عامًا**، ويفضل عنوانًا محجوزًا أو ثابتًا إن كان المزود يتيحه. العنوان الخاص أو المثيل الذي يعمل بـIPv6 فقط أو بوابة NAT للخروج فقط لا يفي بمتطلبات نقطة الاتصال في هذا الدليل.
5. حدد CIDR مصدر SSH صراحة، مثل عنوان IPv4 العام الحالي متبوعًا بـ`/32`. لا تفترض أن القيمة الافتراضية للإضافة تقيد الوصول. قد يتطلب التنقل بين بيانات الهاتف وWi-Fi تحديث القاعدة عبر لوحة السحابة.

تخوّل بيانات اعتماد API السحابة إدارة الموارد، بينما تخوّل مفاتيح SSH تسجيل الدخول إلى الخادم. إنهما نوعان مختلفان. أدخل أسرار API في نموذج بيانات الاعتماد المحمي الخاص بالمزود فقط، لا في المطالبات الصوتية أو أوامر الطرفية أو ملفات المصدر. في سير عمل Android المحلي، تتولى الشيفرة الأصلية مصادقة المزود وتخزين بيانات الاعتماد مشفّرة؛ تُرسل البيانات إلى مزودها عند الحاجة، لا إلى الجهاز الافتراضي أو عامل الإضافة. وجود نموذج صوتي غير متصل لا يجعل استدعاءات API السحابة أو التنزيلات أو SSH تعمل دون إنترنت.

## اختر سحابة واحصل على عنوان عام

عند **الإعداد من لوحة التحكم**، سجّل الدخول إلى المزود بنفسك؛ لا يحتاج Mobile SSH إلى بيانات اعتماد API الخاصة به. ولـ**إنشاء الموارد عبر الإضافات مستقبلًا**، جهّز بيانات الاعتماد أدناه بصلاحيات عمليات الإنشاء والقراءة والشبكة والحذف المطلوبة. قيد الوصول بمشروع أو نشر مخصص حيثما أمكن. تظل سياسات الحساب سارية في الحالتين.

أنشئ جهاز Ubuntu المختار بمفتاح SSH العام، وطبّق قاعدة SSH في القسم التالي. تشرح الروابط خطوات العنوان والمصادقة الخاصة بكل مزود.

**بديل [AWS EC2](./aws-ec2/):** شغّل Ubuntu في شبكة فرعية عامة فيها [بوابة إنترنت ومسار بوابة `0.0.0.0/0`](https://docs.aws.amazon.com/vpc/latest/userguide/VPC_Internet_Gateway.html)، واختر مفتاح SSH ومجموعة أمان، ثم اربط [Elastic IP](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/working-with-eips.html). استخدم `ubuntu`. يستهدف المحوّل التلقائي المحلي Lightsail؛ أما EC2 فمساره لوحة التحكم. لا يجعل Elastic IP وحده الشبكة الفرعية الخاصة قابلة للوصول.

إذا كانت المؤسسة تمنع مفاتيح حسابات الخدمة أو عناوين IP الخارجية أو طريقة مصادقة SSH المختارة، احصل على إعداد يوافق عليه المسؤول. لا يتجاوز الإعداد من لوحة التحكم هذه القيود.

## أنشئ الموارد واحفظ اتصال SSH

في سير العمل المنفصل المقصود، افتح **الإضافات**، وثبّت إضافة الإنشاء الخاصة بالمزود من فهرس موثوق، واختر الحساب والمنطقة، ثم حجم الجهاز والصورة والعنوان العام ومفتاح SSH. راجع الموارد والتكاليف قبل تأكيد الإنشاء. لا تستطيع إضافة للإدارة فقط دون إجراء إنشاء تنفيذ هذه الخطوة؛ استخدم لوحة المزود بدلًا منها.

انتظر حتى يعلن المزود أن الجهاز يعمل وأن SSH متاح. احتفظ بمعرّفات الجهاز والقرص والعنوان والجدار الناري. إذا انتهت مهلة طلب، افحص العملية الحالية أو استأنفها قبل إعادة الإنشاء، لتجنب إنشاء جهاز ثانٍ تُحتسب عليه رسوم.

احفظ الاتصال الناتج في Mobile SSH، أو أضفه يدويًا ضمن **الخوادم**: IPv4 العام، ومنفذ SSH `22`، واسم مستخدم الصورة، وبيانات المفتاح الخاص المطابق. قارن بصمة مفتاح مضيف SSH عبر لوحة المزود الموثوقة قبل الاتصال. راجع [البدء](../getting-started/) لفحوص الهوية وبيانات الاعتماد المحفوظة.

## اضبط طبقتَي الشبكة

يحتاج العنوان العام إلى مسار، وسماح في جدار السحابة الناري وجدار النظام الضيف، وخدمة تستمع. استخدم القواعد التالية في جدار المزود/مجموعة الأمان؛ واحتفظ بقواعد النظام الضيف الحالية المطلوبة.

- **TCP 22:** اسمح بـSSH من CIDR الإدارة المختار. اضبطه أثناء إنشاء الموارد.
- **UDP 51820:** اسمح من الشبكات التي ستستخدم VPN. للعملاء المتنقلين قد يعني ذلك `0.0.0.0/0`. أضفه عند إعداد WireGuard عبر إضافة الإنشاء أو لوحة التحكم.
- **TCP 51821:** أبقه مغلقًا للعامة. انشر واجهة إدارة wg-easy على عنوان الاسترجاع المحلي للخادم فقط، وادخل إليها عبر نفق SSH.
- **حركة الخروج:** اسمح بتنزيل الحزم والحاويات وDNS وحركة الإنترنت التي يُراد تمريرها عبر VPN.

راجع [سلوك الجدار الناري في Docker](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations): قد تتجاوز منافذ الحاويات المنشورة قواعد UFW. لا تعتمد على UFW وحده لإخفاء واجهة الإدارة، ولا تمسح سلاسل جدار المزود، خصوصًا قواعد تخزين/iSCSI في OCI.

## ثبّت wg-easy على الجهاز المختار

ينبغي أن يستقبل المثبّت المنفصل خادم SSH المحفوظ ويطلب الموافقة على تغييرات الخادم. وينبغي أن يفحص النظام والصلاحيات وتثبيت Docker/VPN الموجود وتعارض المنافذ، ويحفظ البيانات الدائمة، ويعرض الإصدار المثبّت. لا يحتاج إلى سر الحساب السحابي؛ استخدم إضافة الإنشاء أو لوحة التحكم لتغييرات جدار السحابة الناري.

تتطلب إضافة الفهرس الأقدم **WireGuard (wg-easy)** جلسة SSH نشطة وDocker. وهي ليست المثبّت التلقائي الجديد، ولا تضمن استيراد العميل الأصلي. استخدم مثبّتًا محدّثًا متوافقًا، أو المسار اليدوي التالي من طرفية Mobile SSH على جهاز جديد مخصص.

### التثبيت اليدوي عبر SSH

ثبّت Docker Engine وإضافة Compose وفق [تعليمات Ubuntu](https://docs.docker.com/engine/install/ubuntu/) الرسمية. ثم نزّل إعداد المشروع الأصلي المحدد الإصدار:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.4.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

حرر `/opt/wg-easy/compose.yaml` بمحرر طرفية ذي صلاحيات قبل التشغيل. ضمن `services.wg-easy`، استبدل الصورة، وأزل التعليق عن كتلة البيئة أو اضبطها، واستبدل تعيينات المنافذ بالقيم التالية. احتفظ ببقية الملف الأصلي، بما فيها وحدة التخزين الدائمة وربط الوحدات والقدرات والشبكات وإعدادات sysctls:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.4.0@sha256:0e7bc9d34e86ddcaa92bc700d4d7dc9b33291dbc07ac8d13382f7c2095f949ec
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

هذا جزء للاستبدال وليس ملف Compose كاملًا؛ حافظ على مسافات YAML البادئة تحت الخدمة. يسمح `INSECURE=true` بـHTTP لنفق SSH عبر الاسترجاع المحلي فقط. لا تنشر منفذ الإدارة على الإنترنت. مستمع الحاوية مختلف عن تعيين الاسترجاع المحلي على المضيف. راجع [إعداد HTTP](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) في المشروع الأصلي.

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

احتفظ ببيانات `/etc/wireguard` للحاوية في وحدة تخزينها الدائمة. لا تطبّق وصفات `PASSWORD` أو `PASSWORD_HASH` أو `WG_HOST` القديمة على v15؛ استخدم معالج الإعداد. الصورة مثبتة عمدًا: تتطلب الترقية مراجعة إصدار جديد وتغيير المرجع المثبت، لا مجرد تنفيذ `pull`.

## افتح واجهة الإدارة وأضف عميلًا

أنشئ [إعادة توجيه منفذ محلي](../port-forwarding/) في Mobile SSH بمنفذ محلي `51821` ومضيف بعيد `127.0.0.1` ومنفذ بعيد `51821`. أبقِ اتصال SSH نشطًا وافتح `http://127.0.0.1:51821` على الهاتف نفسه. إذا كان المنفذ المحلي مشغولًا، اختر منفذًا آخر واستخدمه في URL المتصفح.

في [معالج التشغيل الأول](https://wg-easy.github.io/wg-easy/latest/guides/setup/) لـwg-easy، أنشئ حساب مسؤول، واختر تثبيتًا جديدًا، واضبط نقطة اتصال VPN على IPv4 العام للجهاز أو اسم DNS مع المنفذ `51820`. نقطة VPN ليست عنوان الاسترجاع المحلي لواجهة الويب أو المنفذ `51821`.

أنشئ عميلًا لكل جهاز ونزّل ملف WireGuard بصيغة `.conf`. إذا كانت نسخة Mobile SSH توفر ذلك، افتح **VPN → WireGuard**، وأضف ملف تعريف واستورد الملف واحفظه. تدعم شيفرة Android وiOS الحالية استيراد الملفات؛ تحقق من نسختك المثبتة. يستطيع سير عمل Android المحلي المجمّع الاستيراد مباشرة، لكن هذا ليس وعدًا بشأن الإضافة الأقدم أو أتمتة iOS. تحتوي ملفات الإعداد ورموز QR على مفاتيح خاصة؛ حافظ على سريتها.

## تحقق من VPN وعالج الأعطال

ابدأ ملف التعريف ووافق على طلب VPN من نظام التشغيل. تحقق من مصافحة حديثة مع النظير وتزايد عدادات المرور، ثم اختبر DNS ومسارات الإنترنت أو الشبكة الخاصة المقصودة. لا يثبت استيراد ملف أو تشغيل حاوية وحده أن VPN يعمل.

- **رُفض إنشاء الجهاز:** تحقق من الفوترة والحصة وسعة المنطقة وانتهاء بيانات الاعتماد وصلاحيات IAM الدقيقة. تحتاج كتابة جدار Google Cloud الناري إلى صلاحيات تتجاوز Network Admin.
- **انتهاء مهلة SSH:** تحقق من العنوان العام وتوجيه الشبكة الفرعية وقواعد TCP 22 وعنوان مصدر الهاتف الحالي. يتطلب فشل المصادقة عادة اسم المستخدم الصحيح للصورة ومفتاح SSH الصحيح.
- **واجهة الإدارة غير متاحة:** أبقِ إعادة توجيه SSH متصلة، وافحص حالة الحاوية وتعيين منفذ الاسترجاع المحلي، وتأكد من تفعيل HTTP للنفق فقط.
- **لا توجد مصافحة WireGuard:** افحص نقطة العميل وUDP 51820 في طبقتَي الجدار الناري ومفاتيح العميل واستماع الخادم.
- **مصافحة دون مرور:** افحص التوجيه/NAT وDNS وتداخل المسارات و`AllowedIPs`. يستخدم نفق IPv4 الكامل `0.0.0.0/0`؛ قيّم IPv6 بشكل منفصل. لا يستطيع جهاز بلا IPv6 صاعد توفير خروج IPv6 إلى الإنترنت، وقد تُبقي مسارات IPv4 فقط حركة IPv6 خارج VPN.

## أزل العملاء وأوقف الرسوم السحابية

ألغِ العميل في wg-easy قبل التخلص من ملفه المحلي. لا يحذف ملف التعريف في Mobile SSH مفتاح النظير من الخادم أو يلغيه. انسخ الإعداد المطلوب احتياطيًا بأمان قبل إزالة حاوية VPN أو بياناتها الدائمة.

استخدم إضافة الإنشاء المالكة أو لوحة المزود لحذف جهاز لم تعد تحتاجه، ثم تحقق من الأقراص واللقطات والعناوين المحجوزة/العامة وموارد الشبكة المحتفظ بها. راجع محتويات مجموعة موارد Azure المخصصة قبل حذفها. لا تضم موارد غير مرتبطة إلى نشر تديره الإضافة.

إيقاف جهاز افتراضي أو إلغاء مهمة إعداد أو إزالة الإضافة لا يضمن حذف الموارد أو توقف الرسوم. الموارد المنشأة عبر لوحة التحكم تبقى مسؤوليتك في التنظيف؛ احتفظ بمعرّفات المزود حتى يتأكد الحذف.
