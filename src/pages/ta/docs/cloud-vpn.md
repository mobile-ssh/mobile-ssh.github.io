# கிளவுட் VM மற்றும் wg-easy

சொந்த கிளவுட் கணக்கில் Linux VM உருவாக்கி wg-easy மூலம் WireGuard VPN இயக்குங்கள். பொருந்தும் Android கட்டமைப்புகளில் வெளியிடப்பட்ட **VPN Setup** செருகுநிரல் ஒரே வழிகாட்டிய பணிப்பாய்வில் VM உருவாக்கி, wg-easy நிறுவி, கிளையன்ட்டை இறக்குமதி செய்யும். வழங்குநர் கன்சோலில் VM உருவாக்கி Mobile SSH வழியாக நிறுவலாம் அல்லது ஏற்கெனவே உள்ள பொது சேவையகத்தைப் பயன்படுத்தலாம்.

**கிடைக்கும் நிலை — நவம்பர் 19, 2026:** **VPN Setup 1.0.7** [இயல்புநிலை செருகுநிரல் பட்டியலில்](https://github.com/mobile-ssh/mobile-ssh-plugins/tree/main/plugins/vpnsetup) வெளியிடப்பட்டுள்ளது. அடிப்படை அமைப்பிற்கு செருகுநிரல் பிரிட்ஜ் **1.3.0**, சேவையகப் புதுப்பிப்பிற்கு **1.4.0**, தகுதியுள்ள முடிந்த பதிவுகளை அகற்ற **1.5.0** தேவை. கிடைக்கும் நிலை நிறுவிய Android கட்டமைப்பையும் வெளியீட்டுப் பாதையையும் பொறுத்தது; செருகுநிரல் வெளியீடு ஒரு குறிப்பிட்ட செயலிப் பதிப்பு உங்களுக்குக் கிடைப்பதை உறுதிப்படுத்தாது. சமமான iOS தானியக்கம் உறுதியாகவில்லை. செருகுநிரல் கிடைக்காவிட்டால் கீழுள்ள கன்சோல் மற்றும் கைமுறை வழிமுறைகளைப் பின்பற்றுங்கள்.

## வழிகாட்டிய அல்லது கைமுறைப் பணிப்பாய்வைத் தேர்ந்தெடுக்கவும்

- **கிளவுட் API மூலம் உருவாக்கு:** VPN Setup உங்கள் வழங்குநர் கணக்கைப் பயன்படுத்தி VM, வலையமைப்பு வளங்களை உருவாக்கி, SSH இணைப்பைச் சேமித்து, wg-easy நிறுவி கிளையன்ட்டை இறக்குமதி செய்யும். பின்னர் அகற்றுவதற்காக வள ID-களையும் உரிமைப் பதிவுகளையும் வைத்திருக்கும்.
- **கிளவுட் கன்சோலில் உருவாக்கு அல்லது இருக்கும் சேவையகத்தைப் பயன்படுத்து:** VM-ஐ நீங்களே உருவாக்கி அதன் பொது IPv4, SSH பயனர்பெயர், விசையை VPN Setup-க்கு வழங்குங்கள் அல்லது கீழுள்ள கைமுறை நிறுவலைச் செய்யுங்கள். உங்கள் சேவையகத்தில் நிறுவ செருகுநிரலுக்கு கிளவுட் API உள்நுழைவு விவரங்கள் தேவையில்லை.

வெளியிடப்பட்ட செருகுநிரல் வள உருவாக்கத்தையும் நிறுவலையும் இணைக்கிறது; தனி உருவாக்கி, நிறுவி செருகுநிரல்கள் இன்னும் திட்டமிட்ட கட்டமைப்பு. API-யால் உருவாக்கிய வளங்களுக்கும் நீங்கள் கொண்டுவரும் சேவையகங்களுக்கும் நீக்கும் நடத்தை வேறுபடும்; கீழே விளக்கப்பட்டுள்ளது. பதிவுசெய்த நேரடி Hetzner சோதனையில் Android முன்மாதிரியில் அமைப்பு, VPN போக்குவரத்து, கிளையன்ட் நிர்வாகம், தனிப்பட்ட நிர்வாக அணுகல், அகற்றுதல் வெற்றிபெற்றன. இதனால் ஒவ்வொரு வழங்குநர், கணக்குக் கொள்கை அல்லது உண்மையான தொலைபேசியிலும் நேரடிச் சோதனை வெற்றி உறுதியாகாது.

## கணக்கையும் சர்வர் அமைப்புகளையும் தயார்செய்யுங்கள்

1. கிளவுட் கணக்கையும் கட்டண வசதியையும் செயல்படுத்தி, பகுதியைத் தேர்ந்தெடுத்து, VM, வட்டு, பொது IP ஒதுக்கீட்டு வரம்புகளைச் சரிபாருங்கள். வழங்குநரின் தற்போதைய VM, IPv4, சேமிப்பு, போக்குவரத்துக் கட்டணங்களைப் பாருங்கள்; இலவசத் திட்டம் கிடைக்கும் என்று கருதப்படவில்லை.
2. இந்த வழிகாட்டிக்கு **amd64 அல்லது arm64** கட்டமைப்பில் குறைந்தது **1 GB RAM மற்றும் 20 GB வட்டு** கொண்ட தனியான **Ubuntu 24.04 LTS** VM தேர்ந்தெடுக்கவும். இவை இந்த அமைப்பின் அடிப்படைத் தேர்வுகள்; wg-easy-க்கான பொதுவான குறைந்தபட்சத் தேவைகள் அல்ல. root அல்லது sudo அணுகலுள்ள உள்நுழைவைப் பயன்படுத்துங்கள்; மேற்பார்வையற்ற நிறுவலுக்கு இடையில் கேள்வி கேட்காமல் உரிமைகளை உயர்த்த இயல வேண்டும்.
3. SSH விசையைத் தேர்ந்தெடுங்கள் அல்லது உருவாக்குங்கள்; தனிப்பட்ட விசையை Mobile SSH-இல் வைத்திருங்கள். பொது விசையை மட்டும் கிளவுட்டில் பதிவேற்றுங்கள். Lightsail இறக்குமதி முறைக்கு RSA SSH விசை தேவை. பிற வழங்குநர்களும் இமேஜ்களும் ஏற்கும் விசை வகைகள் வேறுபடலாம். தற்போதைய iOS SSH கிளையன்ட் RSA தனிப்பட்ட விசைகளுக்குப் பதிலாக Ed25519/ECDSA-ஐ ஆதரிக்கிறது. iOS-இல் Lightsail பயன்படுத்த, முதலில் வழங்குநரின் உலாவி SSH கன்சோல் மூலம் செயலி ஆதரிக்கும் பொது விசையை `authorized_keys`-இல் சேர்த்து, பின்னர் அந்த விசையுடன் இணையுங்கள்.
4. **பொது IPv4** தேர்ந்தெடுக்கவும்; வழங்குநர் அளித்தால் ஒதுக்கிவைத்த/நிலையான முகவரிக்கு முன்னுரிமை கொடுங்கள். தனிப்பட்ட முகவரி, IPv6 மட்டும் உள்ள இயந்திரம் அல்லது வெளிச்செல்லும் போக்குவரத்துக்கான NAT கேட்வே மட்டும் இந்த வழிகாட்டியின் இணைப்பு முகவரித் தேவையை நிறைவேற்றாது.
5. SSH மூல CIDR-ஐ வெளிப்படையாக அமைக்கவும்; உதாரணமாக தற்போதைய பொது IPv4-க்குப் பின் `/32`. செருகுநிரலின் இயல்புநிலை அணுகலைக் கட்டுப்படுத்தும் என்று கருத வேண்டாம். மொபைல் தரவு அல்லது Wi-Fi மாறும்போது கிளவுட் கன்சோலில் விதியை மாற்ற வேண்டியிருக்கலாம்.

கைமுறை வழி மேலுள்ள கட்டமைப்புகளை ஆதரிக்கிறது. VPN Setup தற்போது **amd64/x86-64-இல் Ubuntu 24.04** தேர்ந்தெடுத்து **SSH போர்ட் 22**-இல் இணையும்; **Ed25519 அல்லது RSA** SSH விசைகளை ஏற்கும். அதன் Lightsail வழிக்கு RSA தேவை. ECDSA விசைகள், தனிப்பட்ட முகவரி மட்டுமுள்ள ஹோஸ்ட்கள், IPv6 மட்டும் உள்ள இணைப்பு முனைகள் இப்பணிப்பாய்வில் ஆதரிக்கப்படாது. இருக்கும் சேவையகத்திற்கு பொது IPv4 மற்றும் இடையீட்டுக் கேள்விகளற்ற நிர்வாக அணுகல் வேண்டும்.

கிளவுட் API விவரங்கள் வள நிர்வாகத்திற்கும் SSH விசைகள் சேவையக உள்நுழைவிற்கும் அனுமதிக்கின்றன. API ரகசியங்களைப் பாதுகாக்கப்பட்ட நேட்டிவ் சான்றுப் படிவத்தில் மட்டுமே உள்ளிடுங்கள்; குரல் ப்ராம்ப்ட், முனையக் கட்டளை அல்லது மூலக் கோப்புகளில் வேண்டாம். நேட்டிவ் குறியீடு அங்கீகரித்த வழங்குநர் முனைகளுடன் அடையாளத்தைச் சரிபார்க்கும்; ரகசியங்கள் VM அல்லது செருகுநிரல் பணியாளருக்குச் செல்லாது. நினைவில் வைக்கும் விவரங்கள் Android Keystore குறியாக்கத்தைப் பயன்படுத்தும்; நினைவில் வைக்கத் தேர்ந்தெடுக்காவிட்டால் நினைவகத்தில் இருக்கும், செயலிச் செயல்முறை முடிந்தபின் மீண்டும் உள்ளிட வேண்டியிருக்கலாம்.

குரல் கட்டுப்பாடுகள் ஆதரிக்கும் ரகசியமற்ற கேள்விகளுக்கு பதிலளித்து முன்னேற்றத்தைத் தெரிவிக்கும்; உள்நுழைவு விவரங்களையும் ஒப்புதல்களையும் திரையில் வழங்க வேண்டும். பாதுகாக்கப்பட்ட சான்றுப் படிவங்களில் மைக்ரோஃபோன் பதிவு இடைநிறுத்தப்படும்; தொடர வெளிப்படையான செயல் தேவை. குரல் அமைப்புக்கு விருப்ப ஒப்புதல், பதிவிறக்கிய உள்ளக மாதிரி, மைக்ரோஃபோன் அனுமதி தேவை. ஆஃப்லைன் குரல் மாதிரி இருப்பதால் கிளவுட் API அழைப்புகள், பதிவிறக்கங்கள், SSH இணையமின்றி இயங்காது.

## கிளவுட்டைத் தேர்ந்தெடுத்துப் பொது முகவரியைப் பெறுங்கள்

**கன்சோல் அமைப்புக்கு** வழங்குநரிடம் நீங்களே உள்நுழையுங்கள்; Mobile SSH-க்கு அதன் API விவரங்கள் தேவையில்லை. **VPN Setup API வள உருவாக்கத்திற்கு** கீழுள்ள விவரங்களைத் தேவையான உருவாக்கம், வாசிப்பு, வலையமைப்பு, நீக்க அனுமதிகளுடன் தயாரியுங்கள். இச்செருகுநிரல் அட்டவணையின் பத்து வழங்குநர்களைச் செயல்படுத்துகிறது; AWS EC2 தனி கன்சோல்-மட்டும் விருப்பம். ஆதரிக்கும்போது அணுகலைத் தனி திட்டம் அல்லது நிறுவலுக்குள் கட்டுப்படுத்துங்கள். இரு முறைகளுக்கும் கணக்குக் கொள்கைகள் பொருந்தும்.

உங்கள் SSH பொது விசையுடன் தேர்ந்தெடுத்த Ubuntu VM-ஐ உருவாக்கி, அடுத்த பகுதியிலுள்ள SSH விதியைப் பயன்படுத்துங்கள். இணைப்புகள் வழங்குநருக்குரிய முகவரி மற்றும் அங்கீகாரப் படிகளை விளக்குகின்றன.

## வளங்களை உருவாக்கி SSH இணைப்பைச் சேமியுங்கள்

**செருகுநிரல்கள்** திறந்து இயல்புநிலைப் பட்டியலிலிருந்து **VPN Setup** நிறுவி அதன் தனிப் பக்கத்தைத் திறங்கள். **VPN அமை**, வழங்குநர், பிறகு **கிளவுட் API மூலம் உருவாக்கு** அல்லது **கிளவுட் கன்சோலில் உருவாக்கு** தேர்ந்தெடுங்கள். ஏற்கெனவே சேவையகம் இருந்தால் இருக்கும் பொது சேவையக விருப்பத்தைத் தேர்ந்தெடுங்கள். நேட்டிவ் படிவத்தில் விவரங்களை உள்ளிட்டு SSH விசையைத் தேர்ந்தெடுக்கவும் அல்லது உருவாக்கவும்; இடம், அளவு, இமேஜ், SSH மூல CIDR பரிசீலியுங்கள். கணக்கிலிருந்து கிடைக்கும் தேர்வுகளும் முன்சோதனைகளும் ஆதரிக்கும் வசதிகளைத் தேர்வுசெய்ய உதவும்; கொள்ளளவை ஒதுக்கவோ கோட்டாவை உறுதிப்படுத்தவோ செய்யாது. வழங்குநரின் தற்போதைய விலைகளைப் பார்த்து உருவாக்கத்தைத் திரையில் ஒப்புக்கொள்ளுங்கள்.

VM, SSH தயாராகும்வரை அதே செயல்பாட்டைப் பின்பற்றுங்கள். கோரிக்கை காலாவதியானாலோ Android பின்னணி வேலையை இடைநிறுத்தினாலோ மற்றொரு கட்டண VM உருவாக்காமல் அதே செயல்பாட்டைத் தொடரவும் பரிசீலிக்கவும். உருவாக்கப் பதில் தொலைந்தால் கிளவுட் தேடல் அல்லது கன்சோல் பரிசீலனை தேவைப்படலாம். VM, வட்டு, முகவரி, ஃபயர்வால் வள ID-களை வைத்திருங்கள்; நிறுத்திய பணிப்பாய்வும் வளங்களை உருவாக்கியிருக்கலாம்.

VPN Setup SSH ஹோஸ்ட் விசை ஒப்புதலைக் கேட்டு, இணைப்பைச் சேமித்து, wg-easy நிறுவி முதல் கிளையன்ட்டை இறக்குமதி செய்யும். கைரேகையை வழங்குநரின் நம்பகமான கன்சோலுடன் ஒப்பிடுங்கள். கைமுறை அமைப்பில் **சேவையகங்கள்** பகுதியில் பொது IPv4, SSH போர்ட் `22`, இமேஜ் பயனர்பெயர், பொருந்தும் தனிச்சாவியுடன் சேருங்கள். தானியக்க Google Cloud, Azure அடாப்டர்கள் `ubuntu` பயன்படுத்தும்; கன்சோல் வழிகாட்டிகள் அங்கு அமைத்த பயனர்பெயர்களைப் பயன்படுத்தும். அடையாளச் சோதனைகள், சேமித்த விவரங்களுக்கு [தொடங்குதல்](../getting-started/) பார்க்கவும்.

## வலையமைப்பின் இரண்டு அடுக்குகளையும் அமைக்கவும்

பொது முகவரிக்கு வழித்தடம், கிளவுட் ஃபயர்வால் அனுமதி, விருந்தினர் இயந்திர ஃபயர்வால் அனுமதி, கேட்கும் சேவை ஆகியவை தேவை. வழங்குநரின் ஃபயர்வால்/பாதுகாப்புக் குழுவில் இந்த விதிகளைப் பயன்படுத்துங்கள்; தேவையான தற்போதைய விருந்தினர் விதிகளைப் பாதுகாக்கவும்.

- **TCP 22:** SSH-க்கு நீங்கள் தேர்ந்தெடுத்த மேலாண்மை CIDR-இலிருந்து அனுமதிக்கவும். வள உருவாக்கத்தின்போது அமைக்கவும்.
- **UDP 51820:** VPN பயன்படுத்தும் வலையமைப்புகளிலிருந்து அனுமதிக்கவும். இடம்மாறும் கிளையன்ட்களுக்கு இது `0.0.0.0/0` ஆக இருக்கலாம். API மூலம் உருவாக்கிய நிறுவல்களுக்கு VPN Setup இதை அமைக்கும்; நீங்கள் கொண்டுவரும் சேவையகத்திற்கு கிளவுட் கன்சோலைப் பயன்படுத்தவும்.
- **TCP 51821:** பொதுவெளியில் மூடியே வைத்திருக்கவும். wg-easy நிர்வாக UI-ஐ சர்வர் லூப்பேக்கில் மட்டும் வெளியிட்டு SSH சுரங்கம் மூலம் அணுகவும்.
- **வெளிச்செல்லும் போக்குவரத்து:** தொகுப்பு/கன்டெய்னர் பதிவிறக்கங்கள், DNS, VPN கொண்டுசெல்ல வேண்டிய இணையப் போக்குவரத்தை அனுமதிக்கவும்.

Docker-இன் [ஃபயர்வால் நடத்தையை](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations) சரிபாருங்கள்: வெளியிடப்பட்ட கன்டெய்னர் போர்ட்கள் UFW விதிகளைத் தவிர்க்கலாம். நிர்வாக UI-ஐ மறைக்க UFW-ஐ மட்டும் நம்பாதீர்கள்; வழங்குநரின் ஃபயர்வால் சங்கிலிகளை, குறிப்பாக OCI சேமிப்பு/iSCSI விதிகளை, அழிக்காதீர்கள்.

## தேர்ந்தெடுத்த VM-இல் wg-easy நிறுவுங்கள்

ஒப்புதலுக்குப் பிறகு VPN Setup SSH வழியாக டைஜெஸ்டால் நிர்ணயித்த wg-easy பதிப்பை நிறுவி, Ubuntu 24.04-இல் தேவைப்பட்டால் Docker நிறுவி, முதல் கிளையன்ட்டை உருவாக்கும். நிர்வாக இடைமுகத்தை சேவையக லூப்பேக்கில் வைத்திருந்து வழங்குநர் ஃபயர்வால் சங்கிலிகளைப் பாதுகாக்கும். கன்சோலில் உருவாக்கிய அல்லது இருக்கும் சேவையகத்திற்கு கிளவுட் ஃபயர்வாலை நீங்களே அமைக்கவும்; நிறுவிக்கு SSH அணுகலும் நிர்வாக உரிமைகளும் தேவை, கிளவுட் API ரகசியம் அல்ல. தொடர்பற்ற VPN நிறுவலை ஏற்றுக்கொள்ளும் என நினைக்காமல் புதிய தனிச் சேவையகத்தைப் பயன்படுத்தவும்.

பழைய **WireGuard (wg-easy)** பட்டியல் செருகுநிரலுக்கு செயலில் உள்ள SSH அமர்வும் Docker-உம் தேவை. இது **VPN Setup**-இலிருந்து வேறானது; நேட்டிவ் கிளையன்ட் இறக்குமதியை உறுதியளிக்காது. பொருந்தும் Android கட்டமைப்பில் VPN Setup பயன்படுத்துங்கள் அல்லது புதிய தனி VM-இல் Mobile SSH முனையம் வழியாக கீழுள்ள கைமுறை வழியைப் பின்பற்றுங்கள்.

### SSH மூலம் கைமுறை நிறுவல்

அதிகாரப்பூர்வ [Ubuntu வழிமுறைகள்](https://docs.docker.com/engine/install/ubuntu/) மூலம் Docker Engine மற்றும் அதன் Compose செருகுநிரலை நிறுவவும். பின்னர் பதிப்புக்குரிய மேல்நிலைத் திட்ட அமைப்பைப் பதிவிறக்கவும்:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.5.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

தொடங்குவதற்கு முன் நிர்வாக உரிமையுள்ள முனையத் திருத்தியில் `/opt/wg-easy/compose.yaml`-ஐத் திருத்தவும். `services.wg-easy` கீழ் இமேஜை மாற்றி, environment பகுதியின் கருத்துக்குறியை நீக்கி/அமைத்து, போர்ட் மேப்பிங்குகளை இந்த மதிப்புகளால் மாற்றவும். நிலையான வால்யூம், தொகுதி மவுண்ட், திறன்கள், வலையமைப்புகள், sysctls உட்பட மேல்நிலைக் கோப்பின் மற்ற பகுதிகளை வைத்திருக்கவும்:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.5.0@sha256:071f79a639e9361123a5e57733107320207b844ddbbd92dfa6962f541fe8aac8
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

இது மாற்ற வேண்டிய பகுதி; முழுமையான Compose கோப்பு அல்ல. சேவையின் கீழ் YAML உள்தள்ளலைச் சரியாக வைத்திருக்கவும். `INSECURE=true` லூப்பேக் SSH சுரங்கத்திற்காக மட்டும் HTTP அனுமதிக்கிறது. நிர்வாக போர்ட்டை இணையத்தில் வெளியிடாதீர்கள். கன்டெய்னரின் கேட்கும் முகவரியும் ஹோஸ்டின் லூப்பேக் மேப்பிங்கும் வேறு. மேல்நிலைத் திட்டத்தின் [HTTP அமைப்பைப்](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) பார்க்கவும்.

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

கன்டெய்னரின் `/etc/wireguard` தரவை அதன் நிலையான வால்யூமில் வைத்திருங்கள். பழைய `PASSWORD`, `PASSWORD_HASH`, `WG_HOST` வழிமுறைகளை v15-க்குப் பயன்படுத்தாதீர்கள்; அதன் அமைப்பு வழிகாட்டியைப் பயன்படுத்துங்கள். இமேஜ் திட்டமிட்டே ஒரு பதிப்புடன் பிணைக்கப்பட்டுள்ளது: மேம்படுத்த புதிய பதிப்பை ஆய்வு செய்து பிணைப்பை மாற்ற வேண்டும்; `pull` இயக்குவது மட்டும் போதாது.

## நிர்வாக UI திறந்து கிளையன்ட் சேர்க்கவும்

Mobile SSH-இல் உள்ளூர் போர்ட் `51821`, தொலை ஹோஸ்ட் `127.0.0.1`, தொலை போர்ட் `51821` கொண்டு [உள்ளூர் போர்ட் முன்னனுப்பலை](../port-forwarding/) உருவாக்கவும். SSH இணைப்பைச் செயலில் வைத்து அதே தொலைபேசியில் `http://127.0.0.1:51821` திறக்கவும். அந்த உள்ளூர் போர்ட் பயன்பாட்டில் இருந்தால் வேறொன்றைத் தேர்ந்தெடுத்து உலாவி URL-இல் பயன்படுத்தவும்.

wg-easy-இன் [முதன்முறை அமைப்பு வழிகாட்டியில்](https://wg-easy.github.io/wg-easy/latest/guides/setup/) நிர்வாகக் கணக்கை உருவாக்கி, புதிய நிறுவலைத் தேர்ந்தெடுத்து, VPN இணைப்பு முகவரியாக VM-இன் பொது IPv4 அல்லது DNS பெயரையும் போர்ட் `51820`-ஐயும் அமைக்கவும். VPN இணைப்பு முகவரி என்பது வலை UI-இன் லூப்பேக் முகவரியோ போர்ட் `51821`-ஓ அல்ல.

ஒவ்வொரு சாதனத்திற்கும் ஒரு கிளையன்ட் உருவாக்கி WireGuard `.conf` பதிவிறக்குங்கள். உங்கள் Mobile SSH கட்டமைப்பில் இருந்தால் **VPN → WireGuard** திறந்து சுயவிவரத்தைச் சேர்த்து கோப்பை இறக்குமதி செய்து சேமியுங்கள். தற்போதைய Android, iOS மூலக்குறியீடு கோப்பு இறக்குமதியை ஆதரிக்கிறது; நிறுவிய கட்டமைப்பைச் சரிபாருங்கள். பொருந்தும் Android கட்டமைப்புகளில் VPN Setup முதல் கிளையன்ட்டை நேரடியாக இறக்குமதி செய்யும். அதன் பக்கத்தில் தனிப்பட்ட SSH டனல் மூலம் **கிளையன்ட் சேர்**, **கிளையன்ட் ரத்துசெய்**, **கிளையன்ட்/QR ஏற்றுமதி**, **நிர்வாகம் திற** கிடைக்கும். பழைய செருகுநிரலிலோ சமமான iOS தானியக்கத்திலோ இவை இருப்பதை இது உறுதிப்படுத்தாது. அமைப்புக் கோப்புகளிலும் QR குறியீடுகளிலும் தனிச்சாவிகள் இருக்கும்; தனிப்பட்டதாக வைத்திருங்கள்.

## VPN சரிபார்த்து தோல்விகளைக் கையாளுங்கள்

சுயவிவரத்தைத் தொடங்கி இயங்குதளத்தின் VPN கோரிக்கையை அனுமதிக்கவும். அண்மைய பியர் கைகுலுக்கலையும் அதிகரிக்கும் போக்குவரத்து எண்ணிகளையும் பார்த்து, பின்னர் DNS மற்றும் எதிர்பார்த்த இணைய அல்லது தனிப்பட்ட வலையமைப்பு வழித்தடங்களைச் சோதிக்கவும். இறக்குமதி செய்த சுயவிவரமோ இயங்கும் கன்டெய்னரோ மட்டும் VPN வேலை செய்வதை நிரூபிக்காது.

- **VM உருவாக்கம் மறுக்கப்பட்டது:** கட்டணம், ஒதுக்கீட்டு வரம்பு, பகுதியின் கொள்ளளவு, சான்றுக் காலாவதி, துல்லியமான IAM அனுமதிகளைப் பார்க்கவும். Google Cloud ஃபயர்வால் எழுத Compute Network Admin-க்கு மேலான அனுமதிகள் தேவை; நிறுவனம் கட்டாயப்படுத்தும் OS Login-க்கு ஒப்புதல் பெற்ற கன்சோல் அமைப்பு தேவை.
- **SSH நேரம் முடிந்தது:** பொது முகவரி, சப்நெட் வழித்தடம், TCP 22 விதிகள், தொலைபேசியின் தற்போதைய மூல IP-ஐச் சரிபார்க்கவும். அங்கீகாரத் தோல்விகளுக்கு பொதுவாகச் சரியான இமேஜ் பயனர்பெயரும் SSH விசையும் தேவை.
- **நிர்வாக UI கிடைக்கவில்லை:** SSH முன்னனுப்பலை இணைத்தே வைத்திருந்து, கன்டெய்னர் நிலை, லூப்பேக் போர்ட் மேப்பிங்கைப் பார்த்து, சுரங்கத்திற்காக மட்டும் HTTP இயக்கப்பட்டதை உறுதிப்படுத்தவும்.
- **WireGuard கைகுலுக்கல் இல்லை:** கிளையன்ட் இணைப்பு முகவரி, இரு ஃபயர்வால் அடுக்குகளிலும் UDP 51820, கிளையன்ட் விசைகள், சர்வர் கேட்கிறதா என்பவற்றைப் பார்க்கவும்.
- **கைகுலுக்கல் உள்ளது, போக்குவரத்து இல்லை:** முன்னனுப்பல்/NAT, DNS, வழித்தட மோதல், `AllowedIPs` ஆகியவற்றை ஆய்வு செய்யவும். முழுச் சுரங்க IPv4-க்கு `0.0.0.0/0` பயன்படும்; IPv6-ஐத் தனியாக மதிப்பிடவும். மேல்நிலை IPv6 இல்லாத VM IPv6 இணைய வெளியேற்றத்தை வழங்க முடியாது; IPv4 மட்டும் கொண்ட வழித்தடங்கள் IPv6-ஐ VPN-க்கு வெளியே விடலாம்.

## செருகுநிரலையும் VPN சேவையகத்தையும் புதுப்பிக்கவும்

**செருகுநிரல்கள்** பகுதியில் அதே பட்டியலில் கிடைக்கும் புதிய பொருந்தும் பதிப்பிற்கு **புதுப்பி** செயல்பாட்டைப் பயன்படுத்துங்கள். புதிதாகக் கேட்கும் திறன்களைப் பரிசீலியுங்கள். அமைப்புகள், சான்றுகள், நிறுவல் பதிவுகள் வைக்கப்படும்; முடிக்காத செயல்பாடு தொடங்கிய செருகுநிரல் பதிப்பிலேயே தொடரும். செருகுநிரலை மட்டும் புதுப்பிப்பது சேவையக wg-easy கன்டெய்னரைப் புதுப்பிக்காது.

செருகுநிரல் பிரிட்ஜ் 1.4.0 அல்லது புதியதில் **சேவையகத்தைச் சோதி** இயங்கும் wg-easy பதிப்பைக் காட்டும்; **WireGuard புதுப்பி** செருகுநிரல் நிர்ணயித்த பதிப்பை வழங்கும். திரையில் புதுப்பிப்பை ஒப்புக்கொள்ளுங்கள். சேவையை மாற்றும்முன் இமேஜ் பதிவிறக்கப்பட்டு, சேவையகச் சாவிகள், கிளையன்ட்கள், உள்ளக சுயவிவரங்கள் பாதுகாக்கப்படும். இத்தொலைபேசி அந்த VPN-ஐ பயன்படுத்தினால் புதுப்பிக்கும்முன் செயலி துண்டிக்கும்; பிறகு மீண்டும் இணையுங்கள். இது நிர்வகிக்கும் கன்டெய்னரைப் புதுப்பிக்கும், ஹோஸ்ட் இயங்குதளத்தை அல்ல.

தோல்வியுற்ற புதுப்பிப்பு இமேஜ் பதிவிறக்கத் தோல்வி, வெற்றிகரமான பழையநிலை மீட்பு, VPN நிறுத்தத்துடன் முடியும் தோல்வியுற்ற மீட்பு ஆகியவற்றை வேறுபடுத்தும். சேவை திரும்பியதாக எண்ணாமல் மீட்புச் சோதனை அல்லது மறுமுயற்சியைப் பின்பற்றுங்கள். கைமுறை நிறுவல்களுக்கு தனியே பரிசீலித்த இமேஜ் பின் மாற்றமும் காப்புப்பிரதியும் தேவை; மேலுள்ள புதிய நிறுவல் செய்முறை இடமாற்ற வழிகாட்டி அல்ல.

## கிளையன்ட்களை அகற்றி கிளவுட் கட்டணங்களை நிறுத்துங்கள்

உள்ளூர் சுயவிவரத்தை அகற்றும்முன் wg-easy-இல் கிளையன்ட்டைத் திரும்பப்பெறுங்கள். Mobile SSH-இல் சுயவிவரத்தை நீக்குவது சர்வரின் பியர் விசையைத் திரும்பப்பெறாது. VPN கன்டெய்னரையோ அதன் நிலையான தரவையோ அகற்றும்முன் தேவையான அமைப்பைப் பாதுகாப்பாகக் காப்பெடுக்கவும்.

API மூலம் உருவாக்கிய நிறுவலில் **நிறுவலை நீக்கு** அதன் சொந்த கிளவுட் வளங்களைப் பரிசீலித்து வழங்குநர் API வழியாக நீக்கும்; SSH கிடைக்காவிட்டாலும் இயங்கும். நீக்கம் இடைநிறுத்தப்பட்டால் அல்லது தோல்வியுற்றால் மீதமுள்ளதாகக் காட்டும் வளங்களைப் பாருங்கள்; அகற்றலைத் தொடருங்கள் அல்லது கன்சோலைப் பாருங்கள். செருகுநிரல் நிர்வகிக்கும் நிறுவலில், குறிப்பாக அதன் தனி Azure வளக் குழுவில், தொடர்பற்ற வளங்களை வைக்காதீர்கள்.

கன்சோலில் உருவாக்கிய அல்லது இருக்கும் சேவையகத்தில் செருகுநிரல் நீக்கம் அதன் நிர்வகித்த VPN நிறுவலை அகற்றும்; உங்கள் VM அல்லது பொது IP-ஐ **நீக்காது**. தேவை முடிந்ததும் வழங்குநர் கன்சோலில் அவற்றை நீக்கி, மீந்த வட்டுகள், ஸ்னாப்ஷாட்கள், முகவரிகள், வலையமைப்பு வளங்களைச் சரிபாருங்கள். மீட்பின்போது கணக்கு அல்லது இட அமைப்புகள் மாறியிருந்தால் பழைய கணக்கு மற்றும் இடத்தையும் பாருங்கள்; பழைய Scaleway திட்டம் அல்லது Oracle Cloud கம்பார்ட்மென்ட்டும் இதில் அடங்கும்.

**பணிப்பாய்வை நிறுத்து** செயல்பாட்டை நிறுத்தும்; வளங்களை நீக்காது. பிரிட்ஜ் 1.5.0 அல்லது புதியதில், பதிவு மறக்கத் தகுதியானது, முடிக்காத செயல்பாடுகளோ மீதமுள்ள நிர்வகித்த வளங்களோ இல்லை என்பதை செயலி உறுதிப்படுத்தினால் மட்டுமே **பட்டியலிலிருந்து அகற்று** கிடைக்கும். இது உள்ளக வரலாற்றை அழிக்கும், கிளவுட் வளங்களை அல்ல. VM நிறுத்துவதோ செருகுநிரலை அகற்றுவதோ கட்டணம் நிற்பதை உறுதிப்படுத்தாது. நீக்கம் உறுதியாகும்வரை வள ID-களை வைத்திருங்கள்.
