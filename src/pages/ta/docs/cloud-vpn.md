# கிளவுட் VM மற்றும் wg-easy

உங்கள் கிளவுட் கணக்கில் Linux VM உருவாக்கி, Mobile SSH மூலம் இணைந்து, WireGuard VPN இயக்க wg-easy நிறுவுங்கள். வளங்களை உருவாக்குவதையும் நிறுவுவதையும் பிரித்து வைத்தால், அதே VM-ஐ வேறொரு சேவைக்குப் பயன்படுத்தலாம் அல்லது ஏற்கெனவே உள்ள சர்வரில் VPN நிறுவலாம்.

**கிடைக்கும் நிலை — 8 நவம்பர் 2026:** கீழே விவரிக்கும் திட்டமிட்ட பணிமுறையில் VM உருவாக்கத் தனிச் செருகுநிரல்கள் உள்ளன. ஆய்வு செய்யப்பட்ட உள்ளூர் Android **VPN Setup** செயலாக்கம் வள உருவாக்கம், நிறுவல், கிளையன்ட் இறக்குமதி ஆகியவற்றை ஒன்றாகச் செய்கிறது; அதன் செருகுநிரல்/பட்டியல் மாற்றங்கள் இன்னும் வெளியிடப்படவில்லை; உண்மையான கிளவுட் நிறுவல்களும் சோதிக்கப்படவில்லை. தனித்தனி AWS, Google Cloud, Azure பதிவுகள் தற்போது மெனிஃபெஸ்ட்/அமைப்புகளுக்கான தொடக்கக் கட்டமைப்புகளாக மட்டுமே உள்ளன; அவற்றின் VM பட்டியலிடல் மற்றும் கட்டுப்பாட்டுச் செயல்கள் செயல்படுத்தப்படவில்லை, அவை VM-களையும் உருவாக்குவதில்லை. உங்கள் பட்டியலில் உருவாக்கும் பணிமுறை இல்லாவிட்டால் கீழுள்ள கன்சோல் மற்றும் கைமுறை நிறுவல் வழிமுறைகளைப் பயன்படுத்துங்கள். புதிய நேட்டிவ் பணிமுறைக்குப் பொருந்தும் Android பதிப்பு தேவை; அதற்கு இணையான iOS தானியக்கச் செயல்பாடு நிறுவப்படவில்லை.

## தனித்தனி பொறுப்புகளுடன் இரண்டு செருகுநிரல்கள்

- **கிளவுட் வள உருவாக்கி:** வழங்குநரின் API மூலம் VM, பொது முகவரி, தேவையான வலையமைப்பு வளங்களை உருவாக்கி, SSH இணைப்பைச் சேமிக்கிறது. பின்னர் நிர்வகிக்க அல்லது நீக்கத் தேவையான கிளவுட் வள ID-களை வைத்திருக்கிறது.
- **wg-easy நிறுவி:** தேர்ந்தெடுத்த சேமிக்கப்பட்ட சர்வருடன் SSH மூலம் இணைந்து, VPN சேவையை நிறுவி, கிளையன்ட் அமைப்பை உருவாக்க உதவுகிறது. இதற்குச் சர்வர் அணுகலும் நிர்வாக உரிமைகளும் தேவை; உங்கள் கிளவுட் API சான்றுகள் தேவையில்லை. கைமுறையாக உருவாக்கிய VM-ஐயும் பயன்படுத்தலாம்.

பணியை ஒப்படைக்கும்போது சேமித்த சர்வரின் குறிப்பு, பொது முகவரி, SSH போர்ட், பயனர்பெயர், SSH சான்றுக் குறிப்பு, நிறுவல்/வள ID-கள் இடம்பெற வேண்டும். கிளவுட் ரகசியங்களையும் SSH தனிப்பட்ட விசைகளையும் செருகுநிரல் வெளியீட்டிலோ VM-இலோ நகலெடுக்கக் கூடாது. VPN-ஐ அகற்றுவதும் கிளவுட் VM-ஐ நீக்குவதும் தனித்தனி செயல்கள்.

## கணக்கையும் சர்வர் அமைப்புகளையும் தயார்செய்யுங்கள்

1. கிளவுட் கணக்கையும் கட்டண வசதியையும் செயல்படுத்தி, பகுதியைத் தேர்ந்தெடுத்து, VM, வட்டு, பொது IP ஒதுக்கீட்டு வரம்புகளைச் சரிபாருங்கள். வழங்குநரின் தற்போதைய VM, IPv4, சேமிப்பு, போக்குவரத்துக் கட்டணங்களைப் பாருங்கள்; இலவசத் திட்டம் கிடைக்கும் என்று கருதப்படவில்லை.
2. இந்த வழிகாட்டிக்கு **amd64 அல்லது arm64** கட்டமைப்பில் குறைந்தது **1 GB RAM மற்றும் 20 GB வட்டு** கொண்ட தனியான **Ubuntu 24.04 LTS** VM தேர்ந்தெடுக்கவும். இவை இந்த அமைப்பின் அடிப்படைத் தேர்வுகள்; wg-easy-க்கான பொதுவான குறைந்தபட்சத் தேவைகள் அல்ல. root அல்லது sudo அணுகலுள்ள உள்நுழைவைப் பயன்படுத்துங்கள்; மேற்பார்வையற்ற நிறுவலுக்கு இடையில் கேள்வி கேட்காமல் உரிமைகளை உயர்த்த இயல வேண்டும்.
3. SSH விசையைத் தேர்ந்தெடுங்கள் அல்லது உருவாக்குங்கள்; தனிப்பட்ட விசையை Mobile SSH-இல் வைத்திருங்கள். பொது விசையை மட்டும் கிளவுட்டில் பதிவேற்றுங்கள். Lightsail இறக்குமதி முறைக்கு RSA SSH விசை தேவை. பிற வழங்குநர்களும் இமேஜ்களும் ஏற்கும் விசை வகைகள் வேறுபடலாம். தற்போதைய iOS SSH கிளையன்ட் RSA தனிப்பட்ட விசைகளுக்குப் பதிலாக Ed25519/ECDSA-ஐ ஆதரிக்கிறது. iOS-இல் Lightsail பயன்படுத்த, முதலில் வழங்குநரின் உலாவி SSH கன்சோல் மூலம் செயலி ஆதரிக்கும் பொது விசையை `authorized_keys`-இல் சேர்த்து, பின்னர் அந்த விசையுடன் இணையுங்கள்.
4. **பொது IPv4** தேர்ந்தெடுக்கவும்; வழங்குநர் அளித்தால் ஒதுக்கிவைத்த/நிலையான முகவரிக்கு முன்னுரிமை கொடுங்கள். தனிப்பட்ட முகவரி, IPv6 மட்டும் உள்ள இயந்திரம் அல்லது வெளிச்செல்லும் போக்குவரத்துக்கான NAT கேட்வே மட்டும் இந்த வழிகாட்டியின் இணைப்பு முகவரித் தேவையை நிறைவேற்றாது.
5. SSH மூல CIDR-ஐ வெளிப்படையாக அமைக்கவும்; உதாரணமாக தற்போதைய பொது IPv4-க்குப் பின் `/32`. செருகுநிரலின் இயல்புநிலை அணுகலைக் கட்டுப்படுத்தும் என்று கருத வேண்டாம். மொபைல் தரவு அல்லது Wi-Fi மாறும்போது கிளவுட் கன்சோலில் விதியை மாற்ற வேண்டியிருக்கலாம்.

கிளவுட் API சான்றுகள் வள மேலாண்மையை அனுமதிக்கின்றன; SSH விசைகள் சர்வர் உள்நுழைவை அனுமதிக்கின்றன. அவை வெவ்வேறு சான்றுகள். API ரகசியங்களை வழங்குநரின் பாதுகாக்கப்பட்ட சான்றுப் படிவத்தில் மட்டும் உள்ளிடுங்கள்; குரல் கோரிக்கைகள், முனையக் கட்டளைகள் அல்லது மூலக் கோப்புகளில் ஒருபோதும் இடாதீர்கள். உள்ளூர் Android பணிமுறையில் நேட்டிவ் நிரல் வழங்குநர் அங்கீகாரத்தையும் மறையாக்கப்பட்ட சான்றுச் சேமிப்பையும் கையாள்கிறது; தேவைப்படும்போது சான்றுகள் அவற்றின் வழங்குநருக்கு அனுப்பப்படுகின்றன, VM அல்லது செருகுநிரல் பணியாளருக்கு அல்ல. ஆஃப்லைன் குரல் மாதிரி இருப்பதால் கிளவுட் API அழைப்புகள், பதிவிறக்கங்கள் அல்லது SSH இணையமின்றி வேலை செய்யாது.

## கிளவுட்டைத் தேர்ந்தெடுத்துப் பொது முகவரியைப் பெறுங்கள்

**கன்சோல் அமைப்புக்கு** வழங்குநரிடம் நீங்களே உள்நுழையுங்கள்; Mobile SSH-க்கு அதன் API சான்றுகள் தேவையில்லை. வருங்கால **செருகுநிரல் வள உருவாக்கத்துக்கு**, கீழே காட்டிய சான்றுகளைத் தேவையான உருவாக்கல், படித்தல், வலையமைப்பு, நீக்கல் அனுமதிகளுடன் தயார்செய்யுங்கள். ஆதரிக்கப்படும் இடங்களில் அணுகலைத் தனித் திட்டம் அல்லது நிறுவலுக்குள் வரையறுக்கவும். இரு முறைகளுக்கும் கணக்குக் கொள்கைகள் பொருந்தும்.

உங்கள் SSH பொது விசையுடன் தேர்ந்தெடுத்த Ubuntu VM-ஐ உருவாக்கி, அடுத்த பகுதியிலுள்ள SSH விதியைப் பயன்படுத்துங்கள். இணைப்புகள் வழங்குநருக்குரிய முகவரி மற்றும் அங்கீகாரப் படிகளை விளக்குகின்றன.

## வளங்களை உருவாக்கி SSH இணைப்பைச் சேமியுங்கள்

திட்டமிட்ட தனித்தனி பணிமுறையில் **செருகுநிரல்கள்** திறந்து, நம்பகமான பட்டியலிலிருந்து வழங்குநரின் வள உருவாக்கச் செருகுநிரலை நிறுவி, அதன் கணக்கையும் பகுதியையும் தேர்ந்தெடுத்து, VM அளவு, இமேஜ், பொது முகவரி, SSH விசையைத் தேர்ந்தெடுக்கவும். உருவாக்கத்தை உறுதிப்படுத்தும்முன் வளங்களையும் செலவுகளையும் பார்வையிடுங்கள். உருவாக்கும் செயல் இல்லாத மேலாண்மைச் செருகுநிரல் இந்தப் படியைச் செய்ய முடியாது; வழங்குநரின் கன்சோலைப் பயன்படுத்துங்கள்.

VM இயங்குவதாக வழங்குநர் தெரிவிக்கும் வரையும் SSH அணுகக்கூடியதாகும் வரையும் காத்திருங்கள். VM, வட்டு, முகவரி, ஃபயர்வால் வள ID-களை வைத்திருங்கள். கோரிக்கையின் நேரம் முடிந்தால் மீண்டும் உருவாக்கும்முன் தற்போதைய செயலை ஆய்வு செய்யுங்கள் அல்லது தொடருங்கள்; இல்லையெனில் கட்டணம் வசூலிக்கும் இரண்டாவது VM உருவாகலாம்.

கிடைத்த இணைப்பை Mobile SSH-இல் சேமிக்கவும் அல்லது **சர்வர்கள்** பகுதியில் கைமுறையாகச் சேர்க்கவும்: பொது IPv4, SSH போர்ட் `22`, இமேஜின் பயனர்பெயர், பொருந்தும் தனிப்பட்ட விசைச் சான்று. இணைவதற்கு முன் வழங்குநரின் நம்பகமான கன்சோல் மூலம் SSH ஹோஸ்ட் விசைக் கைரேகையை ஒப்பிடுங்கள். அடையாளச் சரிபார்ப்புக்கும் சேமித்த சான்றுகளுக்கும் [தொடங்குதல்](../getting-started/) பார்க்கவும்.

## வலையமைப்பின் இரண்டு அடுக்குகளையும் அமைக்கவும்

பொது முகவரிக்கு வழித்தடம், கிளவுட் ஃபயர்வால் அனுமதி, விருந்தினர் இயந்திர ஃபயர்வால் அனுமதி, கேட்கும் சேவை ஆகியவை தேவை. வழங்குநரின் ஃபயர்வால்/பாதுகாப்புக் குழுவில் இந்த விதிகளைப் பயன்படுத்துங்கள்; தேவையான தற்போதைய விருந்தினர் விதிகளைப் பாதுகாக்கவும்.

- **TCP 22:** SSH-க்கு நீங்கள் தேர்ந்தெடுத்த மேலாண்மை CIDR-இலிருந்து அனுமதிக்கவும். வள உருவாக்கத்தின்போது அமைக்கவும்.
- **UDP 51820:** VPN பயன்படுத்தும் வலையமைப்புகளிலிருந்து அனுமதிக்கவும். இடம்மாறும் கிளையன்ட்களுக்கு இது `0.0.0.0/0` ஆக இருக்கலாம். WireGuard அமைக்கும்போது கிளவுட் வள உருவாக்கி அல்லது கன்சோல் மூலம் சேர்க்கவும்.
- **TCP 51821:** பொதுவெளியில் மூடியே வைத்திருக்கவும். wg-easy நிர்வாக UI-ஐ சர்வர் லூப்பேக்கில் மட்டும் வெளியிட்டு SSH சுரங்கம் மூலம் அணுகவும்.
- **வெளிச்செல்லும் போக்குவரத்து:** தொகுப்பு/கன்டெய்னர் பதிவிறக்கங்கள், DNS, VPN கொண்டுசெல்ல வேண்டிய இணையப் போக்குவரத்தை அனுமதிக்கவும்.

Docker-இன் [ஃபயர்வால் நடத்தையை](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations) சரிபாருங்கள்: வெளியிடப்பட்ட கன்டெய்னர் போர்ட்கள் UFW விதிகளைத் தவிர்க்கலாம். நிர்வாக UI-ஐ மறைக்க UFW-ஐ மட்டும் நம்பாதீர்கள்; வழங்குநரின் ஃபயர்வால் சங்கிலிகளை, குறிப்பாக OCI சேமிப்பு/iSCSI விதிகளை, அழிக்காதீர்கள்.

## தேர்ந்தெடுத்த VM-இல் wg-easy நிறுவுங்கள்

தனி நிறுவி சேமித்த SSH சர்வரை ஏற்று சர்வர் மாற்றங்களுக்கு அனுமதி கேட்க வேண்டும். OS, உரிமைகள், தற்போதைய Docker/VPN நிறுவல், போர்ட் முரண்பாடுகளைச் சரிபார்த்து, நிலையான தரவைப் பாதுகாத்து, நிறுவிய பதிப்பைக் காட்ட வேண்டும். கிளவுட் கணக்கு ரகசியம் அதற்குத் தேவையில்லை; கிளவுட் ஃபயர்வால் மாற்றங்களுக்கு வள உருவாக்கி அல்லது கன்சோலைப் பயன்படுத்துங்கள்.

பழைய **WireGuard (wg-easy)** பட்டியல் செருகுநிரலுக்கு செயலில் உள்ள SSH அமர்வும் Docker-மும் தேவை. அது புதிய தானியக்க நிறுவி அல்ல; நேட்டிவ் கிளையன்ட் இறக்குமதியை உறுதியளிப்பதில்லை. பொருந்தும் புதுப்பிக்கப்பட்ட நிறுவியைப் பயன்படுத்தவும் அல்லது புதிய தனி VM-இல் Mobile SSH முனையம் மூலம் பின்வரும் கைமுறை வழியைப் பயன்படுத்தவும்.

### SSH மூலம் கைமுறை நிறுவல்

அதிகாரப்பூர்வ [Ubuntu வழிமுறைகள்](https://docs.docker.com/engine/install/ubuntu/) மூலம் Docker Engine மற்றும் அதன் Compose செருகுநிரலை நிறுவவும். பின்னர் பதிப்புக்குரிய மேல்நிலைத் திட்ட அமைப்பைப் பதிவிறக்கவும்:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.4.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

தொடங்குவதற்கு முன் நிர்வாக உரிமையுள்ள முனையத் திருத்தியில் `/opt/wg-easy/compose.yaml`-ஐத் திருத்தவும். `services.wg-easy` கீழ் இமேஜை மாற்றி, environment பகுதியின் கருத்துக்குறியை நீக்கி/அமைத்து, போர்ட் மேப்பிங்குகளை இந்த மதிப்புகளால் மாற்றவும். நிலையான வால்யூம், தொகுதி மவுண்ட், திறன்கள், வலையமைப்புகள், sysctls உட்பட மேல்நிலைக் கோப்பின் மற்ற பகுதிகளை வைத்திருக்கவும்:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.4.0@sha256:0e7bc9d34e86ddcaa92bc700d4d7dc9b33291dbc07ac8d13382f7c2095f949ec
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

இது மாற்ற வேண்டிய பகுதி; முழுமையான Compose கோப்பு அல்ல. சேவையின் கீழ் YAML உள்தள்ளலைச் சரியாக வைத்திருக்கவும். `INSECURE=true` லூப்பேக் SSH சுரங்கத்திற்காக மட்டும் HTTP அனுமதிக்கிறது. நிர்வாக போர்ட்டை இணையத்தில் வெளியிடாதீர்கள். கன்டெய்னரின் கேட்கும் முகவரியும் ஹோஸ்டின் லூப்பேக் மேப்பிங்கும் வேறு. மேல்நிலைத் திட்டத்தின் [HTTP அமைப்பைப்](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) பார்க்கவும்.

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

கன்டெய்னரின் `/etc/wireguard` தரவை அதன் நிலையான வால்யூமில் வைத்திருங்கள். பழைய `PASSWORD`, `PASSWORD_HASH`, `WG_HOST` வழிமுறைகளை v15-க்குப் பயன்படுத்தாதீர்கள்; அதன் அமைப்பு வழிகாட்டியைப் பயன்படுத்துங்கள். இமேஜ் திட்டமிட்டே ஒரு பதிப்புடன் பிணைக்கப்பட்டுள்ளது: மேம்படுத்த புதிய பதிப்பை ஆய்வு செய்து பிணைப்பை மாற்ற வேண்டும்; `pull` இயக்குவது மட்டும் போதாது.

## நிர்வாக UI திறந்து கிளையன்ட் சேர்க்கவும்

Mobile SSH-இல் உள்ளூர் போர்ட் `51821`, தொலை ஹோஸ்ட் `127.0.0.1`, தொலை போர்ட் `51821` கொண்டு [உள்ளூர் போர்ட் முன்னனுப்பலை](../port-forwarding/) உருவாக்கவும். SSH இணைப்பைச் செயலில் வைத்து அதே தொலைபேசியில் `http://127.0.0.1:51821` திறக்கவும். அந்த உள்ளூர் போர்ட் பயன்பாட்டில் இருந்தால் வேறொன்றைத் தேர்ந்தெடுத்து உலாவி URL-இல் பயன்படுத்தவும்.

wg-easy-இன் [முதன்முறை அமைப்பு வழிகாட்டியில்](https://wg-easy.github.io/wg-easy/latest/guides/setup/) நிர்வாகக் கணக்கை உருவாக்கி, புதிய நிறுவலைத் தேர்ந்தெடுத்து, VPN இணைப்பு முகவரியாக VM-இன் பொது IPv4 அல்லது DNS பெயரையும் போர்ட் `51820`-ஐயும் அமைக்கவும். VPN இணைப்பு முகவரி என்பது வலை UI-இன் லூப்பேக் முகவரியோ போர்ட் `51821`-ஓ அல்ல.

ஒவ்வொரு சாதனத்துக்கும் ஒரு கிளையன்ட் உருவாக்கி அதன் WireGuard `.conf` கோப்பைப் பதிவிறக்கவும். உங்கள் Mobile SSH பதிப்பில் வசதி இருந்தால் **VPN → WireGuard** திறந்து, சுயவிவரம் சேர்த்து, கோப்பை இறக்குமதி செய்து சேமிக்கவும். தற்போதைய Android, iOS மூல நிரல்கள் கோப்பு இறக்குமதியை ஆதரிக்கின்றன; நிறுவிய பதிப்பைச் சரிபாருங்கள். உள்ளூர் Android ஒருங்கிணைந்த பணிமுறை நேரடியாக இறக்குமதி செய்யலாம்; இது பழைய செருகுநிரல் அல்லது iOS தானியக்கத்துக்கான உறுதியல்ல. அமைப்புக் கோப்புகளிலும் QR குறியீடுகளிலும் தனிப்பட்ட விசைகள் உள்ளன; அவற்றைத் தனிப்பட்டதாக வைத்திருங்கள்.

## VPN சரிபார்த்து தோல்விகளைக் கையாளுங்கள்

சுயவிவரத்தைத் தொடங்கி இயங்குதளத்தின் VPN கோரிக்கையை அனுமதிக்கவும். அண்மைய பியர் கைகுலுக்கலையும் அதிகரிக்கும் போக்குவரத்து எண்ணிகளையும் பார்த்து, பின்னர் DNS மற்றும் எதிர்பார்த்த இணைய அல்லது தனிப்பட்ட வலையமைப்பு வழித்தடங்களைச் சோதிக்கவும். இறக்குமதி செய்த சுயவிவரமோ இயங்கும் கன்டெய்னரோ மட்டும் VPN வேலை செய்வதை நிரூபிக்காது.

- **VM உருவாக்கம் மறுக்கப்பட்டது:** கட்டணம், ஒதுக்கீட்டு வரம்பு, பகுதியின் கொள்ளளவு, சான்றுக் காலாவதி, துல்லியமான IAM அனுமதிகளைப் பார்க்கவும். Google Cloud ஃபயர்வால் எழுத Network Admin-க்கு மேலான அனுமதிகள் தேவை.
- **SSH நேரம் முடிந்தது:** பொது முகவரி, சப்நெட் வழித்தடம், TCP 22 விதிகள், தொலைபேசியின் தற்போதைய மூல IP-ஐச் சரிபார்க்கவும். அங்கீகாரத் தோல்விகளுக்கு பொதுவாகச் சரியான இமேஜ் பயனர்பெயரும் SSH விசையும் தேவை.
- **நிர்வாக UI கிடைக்கவில்லை:** SSH முன்னனுப்பலை இணைத்தே வைத்திருந்து, கன்டெய்னர் நிலை, லூப்பேக் போர்ட் மேப்பிங்கைப் பார்த்து, சுரங்கத்திற்காக மட்டும் HTTP இயக்கப்பட்டதை உறுதிப்படுத்தவும்.
- **WireGuard கைகுலுக்கல் இல்லை:** கிளையன்ட் இணைப்பு முகவரி, இரு ஃபயர்வால் அடுக்குகளிலும் UDP 51820, கிளையன்ட் விசைகள், சர்வர் கேட்கிறதா என்பவற்றைப் பார்க்கவும்.
- **கைகுலுக்கல் உள்ளது, போக்குவரத்து இல்லை:** முன்னனுப்பல்/NAT, DNS, வழித்தட மோதல், `AllowedIPs` ஆகியவற்றை ஆய்வு செய்யவும். முழுச் சுரங்க IPv4-க்கு `0.0.0.0/0` பயன்படும்; IPv6-ஐத் தனியாக மதிப்பிடவும். மேல்நிலை IPv6 இல்லாத VM IPv6 இணைய வெளியேற்றத்தை வழங்க முடியாது; IPv4 மட்டும் கொண்ட வழித்தடங்கள் IPv6-ஐ VPN-க்கு வெளியே விடலாம்.

## கிளையன்ட்களை அகற்றி கிளவுட் கட்டணங்களை நிறுத்துங்கள்

உள்ளூர் சுயவிவரத்தை அகற்றும்முன் wg-easy-இல் கிளையன்ட்டைத் திரும்பப்பெறுங்கள். Mobile SSH-இல் சுயவிவரத்தை நீக்குவது சர்வரின் பியர் விசையைத் திரும்பப்பெறாது. VPN கன்டெய்னரையோ அதன் நிலையான தரவையோ அகற்றும்முன் தேவையான அமைப்பைப் பாதுகாப்பாகக் காப்பெடுக்கவும்.

தேவையில்லாத VM-ஐ அதற்கு உரிய வள உருவாக்கி அல்லது வழங்குநர் கன்சோல் மூலம் நீக்கி, பின்னர் தக்கவைக்கப்பட்ட வட்டுகள், ஸ்னாப்ஷாட்கள், ஒதுக்கப்பட்ட/பொது முகவரிகள், வலையமைப்பு வளங்களைச் சரிபார்க்கவும். தனியான Azure வளக் குழுவை நீக்கும்முன் அதன் உள்ளடக்கங்களைப் பார்வையிடவும். தொடர்பில்லாத வளங்களைச் செருகுநிரல் நிர்வகிக்கும் நிறுவலுக்கு வெளியே வைத்திருக்கவும்.

VM-ஐ நிறுத்துவது, அமைப்புப் பணியை ரத்து செய்வது அல்லது செருகுநிரலை அகற்றுவது வளங்கள் நீங்கிவிட்டன அல்லது கட்டணங்கள் நின்றுவிட்டன என்பதற்கு உத்தரவாதமல்ல. கன்சோலில் உருவாக்கிய வளங்களை நீக்குவது உங்கள் பொறுப்பாகவே இருக்கும்; நீக்கல் உறுதியாகும்வரை வழங்குநரின் வள ID-களை வைத்திருங்கள்.
