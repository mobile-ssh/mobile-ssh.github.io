# Облачные ВМ и wg-easy

Создайте Linux-ВМ в своём облачном аккаунте и запустите WireGuard VPN с wg-easy. На совместимых сборках Android опубликованный плагин **VPN Setup** может создать ВМ, установить wg-easy и импортировать клиента в одной пошаговой операции. Можно также создать ВМ в консоли провайдера и установить VPN через Mobile SSH либо использовать существующий публичный сервер.

**Доступность — 19 ноября 2026 года:** **VPN Setup 1.0.7** опубликован в [стандартном каталоге плагинов](https://github.com/mobile-ssh/mobile-ssh-plugins/tree/main/plugins/vpnsetup). Базовая настройка требует моста плагинов **1.3.0**, обновления сервера — **1.4.0**, удаление подходящих завершённых записей — **1.5.0**. Доступность зависит от установленной сборки Android и канала выпуска; публикация плагина не подтверждает доступность конкретного выпуска приложения для вас. Аналогичная автоматизация iOS не подтверждена. Если плагин недоступен, следуйте инструкциям для консоли и ручной установки ниже.

## Выберите пошаговую или ручную настройку

- **Создать через облачный API:** VPN Setup использует ваш аккаунт провайдера для создания ВМ и сетевых ресурсов, сохраняет подключение SSH, устанавливает wg-easy и импортирует клиента. Идентификаторы ресурсов и записи об их принадлежности сохраняются для последующей очистки.
- **Создать в облачной консоли или использовать существующий сервер:** создайте ВМ самостоятельно, затем укажите в VPN Setup её публичный IPv4, имя пользователя SSH и ключ либо выполните ручную установку ниже. Для установки на вашем сервере плагину не нужны учётные данные облачного API.

Опубликованный плагин объединяет создание ресурсов и установку; отдельные плагины для этих задач остаются планируемой архитектурой. Удаление ресурсов, созданных через API, и предоставленных вами серверов различается — подробности ниже. Зафиксированный тест на реальном Hetzner успешно проверил настройку, VPN-трафик, управление клиентами, закрытое администрирование и очистку на эмуляторе Android. Это не подтверждает проверку каждого провайдера, политики аккаунта или физического телефона.

## Подготовьте учётную запись и параметры сервера

1. Активируйте облачную учётную запись и оплату, выберите регион, проверьте квоты на ВМ, диски и публичные IP. Изучите актуальные тарифы на машины, IPv4, хранение и трафик; доступность бесплатного тарифа не предполагается.
2. Для этой инструкции выберите отдельную ВМ **Ubuntu 24.04 LTS** с минимум **1 ГБ ОЗУ и диском 20 ГБ**, архитектурой **amd64 или arm64**. Это базовые параметры данного процесса, а не универсальный минимум для wg-easy. Пользователь должен иметь доступ root или sudo; автоматической установке требуется повышение привилегий без интерактивного ввода.
3. Выберите или создайте ключ SSH, оставив закрытый ключ в Mobile SSH. В облако загружайте только открытый ключ. Для импорта SSH-ключа в Lightsail нужен RSA. У других провайдеров и образов свои допустимые типы ключей. Текущий клиент SSH для iOS поддерживает закрытые ключи Ed25519/ECDSA, но не RSA. Для Lightsail на iOS сначала через браузерную консоль SSH провайдера добавьте поддерживаемый приложением открытый ключ в `authorized_keys`, затем подключитесь с этим ключом.
4. Выберите **публичный IPv4**, желательно зарезервированный или статический, если провайдер это поддерживает. Частный адрес, машина только с IPv6 или шлюз NAT только для исходящих соединений не соответствуют требованиям этой инструкции.
5. Явно задайте исходный CIDR для SSH, например текущий публичный IPv4 с окончанием `/32`. Не считайте, что значение плагина по умолчанию ограничивает доступ. При переходе между мобильной сетью и Wi-Fi может потребоваться изменить правило в облачной консоли.

Ручной способ поддерживает архитектуры, указанные выше. Сейчас VPN Setup выбирает **Ubuntu 24.04 на amd64/x86-64**, подключается к **порту SSH 22** и принимает ключи SSH **Ed25519 или RSA**; для Lightsail нужен RSA. Ключи ECDSA, серверы только с частными адресами и конечные точки только с IPv6 не поддерживаются этим процессом. Существующему серверу нужны публичный IPv4 и неинтерактивный административный доступ.

Учётные данные облачного API разрешают управление ресурсами, а ключи SSH — вход на сервер. Вводите секреты API только в защищённой нативной форме, никогда в голосовых запросах, командах терминала или исходных файлах. Нативный код аутентифицируется на одобренных адресах провайдера; секреты не передаются ВМ или рабочему процессу плагина. Сохранённые данные шифруются через Android Keystore; если отказаться от сохранения, они остаются в памяти и после завершения процесса приложения могут потребовать повторного ввода.

Голосовое управление позволяет отвечать на поддерживаемые несекретные вопросы и сообщать о ходе работы, но ввод учётных данных и подтверждения требуют экрана. Захват микрофона приостанавливается для защищённых форм и возобновляется только явным действием. Голосовую настройку нужно отдельно включить, загрузить локальную модель и разрешить микрофон. Автономная голосовая модель не позволяет вызывать облачные API, загружать данные или работать по SSH без интернета.

Плагин реализует десять провайдеров из таблицы; AWS EC2 доступен отдельно только через консоль. Где возможно, ограничьте доступ отдельным проектом или развёртыванием. Политики аккаунта действуют для обоих способов.

## Создайте ВМ и сохраните подключение SSH

Откройте **Плагины**, установите **VPN Setup** из стандартного каталога и откройте его отдельную страницу. Выберите **Настроить VPN**, провайдера, затем **Создать через облачный API** или **Создать в облачной консоли**. Для уже имеющегося сервера выберите вариант существующего публичного сервера. Введите учётные данные в нативной форме, выберите или создайте ключ SSH и проверьте регион, размер, образ и исходный CIDR для SSH. Выбор вариантов по данным аккаунта и предварительные проверки помогают найти поддерживаемые предложения, но не резервируют мощности и не гарантируют квоты. Проверьте текущие цены провайдера и подтвердите создание на экране.

Следите за текущей операцией до готовности ВМ и SSH. При тайм-ауте или приостановке фоновой работы Android продолжите или проверьте эту операцию, чтобы не создать ещё одну платную ВМ. Если ответ на создание потерян, может потребоваться поиск в облаке или проверка консоли. Сохраните ID ВМ, диска, адреса и брандмауэра; остановленная операция всё равно могла создать ресурсы.

VPN Setup запрашивает подтверждение ключа хоста SSH, сохраняет подключение, устанавливает wg-easy и импортирует первого клиента. Сверьте отпечаток в доверенной консоли провайдера. При ручной настройке добавьте сервер в **Серверы** с публичным IPv4, портом SSH `22`, именем пользователя образа и соответствующим закрытым ключом. Автоматические адаптеры Google Cloud и Azure используют `ubuntu`; руководства по консоли — имена, настроенные там. Проверка идентификации и сохранение учётных данных описаны в [Начале работы](../getting-started/).

## Настройте оба уровня сети

Публичному адресу нужны маршрут, разрешение облачного межсетевого экрана, разрешение межсетевого экрана гостевой ОС и слушающая служба. Примените следующие правила в межсетевом экране или группе безопасности провайдера; сохраните необходимые существующие правила гостевой ОС.

- **TCP 22:** разрешите SSH из выбранного административного CIDR при создании ресурсов.
- **UDP 51820:** разрешите сети, из которых будет использоваться VPN. Для перемещающихся клиентов это может быть `0.0.0.0/0`. VPN Setup настраивает правило для ресурсов, созданных через API; для своего сервера используйте облачную консоль.
- **TCP 51821:** оставьте закрытым публично. Публикуйте админ-интерфейс wg-easy только на loopback сервера и открывайте его через SSH-туннель.
- **Исходящий трафик:** разрешите загрузку пакетов/контейнеров, DNS и интернет-трафик, который должен проходить через VPN.

Изучите [работу Docker с межсетевыми экранами](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations): опубликованные порты контейнеров могут обходить правила UFW. Не полагайтесь только на UFW для защиты веб-интерфейса и не очищайте цепочки межсетевого экрана провайдера, особенно правила хранилища/iSCSI в OCI.

## Установите wg-easy на выбранную ВМ

После подтверждения VPN Setup устанавливает по SSH выпуск wg-easy, закреплённый по digest, при необходимости устанавливает Docker на Ubuntu 24.04 и создаёт первого клиента. Админ-интерфейс остаётся на loopback сервера, цепочки брандмауэра провайдера сохраняются. Для созданного в консоли или существующего сервера настройте облачный брандмауэр сами; установщику нужны SSH и административные права, а не секрет облачного API. Используйте новый выделенный сервер: не рассчитывайте, что он подхватит постороннюю установку VPN.

Старый плагин каталога **WireGuard (wg-easy)** требует активной SSH-сессии и Docker. Он отличается от **VPN Setup** и не обещает нативный импорт клиента. Используйте VPN Setup на совместимой сборке Android либо ручной способ ниже из терминала Mobile SSH на новой выделенной ВМ.

### Ручная установка через SSH

Установите Docker Engine и его плагин Compose по официальной [инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/). Затем загрузите конфигурацию нужной версии из исходного проекта:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.5.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

Перед запуском отредактируйте `/opt/wg-easy/compose.yaml` в терминальном редакторе с повышенными правами. В `services.wg-easy` замените образ, раскомментируйте или задайте блок environment и замените отображения портов на эти значения. Сохраните остальную часть исходного файла, включая постоянный том, монтирование модулей, capabilities, сети и sysctls:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.5.0@sha256:071f79a639e9361123a5e57733107320207b844ddbbd92dfa6962f541fe8aac8
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

Это фрагмент для замены, а не полный файл Compose; сохраните отступы YAML внутри службы. `INSECURE=true` разрешает HTTP только для SSH-туннеля к loopback. Не публикуйте порт администратора в интернете. Слушающий адрес контейнера отличается от отображения на loopback хоста. См. [настройку HTTP](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) в исходном проекте.

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

Храните данные контейнера `/etc/wireguard` в постоянном томе. Не применяйте к v15 старые рецепты с `PASSWORD`, `PASSWORD_HASH` или `WG_HOST`; используйте мастер настройки. Образ закреплён намеренно: для обновления нужно изучить новую версию и изменить привязку, а не просто выполнить `pull`.

## Откройте веб-интерфейс и добавьте клиента

Создайте в Mobile SSH [локальное перенаправление порта](../port-forwarding/): локальный порт `51821`, удалённый хост `127.0.0.1`, удалённый порт `51821`. Не закрывая подключение SSH, откройте `http://127.0.0.1:51821` на том же телефоне. Если локальный порт занят, выберите другой и укажите его в URL браузера.

В [мастере первого запуска](https://wg-easy.github.io/wg-easy/latest/guides/setup/) wg-easy создайте учётную запись администратора, выберите новую установку и задайте VPN-адрес: публичный IPv4 или DNS-имя ВМ с портом `51820`. Адрес VPN — не loopback веб-интерфейса и не порт `51821`.

Создайте отдельного клиента для каждого устройства и скачайте его WireGuard `.conf`. Если сборка Mobile SSH поддерживает это, откройте **VPN → WireGuard**, добавьте профиль, импортируйте файл и сохраните. Текущий исходный код Android и iOS поддерживает импорт файлов; проверьте установленную сборку. VPN Setup импортирует первого клиента напрямую на совместимых сборках Android. На его странице также есть **Добавить клиента**, **Отозвать клиента**, **Экспорт клиента/QR** и **Открыть админ-панель** через закрытый SSH-туннель. Это не подтверждает такие возможности для старого плагина или аналогичную автоматизацию iOS. Файлы конфигурации и QR-коды содержат закрытые ключи; храните их в секрете.

## Проверьте VPN и устраните сбои

Запустите профиль и подтвердите запрос VPN от операционной системы. Проверьте недавнее рукопожатие с пиром и рост счётчиков трафика, затем DNS и нужные маршруты в интернет или частную сеть. Сам по себе импорт профиля или работающий контейнер не доказывает, что VPN работает.

- **Создание ВМ отклонено:** проверьте оплату, квоты, доступность мощностей в регионе, срок учётных данных и точные разрешения IAM. Изменение брандмауэра Google Cloud требует прав сверх Compute Network Admin; обязательный в организации OS Login требует одобренной настройки через консоль.
- **Тайм-аут SSH:** проверьте публичный адрес, маршруты подсети, правила TCP 22 и текущий исходный IP телефона. При ошибках аутентификации обычно нужны правильные имя пользователя образа и ключ SSH.
- **Админ-интерфейс недоступен:** поддерживайте SSH-перенаправление, проверьте контейнер и привязку порта к loopback; HTTP должен быть разрешён только для туннеля.
- **Нет рукопожатия WireGuard:** проверьте адрес клиента, UDP 51820 в обоих брандмауэрах, ключи клиента и прослушивание порта сервером.
- **Рукопожатие есть, трафика нет:** проверьте forwarding/NAT, DNS, пересечение маршрутов и `AllowedIPs`. Полный туннель IPv4 использует `0.0.0.0/0`; IPv6 оценивайте отдельно. ВМ без внешнего IPv6 не обеспечивает выход в интернет по IPv6, а маршруты только IPv4 могут оставить IPv6 вне VPN.

## Обновите плагин и VPN-сервер

В разделе **Плагины** используйте действие **Обновить** для новой совместимой версии из того же каталога. Проверьте новые запрашиваемые возможности. Настройки, учётные данные и записи развёртываний сохраняются; незавершённая операция продолжает работать с версией плагина, которая её начала. Само обновление плагина не обновляет контейнер wg-easy на сервере.

С мостом плагинов 1.4.0 или новее действие **Проверить сервер** показывает работающую версию wg-easy, а **Обновить WireGuard** предлагает закреплённый выпуск плагина. Подтвердите обновление на экране. Образ скачивается до изменения службы, ключи сервера, клиенты и локальные профили сохраняются. Если телефон использует этот VPN, приложение отключит его перед обновлением; затем подключитесь снова. Обновляется управляемый контейнер, а не операционная система сервера.

При неудачном обновлении различаются ошибка загрузки образа, успешный откат и неудачный откат, оставивший VPN отключённым. Выполните предлагаемую проверку восстановления или повторите попытку, не предполагая, что служба восстановилась. Ручная установка требует отдельной проверки новой закреплённой версии образа и резервной копии; приведённая выше чистая установка не является руководством по миграции.

## Удалите клиентов и прекратите облачные расходы

Отзовите клиента в wg-easy, прежде чем удалять его локальный профиль. Удаление профиля в Mobile SSH не отзывает ключ пира на сервере. Перед удалением контейнера VPN или постоянных данных сделайте защищённую резервную копию нужной конфигурации.

Для развёртывания, созданного через API, **Удалить развёртывание** показывает и удаляет принадлежащие ему облачные ресурсы через API провайдера, даже без SSH. При паузе или ошибке проверьте указанные оставшиеся ресурсы; продолжите очистку или откройте консоль. Не помещайте посторонние ресурсы в управляемое плагином развёртывание, особенно в его отдельную группу ресурсов Azure.

Для созданного в консоли или существующего сервера удаление в плагине убирает управляемую установку VPN, но **не** удаляет вашу ВМ или публичный IP. Когда они больше не нужны, удалите их в консоли провайдера и проверьте оставшиеся диски, снимки, адреса и сетевые ресурсы. Если при восстановлении менялись аккаунт или регион, проверьте и прежние, включая прежний проект Scaleway или compartment Oracle Cloud.

**Остановить процесс** прекращает операцию, но не удаляет ресурсы. С мостом 1.5.0 или новее **Убрать из списка** доступно только когда приложение может подтвердить, что запись разрешено забыть: нет незавершённых операций или оставшихся управляемых ресурсов. Это очищает локальную историю, а не облачные ресурсы. Остановка ВМ или удаление плагина также не гарантируют прекращения расходов. Храните ID ресурсов до подтверждения удаления.
