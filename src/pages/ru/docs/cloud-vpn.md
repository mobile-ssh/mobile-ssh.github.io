# Облачные ВМ и wg-easy

Создайте виртуальную машину Linux в своей облачной учётной записи, подключитесь к ней через Mobile SSH, а затем установите wg-easy для работы VPN WireGuard. Разделение создания ВМ и установки позволяет использовать ту же машину для другой службы или установить VPN на уже имеющийся сервер.

**Доступность — 8 ноября 2026 года:** отдельные плагины создания ВМ — это предполагаемый процесс, описанный ниже. Проверенная локальная реализация **VPN Setup** для Android объединяет создание ресурсов, установку и импорт клиента; изменения плагина и каталога ещё не опубликованы, а развёртывание в реальных облаках не проверено. Отдельные записи AWS, Google Cloud и Azure пока содержат только заготовки манифестов и настроек; показ списка ВМ и действия управления не реализованы, и эти плагины не создают ВМ. Если в вашем каталоге нет процесса создания, используйте инструкции для консоли и ручной установки ниже. Новый нативный процесс требует совместимой сборки Android; аналогичная автоматизация iOS не подтверждена.

## Два плагина с разными задачами

- **Плагин создания облачной ВМ:** через API провайдера создаёт машину, публичный адрес и необходимые сетевые ресурсы, затем сохраняет подключение SSH. Он хранит идентификаторы облачных ресурсов для дальнейшего управления или удаления.
- **Установщик wg-easy:** подключается по SSH к выбранному сохранённому серверу, устанавливает VPN и помогает создать конфигурацию клиента. Ему нужны доступ к серверу и права администратора, а не учётные данные облачного API. Подходит и ВМ, созданная вручную.

При передаче между плагинами нужны ссылка на сохранённый сервер, публичный адрес, порт SSH, имя пользователя, ссылка на учётные данные SSH и идентификаторы развёртывания и ресурсов. Облачные секреты и закрытые ключи SSH не должны попадать в вывод плагина или на ВМ. Удаление VPN и удаление облачной машины — разные операции.

## Подготовьте учётную запись и параметры сервера

1. Активируйте облачную учётную запись и оплату, выберите регион, проверьте квоты на ВМ, диски и публичные IP. Изучите актуальные тарифы на машины, IPv4, хранение и трафик; доступность бесплатного тарифа не предполагается.
2. Для этой инструкции выберите отдельную ВМ **Ubuntu 24.04 LTS** с минимум **1 ГБ ОЗУ и диском 20 ГБ**, архитектурой **amd64 или arm64**. Это базовые параметры данного процесса, а не универсальный минимум для wg-easy. Пользователь должен иметь доступ root или sudo; автоматической установке требуется повышение привилегий без интерактивного ввода.
3. Выберите или создайте ключ SSH, оставив закрытый ключ в Mobile SSH. В облако загружайте только открытый ключ. Для импорта SSH-ключа в Lightsail нужен RSA. У других провайдеров и образов свои допустимые типы ключей. Текущий клиент SSH для iOS поддерживает закрытые ключи Ed25519/ECDSA, но не RSA. Для Lightsail на iOS сначала через браузерную консоль SSH провайдера добавьте поддерживаемый приложением открытый ключ в `authorized_keys`, затем подключитесь с этим ключом.
4. Выберите **публичный IPv4**, желательно зарезервированный или статический, если провайдер это поддерживает. Частный адрес, машина только с IPv6 или шлюз NAT только для исходящих соединений не соответствуют требованиям этой инструкции.
5. Явно задайте исходный CIDR для SSH, например текущий публичный IPv4 с окончанием `/32`. Не считайте, что значение плагина по умолчанию ограничивает доступ. При переходе между мобильной сетью и Wi-Fi может потребоваться изменить правило в облачной консоли.

Учётные данные облачного API разрешают управление ресурсами, а ключи SSH — вход на сервер. Это разные данные. Вводите секреты API только в защищённой форме учётных данных провайдера, никогда не в голосовых запросах, командах терминала или исходных файлах. В локальном процессе Android нативный код выполняет аутентификацию у провайдера и хранит учётные данные в зашифрованном виде; при необходимости они передаются своему провайдеру, но не на ВМ и не обработчику плагина. Автономная голосовая модель не позволяет выполнять облачные API-запросы, загрузки или SSH без интернета.

## Выберите облако и получите публичный адрес

При **настройке через консоль** войдите к провайдеру самостоятельно; Mobile SSH не нужны его учётные данные API. Для будущего **создания через плагин** подготовьте указанные ниже данные с правами на необходимые операции создания, чтения, настройки сети и удаления. Где возможно, ограничьте доступ отдельным проектом или развёртыванием. Политики учётной записи действуют для обоих способов.

## Создайте ВМ и сохраните подключение SSH

В предполагаемом раздельном процессе откройте **Плагины**, установите плагин создания ресурсов выбранного провайдера из доверенного каталога, выберите учётную запись, регион, размер ВМ, образ, публичный адрес и ключ SSH. Перед подтверждением проверьте ресурсы и стоимость. Плагин только для управления, без действия создания, не выполнит этот шаг; используйте консоль провайдера.

Дождитесь, когда провайдер сообщит о работающей ВМ и SSH станет доступен. Сохраните идентификаторы машины, дисков, адресов и межсетевых экранов. Если запрос завершился по тайм-ауту, проверьте или возобновите существующую операцию перед повторным созданием, чтобы не получить вторую платную ВМ.

Сохраните полученное подключение в Mobile SSH или добавьте его вручную в разделе **Серверы**: публичный IPv4, порт SSH `22`, имя пользователя образа и соответствующие учётные данные с закрытым ключом. До подключения сравните отпечаток ключа хоста SSH через доверенную консоль провайдера. Проверки подлинности и сохранённые учётные данные описаны в разделе [Начало работы](../getting-started/).

## Настройте оба уровня сети

Публичному адресу нужны маршрут, разрешение облачного межсетевого экрана, разрешение межсетевого экрана гостевой ОС и слушающая служба. Примените следующие правила в межсетевом экране или группе безопасности провайдера; сохраните необходимые существующие правила гостевой ОС.

- **TCP 22:** разрешите SSH из выбранного управляющего CIDR. Настройте при создании ВМ.
- **UDP 51820:** разрешите сети, из которых будут подключаться клиенты VPN. Для перемещающихся клиентов это может быть `0.0.0.0/0`. Добавьте правило при настройке WireGuard через облачный плагин или консоль.
- **TCP 51821:** оставьте закрытым для публичного доступа. Публикуйте веб-интерфейс администратора wg-easy только на loopback сервера и подключайтесь через туннель SSH.
- **Исходящий трафик:** разрешите загрузку пакетов и контейнеров, DNS и интернет-трафик, который должен передавать VPN.

Изучите [работу Docker с межсетевыми экранами](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations): опубликованные порты контейнеров могут обходить правила UFW. Не полагайтесь только на UFW для защиты веб-интерфейса и не очищайте цепочки межсетевого экрана провайдера, особенно правила хранилища/iSCSI в OCI.

## Установите wg-easy на выбранную ВМ

Отдельный установщик должен принимать сохранённый сервер SSH и запрашивать подтверждение изменений на нём. Он должен проверить ОС, права, имеющиеся установки Docker/VPN и конфликты портов, сохранить постоянные данные и сообщить установленную версию. Секрет облачной учётной записи ему не нужен; меняйте облачные правила через плагин создания ресурсов или консоль.

Старый плагин каталога **WireGuard (wg-easy)** требует активного сеанса SSH и установленного Docker. Это не новый автоматический установщик, и автоматический импорт в нативный VPN-клиент он не обещает. Используйте совместимый обновлённый установщик или следующий ручной способ в терминале Mobile SSH на новой отдельной ВМ.

### Ручная установка через SSH

Установите Docker Engine и его плагин Compose по официальной [инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/). Затем загрузите конфигурацию нужной версии из исходного проекта:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.4.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

Перед запуском отредактируйте `/opt/wg-easy/compose.yaml` в терминальном редакторе с повышенными правами. В `services.wg-easy` замените образ, раскомментируйте или задайте блок environment и замените отображения портов на эти значения. Сохраните остальную часть исходного файла, включая постоянный том, монтирование модулей, capabilities, сети и sysctls:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.4.0@sha256:0e7bc9d34e86ddcaa92bc700d4d7dc9b33291dbc07ac8d13382f7c2095f949ec
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

Это фрагмент для замены, а не полный файл Compose; сохраните отступы YAML внутри службы. `INSECURE=true` разрешает HTTP только для SSH-туннеля к loopback. Не публикуйте порт администратора в интернете. Слушающий адрес контейнера отличается от отображения на loopback хоста. См. [настройку HTTP](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) в исходном проекте.

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

Храните данные контейнера `/etc/wireguard` в постоянном томе. Не применяйте к v15 старые рецепты с `PASSWORD`, `PASSWORD_HASH` или `WG_HOST`; используйте мастер настройки. Образ закреплён намеренно: для обновления нужно изучить новую версию и изменить привязку, а не просто выполнить `pull`.

## Откройте веб-интерфейс и добавьте клиента

Создайте в Mobile SSH [локальное перенаправление порта](../port-forwarding/): локальный порт `51821`, удалённый хост `127.0.0.1`, удалённый порт `51821`. Не закрывая подключение SSH, откройте `http://127.0.0.1:51821` на том же телефоне. Если локальный порт занят, выберите другой и укажите его в URL браузера.

В [мастере первого запуска](https://wg-easy.github.io/wg-easy/latest/guides/setup/) wg-easy создайте учётную запись администратора, выберите новую установку и задайте VPN-адрес: публичный IPv4 или DNS-имя ВМ с портом `51820`. Адрес VPN — не loopback веб-интерфейса и не порт `51821`.

Создайте отдельного клиента для каждого устройства и загрузите его файл WireGuard `.conf`. Если ваша сборка Mobile SSH поддерживает это, откройте **VPN → WireGuard**, добавьте профиль, импортируйте файл и сохраните. В актуальном исходном коде Android и iOS есть импорт файлов; проверьте установленную сборку. Локальный объединённый процесс Android может импортировать напрямую, но это не обещание для старого плагина или автоматизации iOS. Файлы конфигурации и QR-коды содержат закрытые ключи; храните их в тайне.

## Проверьте VPN и устраните сбои

Запустите профиль и подтвердите запрос VPN от операционной системы. Проверьте недавнее рукопожатие с пиром и рост счётчиков трафика, затем DNS и нужные маршруты в интернет или частную сеть. Сам по себе импорт профиля или работающий контейнер не доказывает, что VPN работает.

- **Создание ВМ отклонено:** проверьте оплату, квоты, наличие ресурсов в регионе, срок действия учётных данных и точные права IAM. Для изменения межсетевого экрана Google Cloud нужны права сверх Network Admin.
- **Тайм-аут SSH:** проверьте публичный адрес, маршрутизацию подсети, правила TCP 22 и текущий исходный IP телефона. При ошибке аутентификации обычно нужно исправить имя пользователя образа или ключ SSH.
- **Веб-интерфейс недоступен:** сохраняйте подключение для перенаправления SSH, проверьте состояние контейнера, отображение порта loopback и включение HTTP только для туннеля.
- **Нет рукопожатия WireGuard:** проверьте адрес клиента, UDP 51820 на обоих уровнях межсетевых экранов, ключи клиента и слушающую службу сервера.
- **Рукопожатие есть, трафика нет:** проверьте перенаправление/NAT, DNS, пересечения маршрутов и `AllowedIPs`. Полный туннель IPv4 использует `0.0.0.0/0`; отдельно оцените IPv6. ВМ без внешнего IPv6 не обеспечит выход IPv6 в интернет, а маршруты только IPv4 могут оставить IPv6 вне VPN.

## Удалите клиентов и прекратите облачные расходы

Отзовите клиента в wg-easy, прежде чем удалять его локальный профиль. Удаление профиля в Mobile SSH не отзывает ключ пира на сервере. Перед удалением контейнера VPN или постоянных данных сделайте защищённую резервную копию нужной конфигурации.

Удалите ненужную ВМ через управляющий ею плагин или консоль провайдера, затем проверьте оставшиеся диски, снимки, зарезервированные/публичные адреса и сетевые ресурсы. Перед удалением отдельной группы ресурсов Azure изучите её содержимое. Не добавляйте посторонние ресурсы в развёртывание под управлением плагина.

Остановка ВМ, отмена задания настройки или удаление плагина не гарантируют удаления ресурсов и прекращения расходов. Ресурсы, созданные через консоль, остаются вашей ответственностью; храните их идентификаторы до подтверждения удаления.
