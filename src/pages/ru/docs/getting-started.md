# Начало работы

Mobile SSH — это SSH-клиент для Android и iOS для подключения к вашим собственным серверам Linux, Unix, сетевым, IoT или серверам разработки. Вы указываете адрес сервера и учётные данные, а приложение открывает интерактивный SSH-терминал.

## Требования

- Android 8.0 или новее либо iOS 16 или новее (iPhone или iPad).
- Сетевой доступ с устройства к вашему SSH-серверу.
- Имя хоста или IP-адрес SSH-сервера, порт, имя пользователя и пароль либо закрытый ключ.
- На Android — доступ к хранилищу, если вы хотите использовать передачу файлов по SFTP с локальным файловым браузером телефона; iOS вместо этого использует системные средства выбора файлов и фото.

## Установка приложения

- **Android:** установите Mobile SSH из Google Play.
- **iOS:** приложение для iOS распространяется как публичная бета в TestFlight. Установите приложение TestFlight от Apple, затем откройте ссылку-приглашение Mobile SSH с главной страницы сайта, чтобы установить приложение и получать обновления.

## Подключение к серверу

1. Откройте Mobile SSH.
2. Нажмите **+ Add Session** и найдите сохранённый сервер или добавьте новый прямо с этого экрана.
3. Введите хост, порт, имя пользователя и данные аутентификации, если добавляете новый сервер.
4. Нажмите на сервер, чтобы открыть сессию терминала.
5. Используйте **Active Sessions** на стартовом экране, чтобы вернуться к ещё работающим сессиям.

Стандартный порт SSH — `22`. Если ваш сервер использует другой порт, укажите его в профиле сервера.

## Сохранение серверов

Сохранённые серверы хранят цель подключения и необязательную конфигурацию туннелей. Сохранённый сервер может включать:

- Имя хоста или IP-адрес.
- Порт SSH.
- Имя пользователя.
- Данные пароля или закрытого ключа.
- Необязательные правила локального проброса портов.
- Необязательные дополнительные адреса для той же машины (см. ниже).

Используйте сохранённые серверы для хостов, к которым обращаетесь регулярно. Если сохранённый сервер указывает на другой хост, отличный от текущей активной сессии, Mobile SSH запускает новое подключение для выбранной цели.

### Несколько адресов (роуминг между LAN и VPN)

Одна и та же машина часто доступна по разным адресам в зависимости от того, где вы находитесь, — например, по IP в домашней сети Wi-Fi и по IP через VPN. Добавьте альтернативные адреса в диалоге редактирования сервера, каждый со своим портом при необходимости. При подключении Mobile SSH перебирает адреса по порядку, пока один из них не ответит, запоминает последний рабочий адрес и в следующий раз пробует его первым. Смена сети (например, выход из VPN) вызывает немедленное переподключение к тому адресу, который сейчас доступен, вместо ожидания тайм-аута по неработающему маршруту.

## Сохранение учётных данных

Экран **Credentials** хранит многоразовые записи «имя пользователя/пароль» или «имя пользователя/закрытый ключ». Сохранённые учётные данные можно выбрать в диалоге настройки сервера, чтобы не вводить одни и те же данные для входа для каждого хоста.

Записи учётных данных хранятся локально на устройстве — на iOS секреты хранятся в системном Keychain. Защитите устройство блокировкой экрана, если сохраняете пароли, парольные фразы или закрытые ключи.

## Использование закрытых ключей

Mobile SSH поддерживает вставку закрытых ключей и их импорт через файловый выбор системы. На Android приложение поддерживает ключи Ed25519, RSA, ECDSA и DSA; на iOS — ключи Ed25519 и ECDSA (P-256/384/521).

Чтобы использовать закрытый ключ:

1. Откройте **Credentials** или диалог редактирования сервера.
2. Вставьте текст закрытого ключа или выберите **Import from file**.
3. Введите парольную фразу ключа в поле пароля/парольной фразы, если ключ зашифрован.
4. Сохраните учётные данные или сервер.

Импорт закрытого ключа использует файловый выбор системы для файлов ключей. На Android передача файлов использует отдельный локальный файловый браузер и на новых версиях Android может запрашивать более широкий доступ к хранилищу; на iOS файлы поступают через системные средства выбора документов и фото.

## Недавние сессии

На стартовом экране отображаются недавние сессии. Недавняя сессия может переподключиться к тому же набору серверов. Если предыдущая сессия всё ещё активна, Mobile SSH возвращается к ней вместо запуска дублирующего подключения.

## Поиск сохранённых серверов

Нажмите на поле поиска на странице **Saved Servers**, чтобы фильтровать по имени или хосту. Экран **+ Add Session** также открывается с поиском, что позволяет найти сохранённый сервер и подключиться к нему в один шаг.

## Активные сессии

Когда сессии запущены, на стартовом экране отображается **Active Sessions** со счётчиком. Нажмите, чтобы вернуться к сетке терминалов. Постоянное уведомление также перечисляет активные хосты — нажмите на хост в уведомлении, чтобы перейти прямо к соответствующему терминалу.

Возврат на стартовый экран не отключает активные SSH-сессии; закрытие панелей или завершение активности терминала отключает их.

## Первые полезные настройки

Откройте **Settings** на стартовом экране (у него есть отдельная страница):

- Включите показ клавиатуры по нажатию, если предпочитаете, чтобы клавиатура появлялась при касании терминала.
- Включите **Agent alerts**, если вы запускаете длительные фоновые задачи (Claude Code, Codex, shell-скрипты) и хотите получать звуковое или вибро-уведомление, когда агент ожидает вашего ввода.
- Отключите анонимную аналитику использования, если не хотите отправлять никакие данные.

## Языки

Mobile SSH следует системному языку. Приложение поставляется с переводами на арабский, бенгальский, китайский (упрощённый и традиционный), английский, французский, немецкий, хинди, индонезийский, японский, маратхи, нигерийский пиджин, португальский, русский, испанский, тамильский, телугу, турецкий и урду. Меняйте язык в **Настройки → Система → Языки** Android или на iOS в **Настройки → Основные → Язык и регион**, а не внутри приложения.

## Примечание о безопасности

Подключайтесь только к серверам, которым доверяете. Текущее приложение хранит сохранённые данные подключения локально и не предоставляет облачное хранилище или синхронизацию между устройствами. Текущая реализация также не показывает запрос подтверждения известного хоста, поэтому избегайте подключения через недоверенные сети, когда важна идентификация хоста.
