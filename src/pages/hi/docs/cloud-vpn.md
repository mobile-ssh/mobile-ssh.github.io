# क्लाउड VM और wg-easy

अपने क्लाउड खाते में Linux VM बनाएँ, Mobile SSH से उससे जुड़ें, फिर WireGuard VPN चलाने के लिए wg-easy स्थापित करें। संसाधन बनाना और सॉफ़्टवेयर स्थापित करना अलग रखने से उसी VM पर दूसरी सेवा चला सकते हैं या पहले से मौजूद सर्वर पर VPN लगा सकते हैं।

**उपलब्धता — 8 नवंबर 2026:** नीचे वर्णित लक्षित कार्यप्रवाह में VM बनाने के अलग प्लगइन हैं। समीक्षा किया गया स्थानीय Android **VPN Setup** कार्यान्वयन संसाधन बनाना, स्थापना और क्लाइंट आयात एक साथ करता है; उसके प्लगइन/कैटलॉग बदलाव अप्रकाशित हैं और वास्तविक क्लाउड पर तैनाती अभी परीक्षणित नहीं है। अलग AWS, Google Cloud और Azure प्रविष्टियाँ अभी केवल मैनिफ़ेस्ट/सेटिंग के अधूरे ढाँचे हैं; उनकी VM सूची दिखाने और नियंत्रण की कार्रवाइयाँ लागू नहीं हैं, और वे VM बनाती भी नहीं हैं। आपके कैटलॉग में निर्माण कार्यप्रवाह न हो तो नीचे दिए कंसोल और मैन्युअल स्थापना निर्देश अपनाएँ। नए नेटिव कार्यप्रवाह के लिए संगत Android बिल्ड चाहिए; समकक्ष iOS स्वचालन स्थापित नहीं है।

## अलग ज़िम्मेदारियों वाले दो प्लगइन

- **क्लाउड प्रोविज़नर:** प्रदाता के API से VM, सार्वजनिक पता और आवश्यक नेटवर्क संसाधन बनाता है, फिर SSH कनेक्शन सहेजता है। आगे प्रबंधन या हटाने के लिए क्लाउड संसाधनों की ID रखता है।
- **wg-easy इंस्टॉलर:** चुने हुए सहेजे सर्वर से SSH द्वारा जुड़कर VPN सेवा स्थापित करता है और क्लाइंट कॉन्फ़िगरेशन बनाने में मदद करता है। इसे सर्वर तक पहुँच और प्रशासनिक अधिकार चाहिए, आपके क्लाउड API क्रेडेंशियल नहीं। हाथ से बनाया VM भी यहाँ इस्तेमाल हो सकता है।

एक प्लगइन से दूसरे को सहेजे सर्वर का संदर्भ, सार्वजनिक पता, SSH पोर्ट, उपयोगकर्ता नाम, SSH क्रेडेंशियल संदर्भ और तैनाती/संसाधन ID मिलने चाहिए। क्लाउड रहस्य और SSH निजी कुंजियाँ प्लगइन आउटपुट या VM पर कॉपी नहीं होनी चाहिए। VPN हटाना और क्लाउड VM हटाना अलग काम हैं।

## खाता और सर्वर सेटिंग तैयार करें

1. क्लाउड खाता और बिलिंग सक्रिय करें, क्षेत्र चुनें और VM, डिस्क व सार्वजनिक IP के कोटे जाँचें। प्रदाता के वर्तमान VM, IPv4, संग्रह और ट्रैफ़िक शुल्क देखें; मुफ़्त स्तर उपलब्ध मानकर न चलें।
2. इस मार्गदर्शिका के लिए कम-से-कम **1 GB RAM और 20 GB डिस्क** वाला समर्पित **Ubuntu 24.04 LTS** VM, **amd64 या arm64** पर चुनें। ये इस सेटअप के आधारभूत विकल्प हैं, wg-easy की सार्वभौमिक न्यूनतम आवश्यकताएँ नहीं। root या sudo पहुँच वाला लॉगिन लें; बिना हस्तक्षेप की स्थापना के लिए गैर-संवादी अधिकार-वृद्धि चाहिए।
3. SSH कुंजी चुनें या बनाएँ और निजी कुंजी Mobile SSH में रखें। क्लाउड में केवल सार्वजनिक कुंजी अपलोड करें। Lightsail के आयात मार्ग के लिए RSA SSH कुंजी चाहिए। अन्य प्रदाताओं और इमेज के स्वीकार्य कुंजी प्रकार अलग हो सकते हैं। वर्तमान iOS SSH क्लाइंट RSA निजी कुंजियों के बजाय Ed25519/ECDSA समर्थित करता है। iOS पर Lightsail के लिए पहले प्रदाता के ब्राउज़र SSH कंसोल से ऐप द्वारा समर्थित सार्वजनिक कुंजी `authorized_keys` में जोड़ें, फिर उसी कुंजी से जुड़ें।
4. **सार्वजनिक IPv4** चुनें; उपलब्ध हो तो आरक्षित/स्थिर पता बेहतर है। निजी पता, केवल IPv6 वाला इंस्टेंस या सिर्फ़ आउटबाउंड NAT गेटवे इस मार्गदर्शिका की एंडपॉइंट आवश्यकता पूरी नहीं करता।
5. SSH स्रोत CIDR स्पष्ट सेट करें, जैसे आपके वर्तमान सार्वजनिक IPv4 के बाद `/32`। प्लगइन का डिफ़ॉल्ट पहुँच सीमित करता है, ऐसा न मानें। मोबाइल डेटा और Wi-Fi बदलने पर क्लाउड कंसोल से नियम बदलना पड़ सकता है।

क्लाउड API क्रेडेंशियल संसाधन प्रबंधन की अनुमति देते हैं; SSH कुंजियाँ सर्वर लॉगिन की। दोनों अलग क्रेडेंशियल हैं। API रहस्य केवल प्रदाता के सुरक्षित क्रेडेंशियल फ़ॉर्म में भरें, वॉइस प्रॉम्प्ट, टर्मिनल कमांड या सोर्स फ़ाइलों में कभी नहीं। स्थानीय Android कार्यप्रवाह में नेटिव कोड प्रदाता प्रमाणीकरण और एन्क्रिप्टेड क्रेडेंशियल संग्रह संभालता है; ज़रूरत के अनुसार क्रेडेंशियल उनके प्रदाता को भेजे जाते हैं, VM या प्लगइन वर्कर को नहीं। ऑफ़लाइन वॉइस मॉडल से क्लाउड API कॉल, डाउनलोड या SSH काम बिना इंटरनेट नहीं होने लगते।

## क्लाउड चुनें और सार्वजनिक पता लें

**कंसोल सेटअप** के लिए प्रदाता में स्वयं साइन इन करें; Mobile SSH को उसके API क्रेडेंशियल नहीं चाहिए। भविष्य के **प्लगइन प्रोविज़निंग** के लिए नीचे बताए क्रेडेंशियल को आवश्यक निर्माण, पढ़ने, नेटवर्क और हटाने के अधिकारों सहित तैयार करें। जहाँ संभव हो पहुँच समर्पित प्रोजेक्ट या तैनाती तक सीमित रखें। खाते की नीतियाँ दोनों तरीकों पर लागू होती हैं।

चुना हुआ Ubuntu VM अपनी SSH सार्वजनिक कुंजी से बनाएँ और अगले भाग का SSH नियम लगाएँ। लिंक प्रदाता के अनुसार पता और प्रमाणीकरण के चरण बताते हैं।

**[AWS EC2](./aws-ec2/) विकल्प:** [इंटरनेट गेटवे और `0.0.0.0/0` गेटवे रूट](https://docs.aws.amazon.com/vpc/latest/userguide/VPC_Internet_Gateway.html) वाले सार्वजनिक सबनेट में Ubuntu शुरू करें, SSH कुंजी और सुरक्षा समूह चुनें, फिर [Elastic IP](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/working-with-eips.html) जोड़ें। `ubuntu` लें। स्थानीय स्वचालित एडैप्टर Lightsail के लिए है; EC2 कंसोल मार्ग है। केवल Elastic IP से निजी सबनेट पहुँच योग्य नहीं बनता।

संगठन सेवा-खाते की कुंजियाँ, बाहरी IP या चुना SSH प्रमाणीकरण तरीका रोकता हो तो व्यवस्थापक से अनुमोदित कॉन्फ़िगरेशन लें। कंसोल सेटअप उन पाबंदियों को पार नहीं करता।

## संसाधन बनाएँ और SSH कनेक्शन सहेजें

लक्षित अलग कार्यप्रवाह में **प्लगइन** खोलें, विश्वसनीय कैटलॉग से प्रदाता का प्रोविज़निंग प्लगइन स्थापित करें, उसका खाता और क्षेत्र चुनें, फिर VM आकार, इमेज, सार्वजनिक पता और SSH कुंजी चुनें। निर्माण की पुष्टि से पहले संसाधन और लागत देखें। सिर्फ़ प्रबंधन वाला प्लगइन, जिसमें निर्माण कार्रवाई नहीं है, यह चरण नहीं कर सकता; उसके बदले प्रदाता का कंसोल लें।

प्रदाता के VM चालू बताने और SSH पहुँच योग्य होने की प्रतीक्षा करें। VM, डिस्क, पता और फ़ायरवॉल संसाधन ID रखें। अनुरोध का समय समाप्त हो तो दोबारा निर्माण से पहले मौजूदा कार्रवाई जाँचें या जारी करें, ताकि दूसरा शुल्क लगने वाला VM न बने।

मिला कनेक्शन Mobile SSH में सहेजें या **सर्वर** में हाथ से जोड़ें: सार्वजनिक IPv4, SSH पोर्ट `22`, इमेज का उपयोगकर्ता नाम और मेल खाता निजी-कुंजी क्रेडेंशियल। जुड़ने से पहले प्रदाता के विश्वसनीय कंसोल से SSH होस्ट-कुंजी फ़िंगरप्रिंट मिलाएँ। पहचान जाँच और सहेजे क्रेडेंशियल के लिए [शुरुआत करें](../getting-started/) देखें।

## नेटवर्क की दोनों परतें सेट करें

सार्वजनिक पते के लिए रूट, क्लाउड फ़ायरवॉल अनुमति, गेस्ट फ़ायरवॉल अनुमति और सुनती हुई सेवा चाहिए। प्रदाता के फ़ायरवॉल/सुरक्षा समूह में ये नियम लगाएँ; आवश्यक मौजूदा गेस्ट नियम बनाए रखें।

- **TCP 22:** SSH के लिए चुने प्रबंधन CIDR से अनुमति दें। संसाधन बनाते समय इसे सेट करें।
- **UDP 51820:** VPN इस्तेमाल करने वाले नेटवर्क से अनुमति दें। घूमते क्लाइंट के लिए यह `0.0.0.0/0` हो सकता है। WireGuard सेट करते समय क्लाउड प्रोविज़नर या कंसोल से जोड़ें।
- **TCP 51821:** सार्वजनिक रूप से बंद रखें। wg-easy व्यवस्थापक UI केवल सर्वर लूपबैक पर प्रकाशित करें और SSH सुरंग से पहुँचें।
- **आउटबाउंड ट्रैफ़िक:** पैकेज/कंटेनर डाउनलोड, DNS और VPN द्वारा ले जाए जाने वाले इंटरनेट ट्रैफ़िक को अनुमति दें।

Docker का [फ़ायरवॉल व्यवहार](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations) देखें: प्रकाशित कंटेनर पोर्ट UFW नियमों को पार कर सकते हैं। व्यवस्थापक UI छिपाने के लिए केवल UFW पर भरोसा न करें और प्रदाता की फ़ायरवॉल चेन साफ़ न करें, विशेषकर OCI के संग्रह/iSCSI नियम।

## चुने VM पर wg-easy स्थापित करें

अलग इंस्टॉलर को सहेजा SSH सर्वर लेना चाहिए और सर्वर बदलावों की स्वीकृति माँगनी चाहिए। उसे OS, अधिकार, मौजूदा Docker/VPN स्थापना और पोर्ट टकराव जाँचने, स्थायी डेटा बचाने और स्थापित संस्करण बताने चाहिए। क्लाउड खाते का रहस्य उसे नहीं चाहिए; क्लाउड फ़ायरवॉल बदलाव के लिए प्रोविज़नर या कंसोल लें।

पुराने **WireGuard (wg-easy)** कैटलॉग प्लगइन को सक्रिय SSH सत्र और Docker चाहिए। वह नया स्वचालित इंस्टॉलर नहीं है और नेटिव क्लाइंट आयात का वादा नहीं करता। संगत अपडेटेड इंस्टॉलर लें, या नए समर्पित VM पर Mobile SSH टर्मिनल से यह मैन्युअल तरीका अपनाएँ।

### SSH से मैन्युअल स्थापना

आधिकारिक [Ubuntu निर्देशों](https://docs.docker.com/engine/install/ubuntu/) से Docker Engine और उसका Compose प्लगइन स्थापित करें। फिर संस्करण-विशिष्ट अपस्ट्रीम कॉन्फ़िगरेशन डाउनलोड करें:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.4.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

शुरू करने से पहले प्रशासनिक अधिकार वाले टर्मिनल एडिटर में `/opt/wg-easy/compose.yaml` संपादित करें। `services.wg-easy` में इमेज बदलें, environment ब्लॉक अनकमेंट/सेट करें और पोर्ट मैपिंग को इन मानों से बदलें। अपस्ट्रीम फ़ाइल का बाकी हिस्सा रखें, जिसमें स्थायी वॉल्यूम, मॉड्यूल माउंट, क्षमताएँ, नेटवर्क और sysctls शामिल हैं:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.4.0@sha256:0e7bc9d34e86ddcaa92bc700d4d7dc9b33291dbc07ac8d13382f7c2095f949ec
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

यह बदलने वाला अंश है, पूरी Compose फ़ाइल नहीं; सेवा के भीतर YAML इंडेंटेशन बनाए रखें। `INSECURE=true` केवल लूपबैक SSH सुरंग के लिए HTTP की अनुमति देता है। व्यवस्थापक पोर्ट इंटरनेट पर प्रकाशित न करें। कंटेनर का लिसनर होस्ट की लूपबैक मैपिंग से अलग है। अपस्ट्रीम का [HTTP कॉन्फ़िगरेशन](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) देखें।

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

कंटेनर का `/etc/wireguard` डेटा उसके स्थायी वॉल्यूम में रखें। पुराने `PASSWORD`, `PASSWORD_HASH` या `WG_HOST` नुस्खे v15 पर न लगाएँ; उसका सेटअप विज़ार्ड लें। इमेज जानबूझकर पिन की गई है: अपग्रेड के लिए नए संस्करण की समीक्षा और पिन बदलना चाहिए, केवल `pull` चलाना पर्याप्त नहीं।

## व्यवस्थापक UI खोलें और क्लाइंट जोड़ें

Mobile SSH में स्थानीय पोर्ट `51821`, दूरस्थ होस्ट `127.0.0.1` और दूरस्थ पोर्ट `51821` वाला [स्थानीय पोर्ट फ़ॉरवर्ड](../port-forwarding/) बनाएँ। SSH कनेक्शन सक्रिय रखें और उसी फ़ोन पर `http://127.0.0.1:51821` खोलें। स्थानीय पोर्ट व्यस्त हो तो दूसरा चुनें और ब्राउज़र URL में वही लें।

wg-easy के [पहले उपयोग के विज़ार्ड](https://wg-easy.github.io/wg-easy/latest/guides/setup/) में व्यवस्थापक खाता बनाएँ, नई स्थापना चुनें और VPN एंडपॉइंट में VM का सार्वजनिक IPv4 या DNS नाम तथा पोर्ट `51820` दें। VPN एंडपॉइंट वेब UI का लूपबैक पता या पोर्ट `51821` नहीं है।

हर डिवाइस के लिए एक क्लाइंट बनाएँ और उसकी WireGuard `.conf` डाउनलोड करें। जहाँ आपका Mobile SSH बिल्ड यह सुविधा देता हो, **VPN → WireGuard** खोलें, प्रोफ़ाइल जोड़ें, फ़ाइल आयात करके सहेजें। वर्तमान Android और iOS सोर्स फ़ाइल आयात समर्थित करते हैं; अपना स्थापित बिल्ड जाँचें। स्थानीय Android संयुक्त कार्यप्रवाह सीधे आयात कर सकता है, लेकिन यह पुराने प्लगइन या iOS स्वचालन का वादा नहीं। कॉन्फ़िगरेशन फ़ाइलों और QR कोड में निजी कुंजियाँ होती हैं; इन्हें निजी रखें।

## VPN जाँचें और विफलताएँ सँभालें

प्रोफ़ाइल शुरू करें और ऑपरेटिंग सिस्टम का VPN अनुरोध स्वीकारें। हाल का पीयर हैंडशेक और बढ़ते ट्रैफ़िक काउंटर देखें, फिर DNS और इच्छित इंटरनेट या निजी-नेटवर्क रूट जाँचें। आयातित प्रोफ़ाइल या चलता कंटेनर अकेले काम करते VPN का प्रमाण नहीं।

- **VM निर्माण अस्वीकार:** बिलिंग, कोटा, क्षेत्रीय क्षमता, क्रेडेंशियल की अवधि और सटीक IAM अनुमतियाँ जाँचें। Google Cloud में फ़ायरवॉल लिखने के लिए Network Admin से अतिरिक्त अनुमतियाँ चाहिए।
- **SSH टाइमआउट:** सार्वजनिक पता, सबनेट रूटिंग, TCP 22 नियम और फ़ोन का वर्तमान स्रोत IP जाँचें। प्रमाणीकरण विफलता में आम तौर पर सही इमेज उपयोगकर्ता नाम और SSH कुंजी चाहिए।
- **व्यवस्थापक UI अनुपलब्ध:** SSH फ़ॉरवर्डिंग जुड़ी रखें, कंटेनर स्थिति और लूपबैक पोर्ट मैपिंग जाँचें तथा पुष्टि करें कि HTTP केवल सुरंग के लिए चालू है।
- **WireGuard हैंडशेक नहीं:** क्लाइंट एंडपॉइंट, दोनों फ़ायरवॉल परतों में UDP 51820, क्लाइंट कुंजियाँ और सर्वर का सुनना जाँचें।
- **हैंडशेक है, ट्रैफ़िक नहीं:** फ़ॉरवर्डिंग/NAT, DNS, रूट ओवरलैप और `AllowedIPs` देखें। पूर्ण-सुरंग IPv4 में `0.0.0.0/0` लगता है; IPv6 अलग परखें। अपस्ट्रीम IPv6 रहित VM IPv6 इंटरनेट निकास नहीं दे सकता, और केवल IPv4 रूट IPv6 को VPN के बाहर छोड़ सकते हैं।

## क्लाइंट हटाएँ और क्लाउड शुल्क रोकें

स्थानीय प्रोफ़ाइल हटाने से पहले wg-easy में क्लाइंट रद्द करें। Mobile SSH में प्रोफ़ाइल हटाने से सर्वर की पीयर कुंजी रद्द नहीं होती। VPN कंटेनर या स्थायी डेटा हटाने से पहले आवश्यक कॉन्फ़िगरेशन का सुरक्षित बैकअप लें।

अनावश्यक VM को उसके संसाधन बनाने वाले प्रोविज़नर या प्रदाता कंसोल से हटाएँ, फिर बची डिस्क, स्नैपशॉट, आरक्षित/सार्वजनिक पते और नेटवर्क संसाधन जाँचें। समर्पित Azure संसाधन समूह हटाने से पहले उसकी सामग्री देखें। असंबंधित संसाधनों को प्लगइन-प्रबंधित तैनाती से बाहर रखें।

VM रोकने, सेटअप कार्य रद्द करने या प्लगइन अनइंस्टॉल करने से संसाधन हटने या शुल्क रुकने की गारंटी नहीं। कंसोल में बनाए संसाधन साफ़ करने की ज़िम्मेदारी आपकी रहती है; हटाने की पुष्टि तक प्रदाता की संसाधन ID रखें।
