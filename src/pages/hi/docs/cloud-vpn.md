# क्लाउड VM और wg-easy

अपने क्लाउड खाते में Linux VM बनाकर wg-easy से WireGuard VPN चलाएँ। संगत Android बिल्ड पर प्रकाशित **VPN Setup** प्लगइन एक निर्देशित वर्कफ़्लो में VM बना सकता है, wg-easy इंस्टॉल और क्लाइंट आयात कर सकता है। आप प्रदाता के कंसोल में VM बनाकर Mobile SSH से इंस्टॉल कर सकते हैं या मौजूदा सार्वजनिक सर्वर इस्तेमाल कर सकते हैं।

**उपलब्धता — 19 नवंबर 2026:** **VPN Setup 1.0.7** [डिफ़ॉल्ट प्लगइन कैटलॉग](https://github.com/mobile-ssh/mobile-ssh-plugins/tree/main/plugins/vpnsetup) में प्रकाशित है। मूल सेटअप के लिए प्लगइन ब्रिज **1.3.0**, सर्वर अपडेट के लिए **1.4.0** और पात्र पूरी प्रविष्टियाँ हटाने के लिए **1.5.0** चाहिए। उपलब्धता आपके इंस्टॉल Android बिल्ड और रिलीज़ ट्रैक पर निर्भर है; प्लगइन प्रकाशित होना किसी ऐप रिलीज़ के आपके लिए उपलब्ध होने की पुष्टि नहीं करता। समान iOS स्वचालन स्थापित नहीं है। प्लगइन न मिले तो नीचे कंसोल और मैन्युअल निर्देश अपनाएँ।

## निर्देशित या मैन्युअल वर्कफ़्लो चुनें

- **क्लाउड API से बनाएँ:** VPN Setup आपके प्रदाता खाते से VM और नेटवर्क संसाधन बनाता है, SSH कनेक्शन सहेजता है, wg-easy इंस्टॉल और क्लाइंट आयात करता है। बाद की सफ़ाई के लिए संसाधन ID और स्वामित्व रिकॉर्ड रखता है।
- **क्लाउड कंसोल में बनाएँ या मौजूदा सर्वर इस्तेमाल करें:** VM स्वयं बनाएँ, फिर उसका सार्वजनिक IPv4, SSH उपयोगकर्ता नाम और कुंजी VPN Setup को दें, या नीचे मैन्युअल इंस्टॉलेशन करें। आपके सर्वर पर इंस्टॉल करने के लिए प्लगइन को क्लाउड API क्रेडेंशियल नहीं चाहिए।

प्रकाशित प्लगइन संसाधन निर्माण और इंस्टॉलेशन दोनों करता है; अलग प्रोविज़नर और इंस्टॉलर प्लगइन अभी नियोजित संरचना हैं। API से बने संसाधनों और स्वयं लाए सर्वरों के हटाने का व्यवहार अलग है, जैसा नीचे बताया है। दर्ज किए गए वास्तविक Hetzner परीक्षण ने Android एमुलेटर पर सेटअप, VPN ट्रैफ़िक, क्लाइंट प्रबंधन, निजी प्रशासन और सफ़ाई पास की। इससे हर प्रदाता, खाता नीति या वास्तविक फ़ोन पर सफल परीक्षण सिद्ध नहीं होता।

## खाता और सर्वर सेटिंग तैयार करें

1. क्लाउड खाता और बिलिंग सक्रिय करें, क्षेत्र चुनें और VM, डिस्क व सार्वजनिक IP के कोटे जाँचें। प्रदाता के वर्तमान VM, IPv4, संग्रह और ट्रैफ़िक शुल्क देखें; मुफ़्त स्तर उपलब्ध मानकर न चलें।
2. इस मार्गदर्शिका के लिए कम-से-कम **1 GB RAM और 20 GB डिस्क** वाला समर्पित **Ubuntu 24.04 LTS** VM, **amd64 या arm64** पर चुनें। ये इस सेटअप के आधारभूत विकल्प हैं, wg-easy की सार्वभौमिक न्यूनतम आवश्यकताएँ नहीं। root या sudo पहुँच वाला लॉगिन लें; बिना हस्तक्षेप की स्थापना के लिए गैर-संवादी अधिकार-वृद्धि चाहिए।
3. SSH कुंजी चुनें या बनाएँ और निजी कुंजी Mobile SSH में रखें। क्लाउड में केवल सार्वजनिक कुंजी अपलोड करें। Lightsail के आयात मार्ग के लिए RSA SSH कुंजी चाहिए। अन्य प्रदाताओं और इमेज के स्वीकार्य कुंजी प्रकार अलग हो सकते हैं। वर्तमान iOS SSH क्लाइंट RSA निजी कुंजियों के बजाय Ed25519/ECDSA समर्थित करता है। iOS पर Lightsail के लिए पहले प्रदाता के ब्राउज़र SSH कंसोल से ऐप द्वारा समर्थित सार्वजनिक कुंजी `authorized_keys` में जोड़ें, फिर उसी कुंजी से जुड़ें।
4. **सार्वजनिक IPv4** चुनें; उपलब्ध हो तो आरक्षित/स्थिर पता बेहतर है। निजी पता, केवल IPv6 वाला इंस्टेंस या सिर्फ़ आउटबाउंड NAT गेटवे इस मार्गदर्शिका की एंडपॉइंट आवश्यकता पूरी नहीं करता।
5. SSH स्रोत CIDR स्पष्ट सेट करें, जैसे आपके वर्तमान सार्वजनिक IPv4 के बाद `/32`। प्लगइन का डिफ़ॉल्ट पहुँच सीमित करता है, ऐसा न मानें। मोबाइल डेटा और Wi-Fi बदलने पर क्लाउड कंसोल से नियम बदलना पड़ सकता है।

मैन्युअल तरीका ऊपर की आर्किटेक्चर समर्थित करता है। VPN Setup अभी **amd64/x86-64 पर Ubuntu 24.04** चुनता है, **SSH पोर्ट 22** से जुड़ता है और **Ed25519 या RSA** SSH कुंजियाँ स्वीकार करता है; उसके Lightsail तरीके में RSA चाहिए। ECDSA कुंजियाँ, केवल निजी होस्ट और केवल IPv6 एंडपॉइंट इस वर्कफ़्लो में समर्थित नहीं हैं। मौजूदा सर्वर के पास सार्वजनिक IPv4 और बिना इंटरैक्टिव पूछताछ के प्रशासनिक पहुँच होनी चाहिए।

क्लाउड API क्रेडेंशियल संसाधन प्रबंधन और SSH कुंजियाँ सर्वर लॉगिन का अधिकार देती हैं। API रहस्य केवल सुरक्षित नेटिव क्रेडेंशियल फ़ॉर्म में दें, कभी वॉइस प्रॉम्प्ट, टर्मिनल कमांड या स्रोत फ़ाइलों में नहीं। नेटिव कोड मंज़ूर प्रदाता एंडपॉइंट से प्रमाणीकरण करता है; रहस्य VM या प्लगइन वर्कर को नहीं जाते। याद रखे क्रेडेंशियल Android Keystore से एन्क्रिप्ट होते हैं; याद न रखने पर वे मेमोरी में रहते हैं और ऐप प्रक्रिया समाप्त होने के बाद फिर देने पड़ सकते हैं।

वॉइस नियंत्रण समर्थित गैर-गोपनीय प्रश्नों का उत्तर और प्रगति बता सकते हैं, लेकिन क्रेडेंशियल भरने और मंज़ूरी के लिए स्क्रीन चाहिए। सुरक्षित क्रेडेंशियल फ़ॉर्म के समय माइक्रोफ़ोन रिकॉर्डिंग रुकती है और फिर शुरू करने के लिए स्पष्ट कार्रवाई चाहिए। वॉइस सेटअप के लिए उसका ऑप्ट-इन, डाउनलोड किया स्थानीय मॉडल और माइक्रोफ़ोन अनुमति चाहिए। ऑफ़लाइन वॉइस मॉडल क्लाउड API कॉल, डाउनलोड या SSH को इंटरनेट के बिना नहीं चलाता।

## क्लाउड चुनें और सार्वजनिक पता लें

**कंसोल सेटअप** के लिए प्रदाता में स्वयं साइन इन करें; Mobile SSH को उसके API क्रेडेंशियल नहीं चाहिए। **VPN Setup API प्रोविज़निंग** के लिए नीचे के क्रेडेंशियल को आवश्यक बनाने, पढ़ने, नेटवर्क और हटाने की अनुमतियों के साथ तैयार करें। प्लगइन इस तालिका के दस प्रदाता लागू करता है; AWS EC2 अलग, केवल कंसोल विकल्प है। जहाँ संभव हो पहुँच समर्पित प्रोजेक्ट या डिप्लॉयमेंट तक सीमित करें। दोनों तरीकों पर खाता नीतियाँ लागू रहती हैं।

चुना हुआ Ubuntu VM अपनी SSH सार्वजनिक कुंजी से बनाएँ और अगले भाग का SSH नियम लगाएँ। लिंक प्रदाता के अनुसार पता और प्रमाणीकरण के चरण बताते हैं।

| [Scaleway Instances](./scaleway/) | IAM एप्लिकेशन की API रहस्य कुंजी और प्रोजेक्ट UUID, इंस्टेंस, वॉल्यूम, IP, सुरक्षा समूह और SSH-कुंजी अनुमतियों सहित। [API कुंजी निर्माण](https://www.scaleway.com/en/docs/iam/credentials/create-api-keys/) देखें। | Ubuntu इंस्टेंस बनाएँ, [उसी ज़ोन में flexible routed IPv4](https://www.scaleway.com/en/docs/instances/how-to/use-flexips/) जोड़ें, सुरक्षा समूह सेट करें और चालू करें। इमेज का SSH लॉगिन लें, आम तौर पर `root`। |

**[AWS EC2](./aws-ec2/) विकल्प:** [इंटरनेट गेटवे और `0.0.0.0/0` गेटवे रूट](https://docs.aws.amazon.com/vpc/latest/userguide/VPC_Internet_Gateway.html) वाले सार्वजनिक सबनेट में Ubuntu शुरू करें, SSH कुंजी और सुरक्षा समूह चुनें, फिर [Elastic IP](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/working-with-eips.html) जोड़ें। `ubuntu` लें। VPN Setup का स्वचालित AWS एडैप्टर Lightsail के लिए है; EC2 कंसोल मार्ग है। केवल Elastic IP से निजी सबनेट पहुँच योग्य नहीं बनता।

संगठन सेवा-खाते की कुंजियाँ, बाहरी IP या चुना SSH प्रमाणीकरण तरीका रोकता हो तो व्यवस्थापक से अनुमोदित कॉन्फ़िगरेशन लें। कंसोल सेटअप उन पाबंदियों को पार नहीं करता।

## संसाधन बनाएँ और SSH कनेक्शन सहेजें

**प्लगइन** खोलें, डिफ़ॉल्ट कैटलॉग से **VPN Setup** इंस्टॉल करके उसका अलग पेज खोलें। **VPN सेट करें**, प्रदाता, फिर **क्लाउड API से बनाएँ** या **क्लाउड कंसोल में बनाएँ** चुनें। पहले से मौजूद सर्वर के लिए मौजूदा सार्वजनिक सर्वर विकल्प चुनें। नेटिव फ़ॉर्म में क्रेडेंशियल दें, SSH कुंजी चुनें या बनाएँ और स्थान, आकार, इमेज व SSH स्रोत CIDR जाँचें। खाते से मिले विकल्प और पूर्व-जाँच समर्थित ऑफ़र चुनने में मदद करते हैं; वे क्षमता आरक्षित या कोटे की गारंटी नहीं देते। प्रदाता की मौजूदा कीमतें देखें और स्क्रीन पर निर्माण मंज़ूर करें।

VM और SSH तैयार होने तक उसी कार्रवाई को जारी रखें। अनुरोध का समय समाप्त हो या Android पृष्ठभूमि कार्य रोके तो दूसरा शुल्क वाला VM बनाने के बजाय उसी कार्रवाई को जारी करें या जाँचें। निर्माण का उत्तर खोने पर क्लाउड में खोज या कंसोल जाँच चाहिए हो सकती है। VM, डिस्क, पता और फ़ायरवॉल संसाधन ID रखें; रुके वर्कफ़्लो ने भी संसाधन बनाए हो सकते हैं।

VPN Setup SSH होस्ट कुंजी की मंज़ूरी माँगता है, कनेक्शन सहेजता है, wg-easy इंस्टॉल और पहला क्लाइंट आयात करता है। फ़िंगरप्रिंट को प्रदाता के विश्वसनीय कंसोल से मिलाएँ। मैन्युअल सेटअप में **सर्वर** के अंतर्गत सार्वजनिक IPv4, SSH पोर्ट `22`, इमेज उपयोगकर्ता नाम और मेल खाती निजी कुंजी दें। स्वचालित Google Cloud और Azure एडैप्टर `ubuntu` इस्तेमाल करते हैं; कंसोल गाइड वहाँ सेट किए उपयोगकर्ता नाम लेते हैं। पहचान जाँच और सहेजे क्रेडेंशियल के लिए [शुरुआत करें](../getting-started/) देखें।

## नेटवर्क की दोनों परतें सेट करें

सार्वजनिक पते के लिए रूट, क्लाउड फ़ायरवॉल अनुमति, गेस्ट फ़ायरवॉल अनुमति और सुनती हुई सेवा चाहिए। प्रदाता के फ़ायरवॉल/सुरक्षा समूह में ये नियम लगाएँ; आवश्यक मौजूदा गेस्ट नियम बनाए रखें।

- **TCP 22:** SSH के लिए चुने प्रबंधन CIDR से अनुमति दें। संसाधन बनाते समय इसे सेट करें।
- **UDP 51820:** VPN इस्तेमाल करने वाले नेटवर्क से अनुमति दें। घूमते क्लाइंट के लिए यह `0.0.0.0/0` हो सकता है। API से बनाए डिप्लॉयमेंट के लिए VPN Setup इसे सेट करता है; अपने लाए सर्वर के लिए क्लाउड कंसोल इस्तेमाल करें।
- **TCP 51821:** सार्वजनिक रूप से बंद रखें। wg-easy व्यवस्थापक UI केवल सर्वर लूपबैक पर प्रकाशित करें और SSH सुरंग से पहुँचें।
- **आउटबाउंड ट्रैफ़िक:** पैकेज/कंटेनर डाउनलोड, DNS और VPN द्वारा ले जाए जाने वाले इंटरनेट ट्रैफ़िक को अनुमति दें।

Docker का [फ़ायरवॉल व्यवहार](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations) देखें: प्रकाशित कंटेनर पोर्ट UFW नियमों को पार कर सकते हैं। व्यवस्थापक UI छिपाने के लिए केवल UFW पर भरोसा न करें और प्रदाता की फ़ायरवॉल चेन साफ़ न करें, विशेषकर OCI के संग्रह/iSCSI नियम।

## चुने VM पर wg-easy स्थापित करें

मंज़ूरी के बाद VPN Setup SSH से डाइजेस्ट पर पिन किया wg-easy संस्करण इंस्टॉल करता है, Ubuntu 24.04 पर ज़रूरत होने पर Docker इंस्टॉल करता है और पहला क्लाइंट बनाता है। प्रशासनिक इंटरफ़ेस सर्वर लूपबैक पर रहता है और प्रदाता की फ़ायरवॉल चेन बची रहती हैं। कंसोल में बनाए या मौजूदा सर्वर के लिए क्लाउड फ़ायरवॉल स्वयं सेट करें; इंस्टॉलर को SSH पहुँच और प्रशासनिक अधिकार चाहिए, क्लाउड API रहस्य नहीं। असंबंधित VPN इंस्टॉलेशन अपनाने की धारणा के बजाय नया समर्पित सर्वर लें।

पुराने **WireGuard (wg-easy)** कैटलॉग प्लगइन को सक्रिय SSH सत्र और Docker चाहिए। यह **VPN Setup** से अलग है और नेटिव क्लाइंट आयात का वादा नहीं करता। संगत Android बिल्ड पर VPN Setup लें, या नए समर्पित VM पर Mobile SSH टर्मिनल से नीचे का मैन्युअल तरीका अपनाएँ।

### SSH से मैन्युअल स्थापना

आधिकारिक [Ubuntu निर्देशों](https://docs.docker.com/engine/install/ubuntu/) से Docker Engine और उसका Compose प्लगइन स्थापित करें। फिर संस्करण-विशिष्ट अपस्ट्रीम कॉन्फ़िगरेशन डाउनलोड करें:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.5.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

शुरू करने से पहले प्रशासनिक अधिकार वाले टर्मिनल एडिटर में `/opt/wg-easy/compose.yaml` संपादित करें। `services.wg-easy` में इमेज बदलें, environment ब्लॉक अनकमेंट/सेट करें और पोर्ट मैपिंग को इन मानों से बदलें। अपस्ट्रीम फ़ाइल का बाकी हिस्सा रखें, जिसमें स्थायी वॉल्यूम, मॉड्यूल माउंट, क्षमताएँ, नेटवर्क और sysctls शामिल हैं:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.5.0@sha256:071f79a639e9361123a5e57733107320207b844ddbbd92dfa6962f541fe8aac8
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

यह बदलने वाला अंश है, पूरी Compose फ़ाइल नहीं; सेवा के भीतर YAML इंडेंटेशन बनाए रखें। `INSECURE=true` केवल लूपबैक SSH सुरंग के लिए HTTP की अनुमति देता है। व्यवस्थापक पोर्ट इंटरनेट पर प्रकाशित न करें। कंटेनर का लिसनर होस्ट की लूपबैक मैपिंग से अलग है। अपस्ट्रीम का [HTTP कॉन्फ़िगरेशन](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) देखें।

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

कंटेनर का `/etc/wireguard` डेटा उसके स्थायी वॉल्यूम में रखें। पुराने `PASSWORD`, `PASSWORD_HASH` या `WG_HOST` नुस्खे v15 पर न लगाएँ; उसका सेटअप विज़ार्ड लें। इमेज जानबूझकर पिन की गई है: अपग्रेड के लिए नए संस्करण की समीक्षा और पिन बदलना चाहिए, केवल `pull` चलाना पर्याप्त नहीं।

## व्यवस्थापक UI खोलें और क्लाइंट जोड़ें

Mobile SSH में स्थानीय पोर्ट `51821`, दूरस्थ होस्ट `127.0.0.1` और दूरस्थ पोर्ट `51821` वाला [स्थानीय पोर्ट फ़ॉरवर्ड](../port-forwarding/) बनाएँ। SSH कनेक्शन सक्रिय रखें और उसी फ़ोन पर `http://127.0.0.1:51821` खोलें। स्थानीय पोर्ट व्यस्त हो तो दूसरा चुनें और ब्राउज़र URL में वही लें।

wg-easy के [पहले उपयोग के विज़ार्ड](https://wg-easy.github.io/wg-easy/latest/guides/setup/) में व्यवस्थापक खाता बनाएँ, नई स्थापना चुनें और VPN एंडपॉइंट में VM का सार्वजनिक IPv4 या DNS नाम तथा पोर्ट `51820` दें। VPN एंडपॉइंट वेब UI का लूपबैक पता या पोर्ट `51821` नहीं है।

हर डिवाइस के लिए एक क्लाइंट बनाएँ और उसकी WireGuard `.conf` डाउनलोड करें। आपके Mobile SSH बिल्ड में उपलब्ध हो तो **VPN → WireGuard** खोलें, प्रोफ़ाइल जोड़ें, फ़ाइल आयात करें और सहेजें। वर्तमान Android और iOS स्रोत फ़ाइल आयात समर्थित करते हैं; अपना इंस्टॉल बिल्ड जाँचें। संगत Android बिल्ड पर VPN Setup पहला क्लाइंट सीधे आयात करता है। उसके पेज पर निजी SSH टनल से **क्लाइंट जोड़ें**, **क्लाइंट निरस्त करें**, **क्लाइंट/QR निर्यात करें** और **प्रशासन खोलें** भी हैं। इससे पुराने प्लगइन या समान iOS स्वचालन की ये क्षमताएँ सिद्ध नहीं होतीं। कॉन्फ़िगरेशन फ़ाइल और QR कोड में निजी कुंजियाँ होती हैं; इन्हें निजी रखें।

## VPN जाँचें और विफलताएँ सँभालें

प्रोफ़ाइल शुरू करें और ऑपरेटिंग सिस्टम का VPN अनुरोध स्वीकारें। हाल का पीयर हैंडशेक और बढ़ते ट्रैफ़िक काउंटर देखें, फिर DNS और इच्छित इंटरनेट या निजी-नेटवर्क रूट जाँचें। आयातित प्रोफ़ाइल या चलता कंटेनर अकेले काम करते VPN का प्रमाण नहीं।

- **VM निर्माण अस्वीकार:** बिलिंग, कोटा, क्षेत्रीय क्षमता, क्रेडेंशियल की अवधि और सटीक IAM अनुमतियाँ जाँचें। Google Cloud फ़ायरवॉल लिखने के लिए Compute Network Admin से अतिरिक्त अधिकार चाहिए; संगठन द्वारा अनिवार्य OS Login के लिए मंज़ूर कंसोल सेटअप चाहिए।
- **SSH टाइमआउट:** सार्वजनिक पता, सबनेट रूटिंग, TCP 22 नियम और फ़ोन का वर्तमान स्रोत IP जाँचें। प्रमाणीकरण विफलता में आम तौर पर सही इमेज उपयोगकर्ता नाम और SSH कुंजी चाहिए।
- **व्यवस्थापक UI अनुपलब्ध:** SSH फ़ॉरवर्डिंग जुड़ी रखें, कंटेनर स्थिति और लूपबैक पोर्ट मैपिंग जाँचें तथा पुष्टि करें कि HTTP केवल सुरंग के लिए चालू है।
- **WireGuard हैंडशेक नहीं:** क्लाइंट एंडपॉइंट, दोनों फ़ायरवॉल परतों में UDP 51820, क्लाइंट कुंजियाँ और सर्वर का सुनना जाँचें।
- **हैंडशेक है, ट्रैफ़िक नहीं:** फ़ॉरवर्डिंग/NAT, DNS, रूट ओवरलैप और `AllowedIPs` देखें। पूर्ण-सुरंग IPv4 में `0.0.0.0/0` लगता है; IPv6 अलग परखें। अपस्ट्रीम IPv6 रहित VM IPv6 इंटरनेट निकास नहीं दे सकता, और केवल IPv4 रूट IPv6 को VPN के बाहर छोड़ सकते हैं।

## प्लगइन और VPN सर्वर अपडेट करें

**प्लगइन** में उसी कैटलॉग के नए संगत संस्करण के लिए उपलब्ध **अपडेट** कार्रवाई चुनें। नई माँगी गई क्षमताएँ जाँचें। सेटिंग, क्रेडेंशियल और डिप्लॉयमेंट रिकॉर्ड रहते हैं; अधूरी कार्रवाई उसे शुरू करने वाले प्लगइन संस्करण पर चलती रहती है। केवल प्लगइन अपडेट से सर्वर का wg-easy कंटेनर अपडेट नहीं होता।

प्लगइन ब्रिज 1.4.0 या नए पर **सर्वर जाँचें** चल रहे wg-easy संस्करण को बताता है और **WireGuard अपडेट करें** प्लगइन का पिन किया संस्करण देता है। स्क्रीन पर अपडेट मंज़ूर करें। सेवा बदलने से पहले इमेज डाउनलोड होती है और सर्वर कुंजियाँ, क्लाइंट व स्थानीय प्रोफ़ाइल बचते हैं। यह फ़ोन उसी VPN पर हो तो ऐप अपडेट से पहले उसे डिस्कनेक्ट करता है; बाद में फिर जुड़ें। इससे प्रबंधित कंटेनर अपडेट होता है, होस्ट ऑपरेटिंग सिस्टम नहीं।

विफल अपडेट इमेज डाउनलोड विफलता, सफल रोलबैक और VPN बंद छोड़ने वाले विफल रोलबैक को अलग बताता है। सेवा लौटने की धारणा के बजाय उसकी रिकवरी जाँच या पुनः प्रयास अपनाएँ। मैन्युअल इंस्टॉलेशन में अलग से जाँचा इमेज पिन बदलाव और बैकअप चाहिए; ऊपर का नया इंस्टॉलेशन तरीका माइग्रेशन गाइड नहीं है।

## क्लाइंट हटाएँ और क्लाउड शुल्क रोकें

स्थानीय प्रोफ़ाइल हटाने से पहले wg-easy में क्लाइंट रद्द करें। Mobile SSH में प्रोफ़ाइल हटाने से सर्वर की पीयर कुंजी रद्द नहीं होती। VPN कंटेनर या स्थायी डेटा हटाने से पहले आवश्यक कॉन्फ़िगरेशन का सुरक्षित बैकअप लें।

API से बने डिप्लॉयमेंट के लिए **डिप्लॉयमेंट हटाएँ** प्रदाता API से उसके स्वामित्व वाले क्लाउड संसाधन जाँचकर हटाता है, SSH उपलब्ध न हो तब भी। हटाना रुके या विफल हो तो बताए गए बचे संसाधन जाँचें; सफ़ाई जारी करें या कंसोल देखें। प्लगइन प्रबंधित डिप्लॉयमेंट, विशेषतः उसके समर्पित Azure संसाधन समूह, में असंबंधित संसाधन न रखें।

कंसोल में बने या मौजूदा सर्वर पर प्लगइन हटाना उसका प्रबंधित VPN इंस्टॉलेशन हटाता है; आपकी VM या सार्वजनिक IP **नहीं** हटाता। ज़रूरत समाप्त होने पर उन्हें प्रदाता कंसोल में हटाएँ, फिर बची डिस्क, स्नैपशॉट, पते और नेटवर्क संसाधन जाँचें। रिकवरी में खाता या स्थान बदला हो तो पहले वाला भी देखें, जिसमें पिछला Scaleway प्रोजेक्ट या Oracle Cloud कम्पार्टमेंट शामिल है।

**वर्कफ़्लो रोकें** कार्रवाई रोकता है; संसाधन नहीं हटाता। ब्रिज 1.5.0 या नए पर **सूची से हटाएँ** तभी मिलता है जब ऐप जाँच सके कि प्रविष्टि भूलने योग्य है और कोई अधूरी कार्रवाई या बाकी प्रबंधित संसाधन नहीं हैं। यह स्थानीय इतिहास हटाता है, क्लाउड संसाधन नहीं। VM रोकने या प्लगइन अनइंस्टॉल करने से भी शुल्क रुकने की गारंटी नहीं। हटाने की पुष्टि तक संसाधन ID रखें।
