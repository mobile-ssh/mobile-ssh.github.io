# क्लाउड VM आणि wg-easy

स्वतःच्या क्लाउड खात्यात Linux VM तयार करून wg-easy सह WireGuard VPN चालवा. सुसंगत Android बिल्डवर प्रकाशित **VPN Setup** प्लगइन एका मार्गदर्शित कार्यप्रवाहात VM तयार करून wg-easy स्थापित व क्लायंट आयात करू शकते. प्रदात्याच्या कन्सोलमध्ये VM तयार करून Mobile SSH मधून स्थापित करू शकता किंवा विद्यमान सार्वजनिक सर्व्हर वापरू शकता.

**उपलब्धता — 19 नोव्हेंबर 2026:** **VPN Setup 1.0.7** [पूर्वनिर्धारित प्लगइन कॅटलॉगमध्ये](https://github.com/mobile-ssh/mobile-ssh-plugins/tree/main/plugins/vpnsetup) प्रकाशित आहे. मूलभूत सेटअपला प्लगइन ब्रिज **1.3.0**, सर्व्हर अद्यतनांना **1.4.0** आणि पात्र पूर्ण नोंदी काढण्यासाठी **1.5.0** लागते. उपलब्धता स्थापित Android बिल्ड व रिलीज ट्रॅकवर अवलंबून असते; प्लगइन प्रकाशित झाल्याने विशिष्ट ॲप रिलीज तुमच्यासाठी उपलब्ध असल्याची खात्री होत नाही. समतुल्य iOS स्वयंचलन स्थापित झालेले नाही. प्लगइन नसल्यास खालील कन्सोल व हाताने करण्याच्या सूचना वापरा.

## मार्गदर्शित किंवा हाताने करण्याचा कार्यप्रवाह निवडा

- **क्लाउड API ने तयार करा:** VPN Setup प्रदात्याचे खाते वापरून VM आणि नेटवर्क संसाधने तयार करते, SSH जोडणी जतन करते, wg-easy स्थापित व क्लायंट आयात करते. नंतरच्या साफसफाईसाठी संसाधन ID आणि मालकी नोंदी ठेवते.
- **क्लाउड कन्सोलमध्ये तयार करा किंवा विद्यमान सर्व्हर वापरा:** VM स्वतः तयार करून त्याचा सार्वजनिक IPv4, SSH वापरकर्तानाव आणि कळ VPN Setup ला द्या किंवा खालील हाताने स्थापना करा. तुमच्या सर्व्हरवर स्थापित करण्यासाठी प्लगइनला क्लाउड API ओळखपत्रे लागत नाहीत.

प्रकाशित प्लगइन संसाधननिर्मिती व स्थापना एकत्र करते; स्वतंत्र प्रोव्हिजनर व इंस्टॉलर प्लगइन ही अजून नियोजित रचना आहे. API ने तयार केलेली संसाधने आणि स्वतः आणलेले सर्व्हर हटवण्याचे वर्तन वेगळे आहे, जसे खाली स्पष्ट केले आहे. नोंदवलेल्या प्रत्यक्ष Hetzner चाचणीत Android एम्युलेटरवर सेटअप, VPN वाहतूक, क्लायंट व्यवस्थापन, खाजगी प्रशासन आणि साफसफाई यशस्वी झाली. यावरून प्रत्येक प्रदाता, खाते धोरण किंवा प्रत्यक्ष फोनवरील स्वीकृती सिद्ध होत नाही.

## खाते आणि सर्व्हर सेटिंग तयार करा

1. क्लाउड खाते व बिलिंग सक्रिय करा, प्रदेश निवडा आणि VM, डिस्क व सार्वजनिक IP कोटा तपासा. प्रदात्याचे सध्याचे VM, IPv4, साठवण आणि वाहतुकीचे शुल्क पाहा; मोफत स्तर उपलब्ध असेल असे गृहीत धरू नका.
2. या मार्गदर्शकासाठी **amd64 किंवा arm64** वरील किमान **1 GB RAM आणि 20 GB डिस्क** असलेला स्वतंत्र **Ubuntu 24.04 LTS** VM निवडा. हे या मांडणीचे आधारभूत पर्याय आहेत, wg-easy ची सार्वत्रिक किमान अट नाही. root किंवा sudo प्रवेश असलेले लॉगिन वापरा; विनाहस्तक्षेप स्थापनेसाठी संवाद न मागता अधिकारवाढ होणे आवश्यक आहे.
3. SSH कळ निवडा किंवा तयार करा; खाजगी कळ Mobile SSH मध्येच ठेवा. क्लाउडवर फक्त सार्वजनिक कळ अपलोड करा. Lightsail च्या आयात मार्गाला RSA SSH कळ लागते. इतर प्रदाते व इमेज कोणत्या कळा स्वीकारतात ते वेगळे असू शकते. सध्याचा iOS SSH क्लायंट RSA खाजगी कळांऐवजी Ed25519/ECDSA समर्थित करतो. iOS वर Lightsail साठी आधी प्रदात्याच्या ब्राउझर SSH कन्सोलमधून ॲपला समर्थित सार्वजनिक कळ `authorized_keys` मध्ये जोडा, मग त्या कळीने जोडा.
4. **सार्वजनिक IPv4** निवडा; प्रदाता देत असल्यास राखीव/स्थिर पत्ता प्राधान्याने वापरा. खाजगी पत्ता, केवळ IPv6 असलेला इंस्टन्स किंवा फक्त बाहेर जाणाऱ्या वाहतुकीचा NAT गेटवे या मार्गदर्शकाची अंतिम पत्त्याची अट पूर्ण करत नाही.
5. SSH स्रोत CIDR स्पष्टपणे सेट करा, उदा. सध्याच्या सार्वजनिक IPv4 पुढे `/32`. प्लगइनचा मूळ पर्याय प्रवेश मर्यादित करतो असे समजू नका. मोबाइल डेटा आणि Wi-Fi बदलल्यास क्लाउड कन्सोलमधून नियम बदलावा लागू शकतो.

हाताने करण्याचा मार्ग वरच्या आर्किटेक्चरना समर्थन देतो. VPN Setup सध्या **amd64/x86-64 वरील Ubuntu 24.04** निवडते, **SSH पोर्ट 22** वर जोडते आणि **Ed25519 किंवा RSA** SSH कळा स्वीकारते; Lightsail मार्गाला RSA लागते. ECDSA कळा, फक्त खाजगी होस्ट आणि फक्त IPv6 अंतिम पत्ते या कार्यप्रवाहात समर्थित नाहीत. विद्यमान सर्व्हरकडे सार्वजनिक IPv4 आणि संवादात्मक प्रश्नांशिवाय प्रशासकीय प्रवेश असावा.

क्लाउड API ओळखपत्रे संसाधन व्यवस्थापनाचा, तर SSH कळा सर्व्हर लॉगिनचा अधिकार देतात. API गुपिते केवळ संरक्षित नेटिव्ह ओळखपत्र फॉर्ममध्ये भरा; व्हॉइस प्रॉम्प्ट, टर्मिनल आज्ञा किंवा स्रोत फाइलमध्ये कधीही नकोत. नेटिव्ह कोड मंजूर प्रदात्याच्या अंतिम पत्त्यांशी प्रमाणीकरण करतो; गुपिते VM किंवा प्लगइन वर्करकडे जात नाहीत. लक्षात ठेवलेली ओळखपत्रे Android Keystore ने एन्क्रिप्ट होतात; लक्षात न ठेवण्याचे निवडल्यास ती मेमरीत राहतात आणि ॲप प्रक्रिया संपल्यानंतर पुन्हा द्यावी लागू शकतात.

व्हॉइस नियंत्रणे समर्थित बिगरगोपनीय प्रश्नांना उत्तरे देऊ व प्रगती सांगू शकतात; ओळखपत्रे भरणे आणि मंजुरीसाठी पडदा लागतो. संरक्षित ओळखपत्र फॉर्मवर मायक्रोफोन ध्वनिमुद्रण थांबते आणि पुन्हा सुरू करण्यासाठी स्पष्ट कृती लागते. व्हॉइस सेटअपला संमती, डाउनलोड केलेले स्थानिक मॉडेल आणि मायक्रोफोन परवानगी आवश्यक आहे. ऑफलाइन व्हॉइस मॉडेलमुळे क्लाउड API कॉल, डाउनलोड किंवा SSH इंटरनेटशिवाय चालत नाही.

## क्लाउड निवडा आणि सार्वजनिक पत्ता मिळवा

**कन्सोल सेटअप** साठी प्रदात्याकडे स्वतः साइन इन करा; Mobile SSH ला त्याची API ओळखपत्रे लागत नाहीत. **VPN Setup API संसाधननिर्मितीसाठी** खालील ओळखपत्र आवश्यक तयार करणे, वाचणे, नेटवर्क आणि हटवण्याच्या परवानग्यांसह तयार ठेवा. प्लगइन या तक्त्यातील दहा प्रदाते अंमलात आणते; AWS EC2 हा स्वतंत्र, केवळ कन्सोल पर्याय आहे. समर्थित असल्यास प्रवेश स्वतंत्र प्रकल्प किंवा तैनातीपुरता मर्यादित ठेवा. दोन्ही पद्धतींना खाते धोरणे लागू होतात.

तुमची SSH सार्वजनिक कळ वापरून निवडलेला Ubuntu VM तयार करा आणि पुढील विभागातील SSH नियम लावा. दुव्यांमध्ये प्रदात्यानुसार पत्ता आणि प्रमाणीकरणाचे टप्पे आहेत.

Floating/Additional IP ही स्वतंत्र संसाधने आहेत. |
| [Scaleway Instances](./scaleway/) | IAM ॲप्लिकेशनची API गुप्त कळ आणि प्रकल्प UUID; इंस्टन्स, व्हॉल्यूम, IP, सुरक्षा गट व SSH-कळ परवानग्यांसह. [API कळ निर्मिती](https://www.scaleway.com/en/docs/iam/credentials/create-api-keys/) पाहा. | Ubuntu इंस्टन्स तयार करा, [त्याच झोनमधील flexible routed IPv4](https://www.scaleway.com/en/docs/instances/how-to/use-flexips/) जोडा, सुरक्षा गट सेट करा व चालू करा. इमेजचे SSH लॉगिन वापरा, सहसा `root`. |

</div>

**[AWS EC2](./aws-ec2/) पर्याय:** [इंटरनेट गेटवे आणि `0.0.0.0/0` गेटवे मार्ग](https://docs.aws.amazon.com/vpc/latest/userguide/VPC_Internet_Gateway.html) असलेल्या सार्वजनिक सबनेटमध्ये Ubuntu सुरू करा, SSH कळ व सुरक्षा गट निवडा, मग [Elastic IP](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/working-with-eips.html) जोडा. `ubuntu` वापरा. VPN Setup चा स्वयंचलित AWS अडॅप्टर Lightsail साठी आहे; EC2 हा कन्सोल मार्ग आहे. केवळ Elastic IP मुळे खाजगी सबनेटपर्यंत पोहोचता येत नाही.

संस्थेने सेवा-खात्याच्या कळा, बाह्य IP किंवा तुमची SSH प्रमाणीकरण पद्धत प्रतिबंधित केली असल्यास प्रशासकाने मंजूर केलेली संरचना मिळवा. कन्सोल मांडणीमुळे ते निर्बंध चुकवता येत नाहीत.

## संसाधने तयार करा आणि SSH जोडणी जतन करा

**प्लगइन** उघडा, पूर्वनिर्धारित कॅटलॉगमधून **VPN Setup** स्थापित करून त्याचे स्वतंत्र पान उघडा. **VPN सेट करा**, प्रदाता आणि मग **क्लाउड API ने तयार करा** किंवा **क्लाउड कन्सोलमध्ये तयार करा** निवडा. आधीपासून असलेल्या सर्व्हरसाठी विद्यमान सार्वजनिक सर्व्हर पर्याय घ्या. नेटिव्ह फॉर्ममध्ये ओळखपत्रे भरा, SSH कळ निवडा किंवा तयार करा आणि स्थान, आकार, इमेज व SSH स्रोत CIDR तपासा. खात्याधारित पर्याय आणि पूर्वतपासण्या समर्थित पर्याय निवडण्यास मदत करतात; त्या क्षमता राखत किंवा कोट्याची हमी देत नाहीत. प्रदात्याचे सध्याचे दर पाहून पडद्यावर निर्मिती मंजूर करा.

VM आणि SSH तयार होईपर्यंत विद्यमान प्रक्रिया चालू ठेवा. विनंतीची वेळ संपली किंवा Android ने पार्श्वभूमी काम थांबवले तर आणखी शुल्क लागणारा VM बनवण्याऐवजी तीच प्रक्रिया पुढे चालू करा किंवा तपासा. निर्मितीचे उत्तर हरवल्यास क्लाउड शोध किंवा कन्सोल तपासणी लागू शकते. VM, डिस्क, पत्ता व फायरवॉल संसाधन ID ठेवा; थांबलेल्या कार्यप्रवाहानेही संसाधने तयार केली असू शकतात.

VPN Setup SSH होस्ट कळीची मंजुरी मागते, जोडणी जतन करते, wg-easy स्थापित करते आणि पहिला क्लायंट आयात करते. फिंगरप्रिंट प्रदात्याच्या विश्वसनीय कन्सोलशी जुळवा. हाताने सेटअप करताना **सर्व्हर** मध्ये सार्वजनिक IPv4, SSH पोर्ट `22`, इमेज वापरकर्तानाव आणि जुळणारी खाजगी कळ द्या. स्वयंचलित Google Cloud व Azure अडॅप्टर `ubuntu` वापरतात; कन्सोल मार्गदर्शक तिथे सेट केलेली वापरकर्तानावे वापरतात. ओळख तपासणी व जतन केलेल्या ओळखपत्रांसाठी [सुरुवात](../getting-started/) पाहा.

## नेटवर्कचे दोन्ही स्तर सेट करा

सार्वजनिक पत्त्याला मार्ग, क्लाउड फायरवॉल परवानगी, गेस्ट फायरवॉल परवानगी आणि ऐकणारी सेवा आवश्यक आहे. प्रदात्याच्या फायरवॉल/सुरक्षा गटात हे नियम वापरा; आवश्यक विद्यमान गेस्ट नियम राखा.

- **TCP 22:** SSH साठी निवडलेल्या व्यवस्थापन CIDR मधून प्रवेश द्या. संसाधननिर्मितीच्या वेळी सेट करा.
- **UDP 51820:** VPN वापरणाऱ्या नेटवर्कना प्रवेश द्या. फिरत्या क्लायंटसाठी हे `0.0.0.0/0` असू शकते. API ने केलेल्या तैनातीसाठी VPN Setup हे सेट करते; तुम्ही आणलेल्या सर्व्हरसाठी क्लाउड कन्सोल वापरा.
- **TCP 51821:** सार्वजनिकरीत्या बंद ठेवा. wg-easy प्रशासक UI फक्त सर्व्हर लूपबॅकवर प्रकाशित करा आणि SSH टनेलमधून उघडा.
- **बाहेर जाणारी वाहतूक:** पॅकेज/कंटेनर डाउनलोड, DNS आणि VPN ने वाहून न्यायची इंटरनेट वाहतूक अनुमत करा.

Docker चे [फायरवॉल वर्तन](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations) तपासा: प्रकाशित कंटेनर पोर्ट UFW नियम वगळू शकतात. प्रशासक UI लपवण्यासाठी केवळ UFW वर अवलंबून राहू नका; प्रदात्याच्या फायरवॉल साखळ्या, विशेषतः OCI साठवण/iSCSI नियम, पुसू नका.

## निवडलेल्या VM वर wg-easy स्थापित करा

मंजुरीनंतर VPN Setup SSH वरून डायजेस्टनुसार निश्चित केलेली wg-easy आवृत्ती स्थापित करते, Ubuntu 24.04 वर गरज असल्यास Docker स्थापित करते आणि पहिला क्लायंट तयार करते. प्रशासक इंटरफेस सर्व्हर लूपबॅकवर राहतो आणि प्रदात्याच्या फायरवॉल साखळ्या जपल्या जातात. कन्सोलमध्ये तयार किंवा विद्यमान सर्व्हरसाठी क्लाउड फायरवॉल स्वतः सेट करा; इंस्टॉलरला SSH प्रवेश व प्रशासकीय अधिकार लागतात, क्लाउड API गुपित नाही. असंबंधित VPN स्थापना स्वीकारेल असे गृहीत न धरता नवीन स्वतंत्र सर्व्हर वापरा.

जुन्या **WireGuard (wg-easy)** कॅटलॉग प्लगइनला सक्रिय SSH सत्र आणि Docker लागतो. ते **VPN Setup** पेक्षा वेगळे असून नेटिव्ह क्लायंट आयातीचे आश्वासन देत नाही. सुसंगत Android बिल्डवर VPN Setup वापरा किंवा नवीन स्वतंत्र VM वर Mobile SSH टर्मिनलमधून खालील हाताने मार्ग वापरा.

### SSH मधून हाताने स्थापना

अधिकृत [Ubuntu सूचनांनुसार](https://docs.docker.com/engine/install/ubuntu/) Docker Engine आणि त्याचा Compose प्लगइन स्थापित करा. मग आवृत्तीविशिष्ट अपस्ट्रीम संरचना डाउनलोड करा:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.5.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

सुरू करण्यापूर्वी अधिकार असलेल्या टर्मिनल संपादकातून `/opt/wg-easy/compose.yaml` संपादित करा. `services.wg-easy` मध्ये इमेज बदला, environment विभाग अनकमेंट/सेट करा आणि पोर्ट मॅपिंग पुढील मूल्यांनी बदला. कायमस्वरूपी व्हॉल्यूम, मॉड्यूल माउंट, क्षमता, नेटवर्क आणि sysctls सहित उर्वरित अपस्ट्रीम फाइल तशीच ठेवा:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.5.0@sha256:071f79a639e9361123a5e57733107320207b844ddbbd92dfa6962f541fe8aac8
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

हा बदलण्यासाठीचा भाग आहे, संपूर्ण Compose फाइल नाही; सेवेच्या आत YAML ची मोकळी जागा जशी हवी तशी राखा. `INSECURE=true` केवळ लूपबॅक SSH टनेलसाठी HTTP परवानगी देते. प्रशासक पोर्ट इंटरनेटवर प्रकाशित करू नका. कंटेनरचा लिसनर आणि होस्टच्या लूपबॅक मॅपिंग वेगळे आहेत. अपस्ट्रीमचे [HTTP संरचना मार्गदर्शन](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) पाहा.

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

कंटेनरमधील `/etc/wireguard` डेटा त्याच्या कायमस्वरूपी व्हॉल्यूममध्ये ठेवा. जुने `PASSWORD`, `PASSWORD_HASH` किंवा `WG_HOST` निर्देश v15 ला लागू करू नका; त्याचा सेटअप विझार्ड वापरा. इमेज मुद्दाम पिन केलेली आहे: अपग्रेडसाठी नव्या आवृत्तीचे पुनरावलोकन करून पिन बदलावा लागतो; फक्त `pull` पुरेसे नाही.

## प्रशासक UI उघडा आणि क्लायंट जोडा

Mobile SSH मध्ये स्थानिक पोर्ट `51821`, दूरस्थ होस्ट `127.0.0.1` आणि दूरस्थ पोर्ट `51821` असलेला [स्थानिक पोर्ट फॉरवर्ड](../port-forwarding/) तयार करा. SSH जोडणी चालू ठेवा आणि त्याच फोनवर `http://127.0.0.1:51821` उघडा. स्थानिक पोर्ट वापरात असल्यास दुसरा निवडा आणि ब्राउझर URL मध्ये तो वापरा.

wg-easy च्या [पहिल्या वापराच्या विझार्डमध्ये](https://wg-easy.github.io/wg-easy/latest/guides/setup/) प्रशासक खाते तयार करा, नवीन स्थापना निवडा आणि VPN च्या अंतिम पत्त्याला VM चा सार्वजनिक IPv4 किंवा DNS नाव व पोर्ट `51820` द्या. VPN चा अंतिम पत्ता म्हणजे वेब UI चा लूपबॅक पत्ता किंवा पोर्ट `51821` नव्हे.

प्रत्येक उपकरणासाठी एक क्लायंट तयार करून त्याची WireGuard `.conf` डाउनलोड करा. तुमच्या Mobile SSH बिल्डमध्ये असेल तर **VPN → WireGuard** उघडा, प्रोफाइल जोडा, फाइल आयात करून जतन करा. सध्याचे Android व iOS स्रोत फाइल आयात समर्थित करतात; स्थापित बिल्ड तपासा. सुसंगत Android बिल्डवर VPN Setup पहिला क्लायंट थेट आयात करते. त्याच्या पानावर खाजगी SSH टनेलमधून **क्लायंट जोडा**, **क्लायंट रद्द करा**, **क्लायंट/QR निर्यात करा** आणि **प्रशासन उघडा** मिळतात. यावरून जुन्या प्लगइनच्या किंवा समतुल्य iOS स्वयंचलनाच्या या क्षमता सिद्ध होत नाहीत. संरचना फाइल आणि QR कोडमध्ये खाजगी कळा असतात; ते खाजगी ठेवा.

## VPN तपासा आणि अडचणी सोडवा

प्रोफाइल सुरू करा आणि प्रणालीची VPN विनंती मंजूर करा. अलीकडचा पीअर हँडशेक आणि वाढते वाहतूक काउंटर तपासा, मग DNS व अपेक्षित इंटरनेट किंवा खाजगी नेटवर्क मार्ग तपासा. आयात केलेले प्रोफाइल किंवा चालू कंटेनर एवढ्यानेच VPN चालतो हे सिद्ध होत नाही.

- **VM निर्मिती नाकारली:** बिलिंग, कोटा, प्रदेशातील क्षमता, ओळखपत्रांची मुदत आणि नेमक्या IAM परवानग्या तपासा. Google Cloud फायरवॉल लिहिण्यासाठी Compute Network Admin पलीकडील परवानग्या हव्यात; संस्थेने बंधनकारक केलेल्या OS Login साठी मंजूर कन्सोल मांडणी वापरा.
- **SSH वेळ संपली:** सार्वजनिक पत्ता, सबनेट मार्ग, TCP 22 नियम आणि फोनचा सध्याचा स्रोत IP तपासा. प्रमाणीकरण अयशस्वी झाल्यास सहसा योग्य इमेज वापरकर्तानाव आणि SSH कळ लागते.
- **प्रशासक UI उपलब्ध नाही:** SSH फॉरवर्डिंग जोडलेले ठेवा, कंटेनर स्थिती व लूपबॅक पोर्ट मॅपिंग तपासा आणि HTTP केवळ टनेलसाठी सक्षम असल्याची खात्री करा.
- **WireGuard हँडशेक नाही:** क्लायंटचा अंतिम पत्ता, दोन्ही फायरवॉल स्तरांतील UDP 51820, क्लायंट कळा आणि सर्व्हर ऐकत आहे का ते तपासा.
- **हँडशेक असून वाहतूक नाही:** फॉरवर्डिंग/NAT, DNS, मार्गांचा संघर्ष आणि `AllowedIPs` तपासा. पूर्ण-टनेल IPv4 साठी `0.0.0.0/0` वापरतात; IPv6 वेगळा तपासा. अपस्ट्रीम IPv6 नसलेला VM IPv6 इंटरनेट बाहेर जाण्याचा मार्ग देऊ शकत नाही; केवळ IPv4 मार्गांमुळे IPv6 VPN बाहेर राहू शकतो.

## प्लगइन आणि VPN सर्व्हर अद्ययावत करा

**प्लगइन** मध्ये त्याच कॅटलॉगमधील नवीन सुसंगत आवृत्तीसाठी उपलब्ध **अद्ययावत करा** वापरा. नव्याने मागितलेल्या क्षमता तपासा. सेटिंग्ज, ओळखपत्रे व तैनाती नोंदी टिकतात; अपूर्ण प्रक्रिया ती सुरू करणाऱ्या प्लगइन आवृत्तीवरच चालते. केवळ प्लगइन अद्यतनाने सर्व्हरचा wg-easy कंटेनर अद्ययावत होत नाही.

प्लगइन ब्रिज 1.4.0 किंवा नवीनवर **सर्व्हर तपासा** चालू wg-easy आवृत्ती सांगते आणि **WireGuard अद्ययावत करा** प्लगइनची निश्चित आवृत्ती देते. पडद्यावर अद्यतन मंजूर करा. सेवा बदलण्याआधी इमेज डाउनलोड होते आणि सर्व्हर कळा, क्लायंट व स्थानिक प्रोफाइल टिकतात. हा फोन तो VPN वापरत असल्यास ॲप अद्यतनाआधी त्याची जोडणी तोडते; नंतर पुन्हा जोडा. हे व्यवस्थापित कंटेनर अद्ययावत करते, होस्ट ऑपरेटिंग प्रणाली नाही.

अयशस्वी अद्यतन इमेज डाउनलोड अपयश, यशस्वी पूर्वस्थिती आणि VPN बंद ठेवणारे अयशस्वी पूर्वस्थितीकरण वेगवेगळे दाखवते. सेवा परत आली असे गृहीत न धरता दिलेली पुनर्प्राप्ती तपासणी किंवा पुनर्प्रयत्न करा. हाताने केलेल्या स्थापनेला स्वतःचा तपासलेला इमेज पिन बदल आणि बॅकअप लागतो; वरील नवीन स्थापनेची पद्धत स्थलांतर मार्गदर्शक नाही.

## क्लायंट काढा आणि क्लाउड शुल्क थांबवा

स्थानिक प्रोफाइल टाकण्यापूर्वी wg-easy मधील क्लायंट रद्द करा. Mobile SSH मधील प्रोफाइल हटवल्याने सर्व्हरची पीअर कळ रद्द होत नाही. VPN कंटेनर किंवा कायमस्वरूपी डेटा काढण्यापूर्वी आवश्यक संरचनेचा सुरक्षित बॅकअप घ्या.

API ने केलेल्या तैनातीसाठी **तैनाती हटवा** तिच्या मालकीच्या क्लाउड संसाधनांचे पुनरावलोकन करून प्रदात्याच्या API मधून ती हटवते, SSH उपलब्ध नसले तरीही. हटवणे थांबले किंवा अयशस्वी झाले तर उरलेली दर्शवलेली संसाधने तपासा; साफसफाई पुढे चालू करा किंवा कन्सोल पाहा. प्लगइन व्यवस्थापित तैनातीत, विशेषतः तिच्या स्वतंत्र Azure संसाधन गटात, असंबंधित संसाधने ठेवू नका.

कन्सोलमध्ये तयार किंवा विद्यमान सर्व्हरवर प्लगइनची हटवण्याची कृती त्याची व्यवस्थापित VPN स्थापना काढते; तुमचा VM किंवा सार्वजनिक IP हटवत **नाही**. गरज संपल्यावर प्रदात्याच्या कन्सोलमध्ये ते हटवा, मग राहिलेल्या डिस्क, स्नॅपशॉट, पत्ते आणि नेटवर्क संसाधने तपासा. पुनर्प्राप्तीदरम्यान खाते किंवा स्थान बदलले असल्यास जुने खाते व स्थानही तपासा, त्यात जुना Scaleway प्रकल्प किंवा Oracle Cloud कंपार्टमेंटही येतो.

**कार्यप्रवाह थांबवा** प्रक्रिया थांबवते; संसाधने हटवत नाही. ब्रिज 1.5.0 किंवा नवीनवर **यादीतून काढा** फक्त नोंद विसरण्यास पात्र असून अपूर्ण प्रक्रिया किंवा उरलेली व्यवस्थापित संसाधने नसल्याचे ॲप पडताळू शकते तेव्हाच मिळते. ती स्थानिक इतिहास काढते, क्लाउड संसाधने नाही. VM थांबवणे किंवा प्लगइन काढणे यानेही शुल्क थांबण्याची हमी नाही. हटवल्याची खात्री होईपर्यंत संसाधन ID जपा.
