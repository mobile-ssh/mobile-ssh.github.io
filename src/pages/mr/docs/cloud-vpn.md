# क्लाउड VM आणि wg-easy

स्वतःच्या क्लाउड खात्यात Linux VM तयार करा, Mobile SSH ने जोडा आणि WireGuard VPN चालवण्यासाठी wg-easy स्थापित करा. संसाधने तयार करणे आणि स्थापना वेगळी ठेवल्यास त्याच VM वर दुसरी सेवा वापरता येते किंवा आधीपासून असलेल्या सर्व्हरवर VPN बसवता येतो.

**उपलब्धता — 8 नोव्हेंबर 2026:** खाली वर्णिलेल्या अपेक्षित कार्यप्रवाहात VM तयार करण्यासाठी स्वतंत्र प्लगइन आहेत. तपासलेली स्थानिक Android **VPN Setup** अंमलबजावणी संसाधननिर्मिती, स्थापना आणि क्लायंट आयात एकत्र करते; तिचे प्लगइन/कॅटलॉग बदल अप्रकाशित आहेत आणि प्रत्यक्ष क्लाउड तैनाती अजून तपासलेल्या नाहीत. स्वतंत्र AWS, Google Cloud आणि Azure नोंदी सध्या केवळ मॅनिफेस्ट/सेटिंगचे अपूर्ण सांगाडे आहेत; त्यांच्या VM यादी दाखवण्याच्या आणि नियंत्रणाच्या कृती अंमलात आलेल्या नाहीत आणि त्या VM तयारही करत नाहीत. तुमच्या कॅटलॉगमध्ये निर्मितीचा कार्यप्रवाह नसल्यास खालील कन्सोल आणि हाताने स्थापनेच्या सूचना वापरा. नव्या नेटिव्ह कार्यप्रवाहासाठी सुसंगत Android बिल्ड आवश्यक आहे; समतुल्य iOS स्वयंचलन स्थापित झालेले नाही.

## स्वतंत्र जबाबदाऱ्या असलेले दोन प्लगइन

- **क्लाउड प्रोव्हिजनर:** प्रदात्याच्या API ने VM, सार्वजनिक पत्ता आणि आवश्यक नेटवर्क संसाधने तयार करतो, मग SSH जोडणी जतन करतो. पुढील व्यवस्थापन किंवा हटवण्यासाठी क्लाउड संसाधनांचे ID राखतो.
- **wg-easy इंस्टॉलर:** निवडलेल्या जतन केलेल्या सर्व्हरशी SSH ने जोडतो, VPN सेवा स्थापित करतो आणि क्लायंट संरचना तयार करण्यास मदत करतो. त्याला सर्व्हर प्रवेश आणि प्रशासकीय अधिकार हवेत; क्लाउड API ओळखपत्रे नकोत. हाताने तयार केलेला VM सुद्धा वापरता येतो.

हस्तांतरणात जतन केलेल्या सर्व्हरचा संदर्भ, सार्वजनिक पत्ता, SSH पोर्ट, वापरकर्तानाव, SSH ओळखपत्र संदर्भ आणि तैनाती/संसाधन ID असावेत. क्लाउड गुपिते आणि SSH खाजगी कळा प्लगइनच्या आउटपुटमध्ये किंवा VM वर कॉपी होऊ नयेत. VPN काढणे आणि क्लाउड VM हटवणे या स्वतंत्र कृती आहेत.

## खाते आणि सर्व्हर सेटिंग तयार करा

1. क्लाउड खाते व बिलिंग सक्रिय करा, प्रदेश निवडा आणि VM, डिस्क व सार्वजनिक IP कोटा तपासा. प्रदात्याचे सध्याचे VM, IPv4, साठवण आणि वाहतुकीचे शुल्क पाहा; मोफत स्तर उपलब्ध असेल असे गृहीत धरू नका.
2. या मार्गदर्शकासाठी **amd64 किंवा arm64** वरील किमान **1 GB RAM आणि 20 GB डिस्क** असलेला स्वतंत्र **Ubuntu 24.04 LTS** VM निवडा. हे या मांडणीचे आधारभूत पर्याय आहेत, wg-easy ची सार्वत्रिक किमान अट नाही. root किंवा sudo प्रवेश असलेले लॉगिन वापरा; विनाहस्तक्षेप स्थापनेसाठी संवाद न मागता अधिकारवाढ होणे आवश्यक आहे.
3. SSH कळ निवडा किंवा तयार करा; खाजगी कळ Mobile SSH मध्येच ठेवा. क्लाउडवर फक्त सार्वजनिक कळ अपलोड करा. Lightsail च्या आयात मार्गाला RSA SSH कळ लागते. इतर प्रदाते व इमेज कोणत्या कळा स्वीकारतात ते वेगळे असू शकते. सध्याचा iOS SSH क्लायंट RSA खाजगी कळांऐवजी Ed25519/ECDSA समर्थित करतो. iOS वर Lightsail साठी आधी प्रदात्याच्या ब्राउझर SSH कन्सोलमधून ॲपला समर्थित सार्वजनिक कळ `authorized_keys` मध्ये जोडा, मग त्या कळीने जोडा.
4. **सार्वजनिक IPv4** निवडा; प्रदाता देत असल्यास राखीव/स्थिर पत्ता प्राधान्याने वापरा. खाजगी पत्ता, केवळ IPv6 असलेला इंस्टन्स किंवा फक्त बाहेर जाणाऱ्या वाहतुकीचा NAT गेटवे या मार्गदर्शकाची अंतिम पत्त्याची अट पूर्ण करत नाही.
5. SSH स्रोत CIDR स्पष्टपणे सेट करा, उदा. सध्याच्या सार्वजनिक IPv4 पुढे `/32`. प्लगइनचा मूळ पर्याय प्रवेश मर्यादित करतो असे समजू नका. मोबाइल डेटा आणि Wi-Fi बदलल्यास क्लाउड कन्सोलमधून नियम बदलावा लागू शकतो.

क्लाउड API ओळखपत्रे संसाधन व्यवस्थापनासाठी, तर SSH कळा सर्व्हर लॉगिनसाठी परवानगी देतात. ती वेगळी ओळखपत्रे आहेत. API गुपिते फक्त प्रदात्याच्या सुरक्षित ओळखपत्र फॉर्ममध्ये भरा; आवाजातील सूचना, टर्मिनल कमांड किंवा स्रोत फाइलमध्ये कधीही नकोत. स्थानिक Android कार्यप्रवाहात नेटिव्ह कोड प्रदाता प्रमाणीकरण आणि कूटबद्ध ओळखपत्र साठवण सांभाळतो; गरजेनुसार ओळखपत्रे त्यांच्या प्रदात्याकडे जातात, VM किंवा प्लगइन वर्करकडे नाहीत. ऑफलाइन ध्वनी मॉडेलमुळे क्लाउड API कॉल, डाउनलोड किंवा SSH इंटरनेटशिवाय चालत नाहीत.

## क्लाउड निवडा आणि सार्वजनिक पत्ता मिळवा

**कन्सोल मांडणीसाठी** प्रदात्याकडे स्वतः साइन इन करा; Mobile SSH ला त्याची API ओळखपत्रे लागत नाहीत. भविष्यातील **प्लगइनद्वारे संसाधननिर्मितीसाठी** खाली दाखवलेली ओळखपत्रे आवश्यक निर्मिती, वाचन, नेटवर्क आणि हटवण्याच्या परवानग्यांसह तयार ठेवा. शक्य तिथे प्रवेश स्वतंत्र प्रकल्प किंवा तैनातीपुरता मर्यादित करा. दोन्ही पद्धतींना खात्याची धोरणे लागू राहतात.

तुमची SSH सार्वजनिक कळ वापरून निवडलेला Ubuntu VM तयार करा आणि पुढील विभागातील SSH नियम लावा. दुव्यांमध्ये प्रदात्यानुसार पत्ता आणि प्रमाणीकरणाचे टप्पे आहेत.

संस्थेने सेवा-खात्याच्या कळा, बाह्य IP किंवा तुमची SSH प्रमाणीकरण पद्धत प्रतिबंधित केली असल्यास प्रशासकाने मंजूर केलेली संरचना मिळवा. कन्सोल मांडणीमुळे ते निर्बंध चुकवता येत नाहीत.

## संसाधने तयार करा आणि SSH जोडणी जतन करा

अपेक्षित स्वतंत्र कार्यप्रवाहात **प्लगइन** उघडा, विश्वसनीय कॅटलॉगमधून प्रदात्याचा प्रोव्हिजनिंग प्लगइन स्थापित करा, खाते व प्रदेश निवडा आणि VM आकार, इमेज, सार्वजनिक पत्ता व SSH कळ ठरवा. निर्मितीची पुष्टी करण्यापूर्वी संसाधने व खर्च पाहा. निर्मिती कृती नसलेला व्यवस्थापनापुरता प्लगइन हा टप्पा करू शकत नाही; त्याऐवजी प्रदात्याचा कन्सोल वापरा.

प्रदात्याने VM चालू असल्याचे दाखवेपर्यंत आणि SSH उपलब्ध होईपर्यंत थांबा. VM, डिस्क, पत्ता आणि फायरवॉल संसाधनांचे ID ठेवा. विनंतीची वेळ संपल्यास पुन्हा निर्मिती करण्यापूर्वी चालू कृती तपासा किंवा पुढे सुरू करा, म्हणजे दुसरा शुल्क आकारला जाणारा VM तयार होणार नाही.

मिळालेली जोडणी Mobile SSH मध्ये जतन करा किंवा **सर्व्हर** अंतर्गत हाताने जोडा: सार्वजनिक IPv4, SSH पोर्ट `22`, इमेजचे वापरकर्तानाव आणि जुळणारी खाजगी-कळ ओळखपत्रे. जोडण्यापूर्वी प्रदात्याच्या विश्वसनीय कन्सोलमधून SSH होस्ट-कळ फिंगरप्रिंटची तुलना करा. ओळख तपासणी व जतन केलेल्या ओळखपत्रांसाठी [सुरुवात](../getting-started/) पाहा.

## नेटवर्कचे दोन्ही स्तर सेट करा

सार्वजनिक पत्त्याला मार्ग, क्लाउड फायरवॉल परवानगी, गेस्ट फायरवॉल परवानगी आणि ऐकणारी सेवा आवश्यक आहे. प्रदात्याच्या फायरवॉल/सुरक्षा गटात हे नियम वापरा; आवश्यक विद्यमान गेस्ट नियम राखा.

- **TCP 22:** SSH साठी निवडलेल्या व्यवस्थापन CIDR मधून प्रवेश द्या. संसाधननिर्मितीच्या वेळी सेट करा.
- **UDP 51820:** VPN वापरणाऱ्या नेटवर्कना प्रवेश द्या. फिरत्या क्लायंटसाठी हे `0.0.0.0/0` असू शकते. WireGuard मांडताना क्लाउड प्रोव्हिजनर किंवा कन्सोलमधून जोडा.
- **TCP 51821:** सार्वजनिकरीत्या बंद ठेवा. wg-easy प्रशासक UI फक्त सर्व्हर लूपबॅकवर प्रकाशित करा आणि SSH टनेलमधून उघडा.
- **बाहेर जाणारी वाहतूक:** पॅकेज/कंटेनर डाउनलोड, DNS आणि VPN ने वाहून न्यायची इंटरनेट वाहतूक अनुमत करा.

Docker चे [फायरवॉल वर्तन](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations) तपासा: प्रकाशित कंटेनर पोर्ट UFW नियम वगळू शकतात. प्रशासक UI लपवण्यासाठी केवळ UFW वर अवलंबून राहू नका; प्रदात्याच्या फायरवॉल साखळ्या, विशेषतः OCI साठवण/iSCSI नियम, पुसू नका.

## निवडलेल्या VM वर wg-easy स्थापित करा

स्वतंत्र इंस्टॉलरने जतन केलेला SSH सर्व्हर स्वीकारून सर्व्हर बदलांसाठी मंजुरी मागावी. OS, अधिकार, विद्यमान Docker/VPN स्थापना आणि पोर्ट संघर्ष तपासावेत, कायमस्वरूपी डेटा जपावा आणि स्थापित आवृत्ती दाखवावी. त्याला क्लाउड खात्याचे गुपित लागत नाही; क्लाउड फायरवॉल बदलांसाठी प्रोव्हिजनर किंवा कन्सोल वापरा.

जुन्या **WireGuard (wg-easy)** कॅटलॉग प्लगइनला सक्रिय SSH सत्र आणि Docker लागतात. तो नवा स्वयंचलित इंस्टॉलर नाही आणि नेटिव्ह क्लायंट आयातीचे वचन देत नाही. सुसंगत अद्ययावत इंस्टॉलर वापरा किंवा नव्या स्वतंत्र VM वर Mobile SSH च्या टर्मिनलमधून पुढील हाताने करण्याचा मार्ग वापरा.

### SSH मधून हाताने स्थापना

अधिकृत [Ubuntu सूचनांनुसार](https://docs.docker.com/engine/install/ubuntu/) Docker Engine आणि त्याचा Compose प्लगइन स्थापित करा. मग आवृत्तीविशिष्ट अपस्ट्रीम संरचना डाउनलोड करा:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.4.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

सुरू करण्यापूर्वी अधिकार असलेल्या टर्मिनल संपादकातून `/opt/wg-easy/compose.yaml` संपादित करा. `services.wg-easy` मध्ये इमेज बदला, environment विभाग अनकमेंट/सेट करा आणि पोर्ट मॅपिंग पुढील मूल्यांनी बदला. कायमस्वरूपी व्हॉल्यूम, मॉड्यूल माउंट, क्षमता, नेटवर्क आणि sysctls सहित उर्वरित अपस्ट्रीम फाइल तशीच ठेवा:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.4.0@sha256:0e7bc9d34e86ddcaa92bc700d4d7dc9b33291dbc07ac8d13382f7c2095f949ec
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

हा बदलण्यासाठीचा भाग आहे, संपूर्ण Compose फाइल नाही; सेवेच्या आत YAML ची मोकळी जागा जशी हवी तशी राखा. `INSECURE=true` केवळ लूपबॅक SSH टनेलसाठी HTTP परवानगी देते. प्रशासक पोर्ट इंटरनेटवर प्रकाशित करू नका. कंटेनरचा लिसनर आणि होस्टच्या लूपबॅक मॅपिंग वेगळे आहेत. अपस्ट्रीमचे [HTTP संरचना मार्गदर्शन](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) पाहा.

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

कंटेनरमधील `/etc/wireguard` डेटा त्याच्या कायमस्वरूपी व्हॉल्यूममध्ये ठेवा. जुने `PASSWORD`, `PASSWORD_HASH` किंवा `WG_HOST` निर्देश v15 ला लागू करू नका; त्याचा सेटअप विझार्ड वापरा. इमेज मुद्दाम पिन केलेली आहे: अपग्रेडसाठी नव्या आवृत्तीचे पुनरावलोकन करून पिन बदलावा लागतो; फक्त `pull` पुरेसे नाही.

## प्रशासक UI उघडा आणि क्लायंट जोडा

Mobile SSH मध्ये स्थानिक पोर्ट `51821`, दूरस्थ होस्ट `127.0.0.1` आणि दूरस्थ पोर्ट `51821` असलेला [स्थानिक पोर्ट फॉरवर्ड](../port-forwarding/) तयार करा. SSH जोडणी चालू ठेवा आणि त्याच फोनवर `http://127.0.0.1:51821` उघडा. स्थानिक पोर्ट वापरात असल्यास दुसरा निवडा आणि ब्राउझर URL मध्ये तो वापरा.

wg-easy च्या [पहिल्या वापराच्या विझार्डमध्ये](https://wg-easy.github.io/wg-easy/latest/guides/setup/) प्रशासक खाते तयार करा, नवीन स्थापना निवडा आणि VPN च्या अंतिम पत्त्याला VM चा सार्वजनिक IPv4 किंवा DNS नाव व पोर्ट `51820` द्या. VPN चा अंतिम पत्ता म्हणजे वेब UI चा लूपबॅक पत्ता किंवा पोर्ट `51821` नव्हे.

प्रत्येक उपकरणासाठी स्वतंत्र क्लायंट तयार करून त्याची WireGuard `.conf` डाउनलोड करा. तुमच्या Mobile SSH बिल्डमध्ये सुविधा असल्यास **VPN → WireGuard** उघडा, प्रोफाइल जोडा, फाइल आयात करून जतन करा. सध्याचा Android व iOS स्रोत फाइल आयात समर्थित करतो; स्थापित बिल्ड तपासा. स्थानिक Android संयुक्त कार्यप्रवाह थेट आयात करू शकतो; हे जुन्या प्लगइन किंवा iOS स्वयंचलनाबद्दलचे वचन नाही. संरचना फाइल आणि QR कोडमध्ये खाजगी कळा असतात; ते खाजगी ठेवा.

## VPN तपासा आणि अडचणी सोडवा

प्रोफाइल सुरू करा आणि प्रणालीची VPN विनंती मंजूर करा. अलीकडचा पीअर हँडशेक आणि वाढते वाहतूक काउंटर तपासा, मग DNS व अपेक्षित इंटरनेट किंवा खाजगी नेटवर्क मार्ग तपासा. आयात केलेले प्रोफाइल किंवा चालू कंटेनर एवढ्यानेच VPN चालतो हे सिद्ध होत नाही.

- **VM निर्मिती नाकारली:** बिलिंग, कोटा, प्रदेशातील क्षमता, ओळखपत्रांची मुदत आणि नेमक्या IAM परवानग्या तपासा. Google Cloud फायरवॉल लिहिण्यासाठी Network Admin पलीकडील परवानग्या हव्यात.
- **SSH वेळ संपली:** सार्वजनिक पत्ता, सबनेट मार्ग, TCP 22 नियम आणि फोनचा सध्याचा स्रोत IP तपासा. प्रमाणीकरण अयशस्वी झाल्यास सहसा योग्य इमेज वापरकर्तानाव आणि SSH कळ लागते.
- **प्रशासक UI उपलब्ध नाही:** SSH फॉरवर्डिंग जोडलेले ठेवा, कंटेनर स्थिती व लूपबॅक पोर्ट मॅपिंग तपासा आणि HTTP केवळ टनेलसाठी सक्षम असल्याची खात्री करा.
- **WireGuard हँडशेक नाही:** क्लायंटचा अंतिम पत्ता, दोन्ही फायरवॉल स्तरांतील UDP 51820, क्लायंट कळा आणि सर्व्हर ऐकत आहे का ते तपासा.
- **हँडशेक असून वाहतूक नाही:** फॉरवर्डिंग/NAT, DNS, मार्गांचा संघर्ष आणि `AllowedIPs` तपासा. पूर्ण-टनेल IPv4 साठी `0.0.0.0/0` वापरतात; IPv6 वेगळा तपासा. अपस्ट्रीम IPv6 नसलेला VM IPv6 इंटरनेट बाहेर जाण्याचा मार्ग देऊ शकत नाही; केवळ IPv4 मार्गांमुळे IPv6 VPN बाहेर राहू शकतो.

## क्लायंट काढा आणि क्लाउड शुल्क थांबवा

स्थानिक प्रोफाइल टाकण्यापूर्वी wg-easy मधील क्लायंट रद्द करा. Mobile SSH मधील प्रोफाइल हटवल्याने सर्व्हरची पीअर कळ रद्द होत नाही. VPN कंटेनर किंवा कायमस्वरूपी डेटा काढण्यापूर्वी आवश्यक संरचनेचा सुरक्षित बॅकअप घ्या.

नको असलेला VM त्याचा मालकीचा प्रोव्हिजनर किंवा प्रदात्याच्या कन्सोलमधून हटवा; मग उरलेल्या डिस्क, स्नॅपशॉट, राखीव/सार्वजनिक पत्ते आणि नेटवर्क संसाधने तपासा. स्वतंत्र Azure संसाधन गट हटवण्यापूर्वी त्यातील सामग्री तपासा. असंबंधित संसाधने प्लगइन-व्यवस्थापित तैनातीच्या बाहेर ठेवा.

VM थांबवणे, सेटअप काम रद्द करणे किंवा प्लगइन काढणे यामुळे संसाधने हटवली किंवा शुल्क थांबले याची हमी नसते. कन्सोलमधून तयार केलेल्या संसाधनांची स्वच्छता तुमची जबाबदारी आहे; हटवण्याची पुष्टी होईपर्यंत प्रदात्याचे संसाधन ID राखा.
