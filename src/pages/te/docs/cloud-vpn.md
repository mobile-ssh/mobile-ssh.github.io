# క్లౌడ్ VMలు మరియు wg-easy

మీ సొంత క్లౌడ్ ఖాతాలో Linux VM సృష్టించి wg-easyతో WireGuard VPN నడపండి. అనుకూల Android బిల్డ్‌లలో ప్రచురించిన **VPN Setup** ప్లగిన్ ఒక మార్గదర్శక వర్క్‌ఫ్లోలో VM సృష్టించి, wg-easy ఇన్‌స్టాల్ చేసి, క్లయింట్‌ను దిగుమతి చేయగలదు. ప్రొవైడర్ కన్సోల్‌లో VM సృష్టించి Mobile SSH ద్వారా ఇన్‌స్టాల్ చేయవచ్చు లేదా ఇప్పటికే ఉన్న పబ్లిక్ సర్వర్ వాడవచ్చు.

**లభ్యత — నవంబర్ 19, 2026:** **VPN Setup 1.0.7** [డిఫాల్ట్ ప్లగిన్ కేటలాగ్‌లో](https://github.com/mobile-ssh/mobile-ssh-plugins/tree/main/plugins/vpnsetup) ప్రచురించబడింది. ప్రాథమిక సెటప్‌కు ప్లగిన్ బ్రిడ్జ్ **1.3.0**, సర్వర్ అప్‌డేట్‌లకు **1.4.0**, అర్హత ఉన్న పూర్తైన ఎంట్రీలను తొలగించడానికి **1.5.0** అవసరం. లభ్యత మీరు ఇన్‌స్టాల్ చేసిన Android బిల్డ్, విడుదల ట్రాక్‌పై ఆధారపడి ఉంటుంది; ప్లగిన్ ప్రచురణ ఒక నిర్దిష్ట యాప్ విడుదల మీకు అందుబాటులో ఉందని నిర్ధారించదు. సమాన iOS ఆటోమేషన్ నిర్ధారించబడలేదు. ప్లగిన్ లేకపోతే కింద కన్సోల్, మాన్యువల్ సూచనలు వాడండి.

## మార్గదర్శక లేదా మాన్యువల్ వర్క్‌ఫ్లో ఎంచుకోండి

- **క్లౌడ్ APIతో సృష్టించు:** VPN Setup మీ ప్రొవైడర్ ఖాతాతో VM, నెట్‌వర్క్ వనరులను సృష్టించి, SSH కనెక్షన్ సేవ్ చేసి, wg-easy ఇన్‌స్టాల్ చేసి క్లయింట్‌ను దిగుమతి చేస్తుంది. తర్వాత తొలగింపు కోసం వనరుల IDలు, యాజమాన్య రికార్డులు ఉంచుతుంది.
- **క్లౌడ్ కన్సోల్‌లో సృష్టించు లేదా ఉన్న సర్వర్ వాడు:** VM మీరే సృష్టించి దాని పబ్లిక్ IPv4, SSH వినియోగదారు పేరు, కీని VPN Setupకు ఇవ్వండి లేదా కింద మాన్యువల్ ఇన్‌స్టాలేషన్ అనుసరించండి. మీ సర్వర్‌లో ఇన్‌స్టాల్ చేయడానికి ప్లగిన్‌కు క్లౌడ్ API ఆధారాలు అవసరం లేదు.

ప్రచురించిన ప్లగిన్ వనరుల సృష్టి, ఇన్‌స్టాలేషన్‌ను కలుపుతుంది; విడి ప్రొవిజనర్, ఇన్‌స్టాలర్ ప్లగిన్‌లు ఇంకా ప్రణాళికలోని నిర్మాణం. APIతో సృష్టించిన వనరులు, మీరు తీసుకొచ్చే సర్వర్ల తొలగింపు విధానం వేరు; కింద వివరించబడింది. నమోదైన ప్రత్యక్ష Hetzner పరీక్ష Android ఎమ్యులేటర్‌లో సెటప్, VPN ట్రాఫిక్, క్లయింట్ నిర్వహణ, ప్రైవేట్ నిర్వహణ, తొలగింపులో విజయవంతమైంది. ఇది ప్రతి ప్రొవైడర్, ఖాతా విధానం లేదా నిజమైన ఫోన్‌లో ప్రత్యక్ష ఆమోద పరీక్షను నిర్ధారించదు.

## ఖాతా మరియు సర్వర్ సెట్టింగ్‌లను సిద్ధం చేయండి

1. క్లౌడ్ ఖాతా, బిల్లింగ్‌ను ప్రారంభించి, ప్రాంతాన్ని ఎంచుకుని, VM, డిస్క్, పబ్లిక్ IP కోటాలను తనిఖీ చేయండి. VM, IPv4, నిల్వ, ట్రాఫిక్‌కు ప్రొవైడర్ ప్రస్తుత ఛార్జీలను చూడండి; ఉచిత స్థాయి లభిస్తుందని ఊహించవద్దు.
2. ఈ సూచనల కోసం కనీసం **1 GB RAM, 20 GB డిస్క్**, **amd64 లేదా arm64**తో ప్రత్యేక **Ubuntu 24.04 LTS** VM ఎంచుకోండి. ఇవి ఈ సెటప్‌కు ప్రాథమిక ఎంపికలు; wg-easyకి సార్వత్రిక కనీస అవసరాలు కావు. root లేదా sudo ప్రవేశం ఉన్న లాగిన్ వాడండి; పర్యవేక్షణలేని ఇన్‌స్టాలేషన్‌కు ఇంటరాక్టివ్ ఇన్‌పుట్ లేకుండానే హక్కులు పెంచగలగాలి.
3. SSH కీని ఎంచుకోండి లేదా సృష్టించండి; ప్రైవేట్ కీని Mobile SSHలోనే ఉంచండి. పబ్లిక్ కీని మాత్రమే క్లౌడ్‌కు అప్‌లోడ్ చేయండి. Lightsail దిగుమతి మార్గానికి RSA SSH కీ అవసరం. ఇతర ప్రొవైడర్లు, ఇమేజ్‌లు అంగీకరించే కీ రకాలు వేర్వేరుగా ఉంటాయి. ప్రస్తుత iOS SSH క్లయింట్ RSA ప్రైవేట్ కీలకు బదులుగా Ed25519/ECDSAకు మద్దతిస్తుంది. iOSలో Lightsail కోసం ముందుగా ప్రొవైడర్ బ్రౌజర్ SSH కన్సోల్ ద్వారా యాప్ మద్దతిచ్చే పబ్లిక్ కీని `authorized_keys`లో జోడించి, తర్వాత ఆ కీతో కనెక్ట్ అవ్వండి.
4. **పబ్లిక్ IPv4** ఎంచుకోండి; ప్రొవైడర్ అందిస్తే రిజర్వ్ చేసిన/స్థిర చిరునామాను తీసుకోండి. ప్రైవేట్ చిరునామా, IPv6 మాత్రమే ఉన్న ఇన్‌స్టాన్స్, బయటకు వెళ్లే కనెక్షన్‌లకు మాత్రమే ఉన్న NAT గేట్‌వే ఈ సూచనల్లోని ఎండ్‌పాయింట్ అవసరాన్ని తీర్చవు.
5. SSH మూల CIDRను స్పష్టంగా సెట్ చేయండి; ఉదాహరణకు మీ ప్రస్తుత పబ్లిక్ IPv4 తర్వాత `/32`. ప్లగిన్ డిఫాల్ట్ ప్రవేశాన్ని పరిమితం చేస్తుందని అనుకోకండి. మొబైల్ డేటా, Wi-Fi మారినప్పుడు క్లౌడ్ కన్సోల్‌లో ఆ నియమాన్ని మార్చాల్సి రావచ్చు.

మాన్యువల్ మార్గం పై ఆర్కిటెక్చర్లకు మద్దతిస్తుంది. VPN Setup ప్రస్తుతం **amd64/x86-64పై Ubuntu 24.04** ఎంచుకుని, **SSH పోర్ట్ 22**తో కనెక్ట్ అవుతుంది; **Ed25519 లేదా RSA** SSH కీలు అంగీకరిస్తుంది. దాని Lightsail మార్గానికి RSA అవసరం. ECDSA కీలు, ప్రైవేట్ మాత్రమే ఉన్న హోస్ట్‌లు, IPv6 మాత్రమే ఉన్న ఎండ్‌పాయింట్‌లకు ఈ వర్క్‌ఫ్లో మద్దతు లేదు. ఉన్న సర్వర్‌కు పబ్లిక్ IPv4, ఇంటరాక్టివ్ ప్రశ్నలు లేని నిర్వహణ యాక్సెస్ ఉండాలి.

క్లౌడ్ API ఆధారాలు వనరుల నిర్వహణకు, SSH కీలు సర్వర్ లాగిన్‌కు అధికారం ఇస్తాయి. API రహస్యాలను రక్షిత నేటివ్ ఆధారాల ఫారమ్‌లో మాత్రమే ఇవ్వండి; వాయిస్ ప్రాంప్ట్‌లు, టెర్మినల్ కమాండ్‌లు, సోర్స్ ఫైళ్లలో ఇవ్వవద్దు. నేటివ్ కోడ్ ఆమోదించిన ప్రొవైడర్ ఎండ్‌పాయింట్‌లతో ధృవీకరిస్తుంది; రహస్యాలు VM లేదా ప్లగిన్ వర్కర్‌కు వెళ్లవు. గుర్తుంచుకున్న ఆధారాలు Android Keystore ఎన్‌క్రిప్షన్ వాడతాయి; గుర్తుంచుకోవద్దని ఎంచుకుంటే మెమరీలో ఉంటాయి, యాప్ ప్రక్రియ ముగిశాక మళ్లీ ఇవ్వాల్సి రావచ్చు.

వాయిస్ నియంత్రణలు మద్దతున్న రహస్యంకాని ప్రశ్నలకు సమాధానమిచ్చి పురోగతి చెప్పగలవు; ఆధారాల నమోదు, ఆమోదాలకు తెర అవసరం. రక్షిత ఆధారాల ఫారమ్‌ల వద్ద మైక్రోఫోన్ రికార్డింగ్ పాజ్ అవుతుంది; తిరిగి ప్రారంభించడానికి స్పష్టమైన చర్య అవసరం. వాయిస్ సెటప్‌కు దాని సమ్మతి, డౌన్‌లోడ్ చేసిన స్థానిక మోడల్, మైక్రోఫోన్ అనుమతి అవసరం. ఆఫ్‌లైన్ వాయిస్ మోడల్ వల్ల క్లౌడ్ API కాల్‌లు, డౌన్‌లోడ్‌లు, SSH ఇంటర్నెట్ లేకుండా పనిచేయవు.

## క్లౌడ్ ఎంచుకుని పబ్లిక్ చిరునామా పొందండి

**కన్సోల్ సెటప్** కోసం ప్రొవైడర్‌లో మీరే సైన్ ఇన్ అవ్వండి; Mobile SSHకు దాని API ఆధారాలు అవసరం లేదు. **VPN Setup API ప్రొవిజనింగ్** కోసం కింద ఆధారాలను అవసరమైన సృష్టి, చదవడం, నెట్‌వర్క్, తొలగింపు అనుమతులతో సిద్ధం చేయండి. ప్లగిన్ ఈ పట్టికలోని పది ప్రొవైడర్లను అమలు చేస్తుంది; AWS EC2 ప్రత్యేకంగా కన్సోల్-మాత్రమే ఎంపిక. మద్దతున్నచోట యాక్సెస్‌ను ప్రత్యేక ప్రాజెక్టు లేదా డిప్లాయ్‌మెంట్‌కు పరిమితం చేయండి. ఖాతా విధానాలు రెండు పద్ధతులకు వర్తిస్తాయి.

మీ SSH పబ్లిక్ కీతో ఎంచుకున్న Ubuntu VM సృష్టించి, తర్వాతి విభాగంలోని SSH నియమాన్ని అమలు చేయండి. లింకులు ప్రతి ప్రొవైడర్ చిరునామా, ధృవీకరణ దశలను వివరిస్తాయి.

## VM సృష్టించి SSH కనెక్షన్‌ను సేవ్ చేయండి

**ప్లగిన్‌లు** తెరిచి డిఫాల్ట్ కేటలాగ్ నుంచి **VPN Setup** ఇన్‌స్టాల్ చేసి దాని ప్రత్యేక పేజీ తెరవండి. **VPN సెటప్ చేయండి**, ప్రొవైడర్, తర్వాత **క్లౌడ్ APIతో సృష్టించు** లేదా **క్లౌడ్ కన్సోల్‌లో సృష్టించు** ఎంచుకోండి. ముందే సర్వర్ ఉంటే ఉన్న పబ్లిక్ సర్వర్ ఎంపిక తీసుకోండి. నేటివ్ ఫారమ్‌లో ఆధారాలు ఇచ్చి, SSH కీ ఎంచుకోండి లేదా సృష్టించండి; ప్రదేశం, పరిమాణం, ఇమేజ్, SSH మూల CIDR పరిశీలించండి. ఖాతా ఆధారిత ఎంపికలు, ముందస్తు తనిఖీలు మద్దతున్న ఆఫర్‌లను ఎంచుకోవడంలో సహాయపడతాయి; సామర్థ్యాన్ని రిజర్వ్ చేయవు లేదా కోటాకు హామీ ఇవ్వవు. ప్రొవైడర్ ప్రస్తుత ధరలు చూసి తెరపై సృష్టిని ఆమోదించండి.

VM, SSH సిద్ధమయ్యేవరకు అదే చర్యను అనుసరించండి. అభ్యర్థన సమయం ముగిసినా లేదా Android నేపథ్య పనిని పాజ్ చేసినా మరో బిల్లు వచ్చే VM సృష్టించకుండా అదే చర్యను కొనసాగించండి లేదా సమీక్షించండి. సృష్టి ప్రతిస్పందన పోతే క్లౌడ్‌లో వెతకడం లేదా కన్సోల్ పరిశీలించడం అవసరం కావచ్చు. VM, డిస్క్, చిరునామా, ఫైర్‌వాల్ వనరుల IDలు ఉంచండి; ఆగిన వర్క్‌ఫ్లో కూడా వనరులను సృష్టించి ఉండవచ్చు.

VPN Setup SSH హోస్ట్ కీ ఆమోదం అడిగి, కనెక్షన్ సేవ్ చేసి, wg-easy ఇన్‌స్టాల్ చేసి తొలి క్లయింట్‌ను దిగుమతి చేస్తుంది. ఫింగర్‌ప్రింట్‌ను ప్రొవైడర్ విశ్వసనీయ కన్సోల్‌తో పోల్చండి. మాన్యువల్ సెటప్‌లో **సర్వర్లు** కింద పబ్లిక్ IPv4, SSH పోర్ట్ `22`, ఇమేజ్ వినియోగదారు పేరు, సరిపడే ప్రైవేట్ కీతో సర్వర్ జోడించండి. ఆటోమేటిక్ Google Cloud, Azure అడాప్టర్లు `ubuntu` వాడతాయి; కన్సోల్ గైడ్‌లు అక్కడ అమర్చిన వినియోగదారు పేర్లు వాడతాయి. గుర్తింపు తనిఖీలు, సేవ్ చేసిన ఆధారాలకు [ప్రారంభించడం](../getting-started/) చూడండి.

## రెండు నెట్‌వర్క్ స్థాయిలను అమర్చండి

పబ్లిక్ చిరునామాకు రూట్, క్లౌడ్ ఫైర్‌వాల్ అనుమతి, గెస్ట్ ఫైర్‌వాల్ అనుమతి, కనెక్షన్లను స్వీకరించే సేవ అవసరం. ప్రొవైడర్ ఫైర్‌వాల్/security groupలో ఈ నియమాలు వాడండి; అవసరమైన ఇప్పటికే ఉన్న గెస్ట్ నియమాలను ఉంచండి.

- **TCP 22:** SSH కోసం ఎంచుకున్న నిర్వహణ CIDR నుంచి అనుమతించండి. VM సృష్టించేటప్పుడే అమర్చండి.
- **UDP 51820:** VPN వాడే నెట్‌వర్క్‌ల నుంచి అనుమతించండి. మారే నెట్‌వర్క్‌లపై ఉన్న క్లయింట్లకు ఇది `0.0.0.0/0` కావచ్చు. APIతో సృష్టించిన డిప్లాయ్‌మెంట్‌లకు VPN Setup దీన్ని అమరుస్తుంది; మీరు తీసుకొచ్చే సర్వర్‌కు క్లౌడ్ కన్సోల్ వాడండి.
- **TCP 51821:** పబ్లిక్‌గా మూసి ఉంచండి. wg-easy నిర్వాహక UIని సర్వర్ loopbackపై మాత్రమే అందించి, SSH టన్నెల్ ద్వారా చేరుకోండి.
- **బయటకు వెళ్లే ట్రాఫిక్:** ప్యాకేజ్/కంటైనర్ డౌన్‌లోడ్‌లు, DNS, VPN తీసుకెళ్లాల్సిన ఇంటర్నెట్ ట్రాఫిక్‌ను అనుమతించండి.

Docker [ఫైర్‌వాల్ ప్రవర్తనను](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations) చూడండి: బయటకు అందించిన కంటైనర్ పోర్టులు UFW నియమాలను దాటవచ్చు. నిర్వాహక UIని దాచడానికి UFWపైనే ఆధారపడవద్దు. ప్రొవైడర్ ఫైర్‌వాల్ గొలుసులను, ముఖ్యంగా OCI నిల్వ/iSCSI నియమాలను తొలగించవద్దు.

## ఎంచుకున్న VMలో wg-easy ఇన్‌స్టాల్ చేయండి

ఆమోదం తర్వాత VPN Setup SSH ద్వారా డైజెస్ట్‌తో స్థిరపరిచిన wg-easy విడుదలను ఇన్‌స్టాల్ చేసి, Ubuntu 24.04లో అవసరమైతే Docker ఇన్‌స్టాల్ చేసి, తొలి క్లయింట్‌ను సృష్టిస్తుంది. నిర్వహణ ఇంటర్‌ఫేస్ సర్వర్ లూప్‌బ్యాక్‌పై ఉంటుంది, ప్రొవైడర్ ఫైర్‌వాల్ చైన్‌లు అలాగే ఉంటాయి. కన్సోల్‌లో సృష్టించిన లేదా ఉన్న సర్వర్‌కు క్లౌడ్ ఫైర్‌వాల్ మీరే అమర్చండి; ఇన్‌స్టాలర్‌కు SSH యాక్సెస్, నిర్వహణ హక్కులు అవసరం, క్లౌడ్ API రహస్యం కాదు. సంబంధం లేని VPN ఇన్‌స్టాలేషన్‌ను స్వీకరిస్తుందని ఊహించకుండా తాజా ప్రత్యేక సర్వర్ వాడండి.

పాత **WireGuard (wg-easy)** కేటలాగ్ ప్లగిన్‌కు క్రియాశీల SSH సెషన్, Docker అవసరం. ఇది **VPN Setup** నుంచి వేరు, నేటివ్ క్లయింట్ దిగుమతికి హామీ ఇవ్వదు. అనుకూల Android బిల్డ్‌లో VPN Setup వాడండి లేదా తాజా ప్రత్యేక VMలో Mobile SSH టెర్మినల్ నుంచి కింది మాన్యువల్ మార్గం అనుసరించండి.

### SSH ద్వారా మాన్యువల్ ఇన్‌స్టాలేషన్

అధికారిక [Ubuntu సూచనలతో](https://docs.docker.com/engine/install/ubuntu/) Docker Engine, దాని Compose ప్లగిన్ ఇన్‌స్టాల్ చేయండి. తర్వాత వెర్షన్‌కు చెందిన అసలు ప్రాజెక్టు కాన్ఫిగరేషన్‌ను డౌన్‌లోడ్ చేయండి:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.5.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

ప్రారంభించే ముందు హక్కులున్న టర్మినల్ ఎడిటర్‌తో `/opt/wg-easy/compose.yaml` సవరించండి. `services.wg-easy` కింద ఇమేజ్‌ను మార్చి, environment బ్లాక్‌ను అన్‌కామెంట్ చేసి లేదా సెట్ చేసి, పోర్ట్ మ్యాపింగ్‌లను కింది విలువలతో మార్చండి. అసలు ఫైల్‌లోని మిగతా భాగాలను అలాగే ఉంచండి: శాశ్వత వాల్యూమ్, module mount, capabilities, నెట్‌వర్క్‌లు, sysctls సహా:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.5.0@sha256:071f79a639e9361123a5e57733107320207b844ddbbd92dfa6962f541fe8aac8
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

ఇది మార్చాల్సిన భాగం మాత్రమే; పూర్తి Compose ఫైల్ కాదు. సేవ కింద YAML ఇండెంటేషన్‌ను ఉంచండి. `INSECURE=true` loopback SSH టన్నెల్ కోసం మాత్రమే HTTP అనుమతిస్తుంది. నిర్వాహక పోర్టును ఇంటర్నెట్‌కు అందించవద్దు. కంటైనర్ స్వీకరించే చిరునామా, హోస్ట్ వైపు loopback మ్యాపింగ్ వేర్వేరు. అసలు ప్రాజెక్టు [HTTP కాన్ఫిగరేషన్](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) చూడండి.

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

కంటైనర్ `/etc/wireguard` డేటాను దాని శాశ్వత వాల్యూమ్‌లో ఉంచండి. పాత `PASSWORD`, `PASSWORD_HASH`, `WG_HOST` విధానాలను v15కు వర్తింపజేయవద్దు; దాని సెటప్ విజార్డ్ వాడండి. ఇమేజ్‌ను ఉద్దేశపూర్వకంగా నిర్దిష్ట వెర్షన్‌కు కట్టిపెట్టాం. అప్‌గ్రేడ్‌కు కొత్త వెర్షన్‌ను సమీక్షించి ఆ పిన్‌ను మార్చాలి; `pull` నడిపితే సరిపోదు.

## నిర్వాహక UI తెరిచి క్లయింట్ జోడించండి

Mobile SSHలో స్థానిక పోర్ట్ `51821`, రిమోట్ హోస్ట్ `127.0.0.1`, రిమోట్ పోర్ట్ `51821`తో [స్థానిక పోర్ట్ ఫార్వార్డ్](../port-forwarding/) సృష్టించండి. SSH కనెక్షన్‌ను క్రియాశీలంగా ఉంచి, అదే ఫోన్‌లో `http://127.0.0.1:51821` తెరవండి. స్థానిక పోర్ట్ వాడుకలో ఉంటే, మరో స్థానిక పోర్ట్ ఎంచుకుని బ్రౌజర్ URLలో దానిని వాడండి.

wg-easy [మొదటి ప్రారంభ సెటప్ విజార్డ్‌లో](https://wg-easy.github.io/wg-easy/latest/guides/setup/) నిర్వాహక ఖాతా సృష్టించి, కొత్త ఇన్‌స్టాలేషన్ ఎంచుకుని, VPN ఎండ్‌పాయింట్‌ను VM పబ్లిక్ IPv4 లేదా DNS పేరుతో, పోర్ట్ `51820`గా సెట్ చేయండి. VPN ఎండ్‌పాయింట్ వెబ్ UI loopback చిరునామా లేదా `51821` పోర్ట్ కాదు.

ప్రతి పరికరానికి ఒక క్లయింట్ సృష్టించి దాని WireGuard `.conf` డౌన్‌లోడ్ చేయండి. మీ Mobile SSH బిల్డ్‌లో ఉంటే **VPN → WireGuard** తెరిచి ప్రొఫైల్ జోడించి, ఫైల్ దిగుమతి చేసి సేవ్ చేయండి. ప్రస్తుత Android, iOS సోర్స్ ఫైల్ దిగుమతికి మద్దతిస్తాయి; ఇన్‌స్టాల్ చేసిన బిల్డ్ చూడండి. అనుకూల Android బిల్డ్‌లలో VPN Setup తొలి క్లయింట్‌ను నేరుగా దిగుమతి చేస్తుంది. దాని పేజీలో ప్రైవేట్ SSH టన్నెల్ ద్వారా **క్లయింట్ జోడించు**, **క్లయింట్ రద్దు చేయు**, **క్లయింట్/QR ఎగుమతి**, **నిర్వహణ తెరువు** కూడా ఉన్నాయి. పాత ప్లగిన్ లేదా సమాన iOS ఆటోమేషన్‌కు ఈ సామర్థ్యాలు ఉన్నాయని ఇది నిర్ధారించదు. కాన్ఫిగరేషన్ ఫైళ్లు, QR కోడ్‌లలో ప్రైవేట్ కీలు ఉంటాయి; గోప్యంగా ఉంచండి.

## VPN తనిఖీ చేసి వైఫల్యాలను పరిష్కరించండి

ప్రొఫైల్ ప్రారంభించి, ఆపరేటింగ్ సిస్టమ్ VPN అభ్యర్థనను ఆమోదించండి. ఇటీవలి పీర్ హ్యాండ్‌షేక్, పెరుగుతున్న ట్రాఫిక్ కౌంటర్లను చూసి, తర్వాత DNS, ఉద్దేశించిన ఇంటర్నెట్ లేదా ప్రైవేట్ నెట్‌వర్క్ రూట్లను పరీక్షించండి. ప్రొఫైల్ దిగుమతి కావడం లేదా కంటైనర్ నడవడం ఒక్కటే VPN పనిచేస్తోందని నిరూపించదు.

- **VM సృష్టి తిరస్కరించబడింది:** బిల్లింగ్, కోటా, ప్రాంతీయ సామర్థ్యం, ఆధారాల గడువు, ఖచ్చితమైన IAM అనుమతులను తనిఖీ చేయండి. Google Cloud ఫైర్‌వాల్ మార్పులకు Compute Network Admin కంటే అదనపు అనుమతులు కావాలి; సంస్థ తప్పనిసరి చేసిన OS Loginకు ఆమోదించిన కన్సోల్ సెటప్ అవసరం.
- **SSH సమయం ముగిసింది:** పబ్లిక్ చిరునామా, సబ్‌నెట్ రూటింగ్, TCP 22 నియమాలు, ఫోన్ ప్రస్తుత మూల IPను తనిఖీ చేయండి. ధృవీకరణ వైఫల్యాలకు సాధారణంగా సరైన ఇమేజ్ వినియోగదారు పేరు, SSH కీ అవసరం.
- **నిర్వాహక UI అందుబాటులో లేదు:** SSH ఫార్వార్డింగ్‌ను కనెక్ట్‌గా ఉంచి, కంటైనర్ స్థితి, loopback పోర్ట్ మ్యాపింగ్‌ను తనిఖీ చేసి, టన్నెల్ కోసమే HTTP ప్రారంభించబడిందని నిర్ధారించండి.
- **WireGuard హ్యాండ్‌షేక్ లేదు:** క్లయింట్ ఎండ్‌పాయింట్, రెండు ఫైర్‌వాల్ స్థాయిల్లో UDP 51820, క్లయింట్ కీలు, సర్వర్ కనెక్షన్లను స్వీకరిస్తోందో తనిఖీ చేయండి.
- **హ్యాండ్‌షేక్ ఉంది, ట్రాఫిక్ లేదు:** forwarding/NAT, DNS, రూట్ల అతివ్యాప్తి, `AllowedIPs` పరిశీలించండి. పూర్తి టన్నెల్ IPv4 `0.0.0.0/0` వాడుతుంది; IPv6ను విడిగా పరీక్షించండి. బయటకు వెళ్లే IPv6 లేని VM IPv6 ఇంటర్నెట్ ప్రవేశాన్ని అందించలేదు; IPv4 రూట్లు మాత్రమే ఉంటే IPv6 VPN బయట ఉండవచ్చు.

## ప్లగిన్, VPN సర్వర్‌ను అప్‌డేట్ చేయండి

**ప్లగిన్‌లు**లో అదే కేటలాగ్ నుంచి కొత్త అనుకూల వెర్షన్‌కు అందుబాటులో ఉన్న **అప్‌డేట్** చర్య వాడండి. కొత్తగా అడిగిన సామర్థ్యాలను సమీక్షించండి. సెట్టింగ్‌లు, ఆధారాలు, డిప్లాయ్‌మెంట్ రికార్డులు ఉంటాయి; పూర్తికాని చర్య మొదలైన ప్లగిన్ వెర్షన్‌తోనే కొనసాగుతుంది. ప్లగిన్ అప్‌డేట్ ఒక్కటే సర్వర్ wg-easy కంటైనర్‌ను అప్‌డేట్ చేయదు.

ప్లగిన్ బ్రిడ్జ్ 1.4.0 లేదా కొత్తదానిలో **సర్వర్ తనిఖీ చేయు** నడుస్తున్న wg-easy వెర్షన్‌ను చూపుతుంది; **WireGuard అప్‌డేట్ చేయు** ప్లగిన్ స్థిరపరిచిన విడుదలను అందిస్తుంది. తెరపై అప్‌డేట్ ఆమోదించండి. సేవ మార్చే ముందు ఇమేజ్ డౌన్‌లోడ్ చేసి సర్వర్ కీలు, క్లయింట్లు, స్థానిక ప్రొఫైళ్లను ఉంచుతుంది. ఈ ఫోన్ ఆ VPN వాడుతుంటే అప్‌డేట్‌కు ముందు యాప్ దాన్ని డిస్‌కనెక్ట్ చేస్తుంది; తర్వాత మళ్లీ కనెక్ట్ అవ్వండి. ఇది నిర్వహించే కంటైనర్‌ను అప్‌డేట్ చేస్తుంది, హోస్ట్ ఆపరేటింగ్ సిస్టమ్‌ను కాదు.

విఫల అప్‌డేట్ ఇమేజ్ డౌన్‌లోడ్ వైఫల్యం, విజయవంతంగా పాత స్థితికి తిరగడం, VPN ఆగిపోయేలా మిగిలే విఫల రోల్‌బ్యాక్‌లను వేరుగా చూపుతుంది. సేవ తిరిగొచ్చిందని ఊహించకుండా రికవరీ తనిఖీ లేదా మళ్లీ ప్రయత్నించడం అనుసరించండి. మాన్యువల్ ఇన్‌స్టాలేషన్‌లకు విడిగా సమీక్షించిన ఇమేజ్ పిన్ మార్పు, బ్యాకప్ అవసరం; పై తాజా ఇన్‌స్టాల్ విధానం మైగ్రేషన్ గైడ్ కాదు.

## క్లయింట్లను తొలగించి క్లౌడ్ ఛార్జీలను ఆపండి

స్థానిక ప్రొఫైల్‌ను తీసివేసే ముందు wg-easyలో క్లయింట్ అనుమతిని రద్దు చేయండి. Mobile SSHలో ప్రొఫైల్ తొలగించడం సర్వర్ పీర్ కీని రద్దు చేయదు. VPN కంటైనర్ లేదా దాని శాశ్వత డేటాను తొలగించే ముందు అవసరమైన కాన్ఫిగరేషన్‌ను సురక్షితంగా బ్యాకప్ చేయండి.

APIతో సృష్టించిన డిప్లాయ్‌మెంట్‌కు **డిప్లాయ్‌మెంట్ తొలగించు** దాని యాజమాన్య క్లౌడ్ వనరులను సమీక్షించి ప్రొవైడర్ API ద్వారా తొలగిస్తుంది, SSH అందుబాటులో లేకపోయినా. తొలగింపు పాజ్ అయితే లేదా విఫలమైతే మిగిలినట్టు చూపిన వనరులను తనిఖీ చేయండి; తొలగింపు కొనసాగించండి లేదా కన్సోల్ చూడండి. ప్లగిన్ నిర్వహించే డిప్లాయ్‌మెంట్‌లో, ముఖ్యంగా ప్రత్యేక Azure రిసోర్స్ గ్రూప్‌లో, సంబంధం లేని వనరులను ఉంచవద్దు.

కన్సోల్‌లో సృష్టించిన లేదా ఉన్న సర్వర్‌లో ప్లగిన్ తొలగింపు అది నిర్వహించే VPN ఇన్‌స్టాలేషన్‌ను తీసేస్తుంది; మీ VM లేదా పబ్లిక్ IPను **తొలగించదు**. అవసరం తీరిన తర్వాత ప్రొవైడర్ కన్సోల్‌లో వాటిని తొలగించి, మిగిలిన డిస్క్‌లు, స్నాప్‌షాట్‌లు, చిరునామాలు, నెట్‌వర్క్ వనరులను చూడండి. రికవరీలో ఖాతా లేదా ప్రదేశ సెట్టింగ్‌లు మారితే పాతవీ చూడండి; పాత Scaleway ప్రాజెక్టు లేదా Oracle Cloud కంపార్ట్‌మెంట్‌తో సహా.

**వర్క్‌ఫ్లో ఆపు** చర్యను ఆపుతుంది; వనరులను తొలగించదు. బ్రిడ్జ్ 1.5.0 లేదా కొత్తదానిలో ఎంట్రీని మరచిపోవడానికి అర్హమని, పూర్తికాని చర్యలు లేదా మిగిలిన నిర్వహించే వనరులు లేవని యాప్ నిర్ధారించగలిగితేనే **జాబితా నుంచి తొలగించు** వస్తుంది. ఇది స్థానిక చరిత్రను తొలగిస్తుంది, క్లౌడ్ వనరులను కాదు. VM ఆపడం లేదా ప్లగిన్ అన్‌ఇన్‌స్టాల్ చేయడం వల్ల కూడా ఛార్జీలు ఆగుతాయని హామీ లేదు. తొలగింపు నిర్ధారణ వరకు వనరుల IDలు ఉంచండి.
