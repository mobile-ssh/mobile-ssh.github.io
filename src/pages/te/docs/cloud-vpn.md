# క్లౌడ్ VMలు మరియు wg-easy

మీ సొంత క్లౌడ్ ఖాతాలో Linux VM సృష్టించి, Mobile SSHతో దానికి కనెక్ట్ అవ్వండి. ఆ తర్వాత WireGuard VPN నడపడానికి wg-easy ఇన్‌స్టాల్ చేయండి. వనరుల సృష్టి, ఇన్‌స్టాలేషన్‌ను విడిగా ఉంచితే అదే VMను మరో సేవకు వాడవచ్చు లేదా ఇప్పటికే ఉన్న సర్వర్‌లో VPN ఇన్‌స్టాల్ చేయవచ్చు.

**లభ్యత — 8 నవంబర్ 2026:** కింద వివరించిన ప్రక్రియలో VMలను సృష్టించే ప్రత్యేక ప్లగిన్‌లు ఉద్దేశించిన రూపకల్పన. పరిశీలించిన స్థానిక Android **VPN Setup** అమలు వనరుల సృష్టి, ఇన్‌స్టాలేషన్, క్లయింట్ దిగుమతిని కలిపి చేస్తుంది; దాని ప్లగిన్/కేటలాగ్ మార్పులు ఇంకా ప్రచురించలేదు, నిజమైన క్లౌడ్‌లలో అమలు పరీక్షించలేదు. ప్రత్యేక AWS, Google Cloud, Azure అంశాలు ప్రస్తుతం మానిఫెస్ట్/సెట్టింగ్‌ల ప్రాథమిక రూపాలు మాత్రమే; VMల జాబితా, నియంత్రణ చర్యలు ఇంకా అమలు కాలేదు, అవి VMలను సృష్టించవు. మీ కేటలాగ్‌లో సృష్టించే ప్రక్రియ లేకపోతే కింద ఉన్న కన్సోల్, మాన్యువల్ ఇన్‌స్టాలేషన్ సూచనలను అనుసరించండి. కొత్త నేటివ్ ప్రక్రియకు అనుకూల Android బిల్డ్ అవసరం; దానికి సమానమైన iOS ఆటోమేషన్ నిర్ధారణ కాలేదు.

## వేర్వేరు బాధ్యతలతో రెండు ప్లగిన్‌లు

- **క్లౌడ్ వనరుల సృష్టి ప్లగిన్:** మీ ప్రొవైడర్ APIతో VM, పబ్లిక్ చిరునామా, అవసరమైన నెట్‌వర్క్ వనరులను సృష్టించి, SSH కనెక్షన్‌ను సేవ్ చేస్తుంది. తర్వాత నిర్వహణ లేదా తొలగింపుకు అవసరమైన క్లౌడ్ వనరుల IDలను ఉంచుతుంది.
- **wg-easy ఇన్‌స్టాలర్:** ఎంచుకున్న సేవ్ చేసిన సర్వర్‌కు SSH ద్వారా కనెక్ట్ అయి, VPN సేవను ఇన్‌స్టాల్ చేసి, క్లయింట్ కాన్ఫిగరేషన్ సృష్టించడంలో సహాయపడుతుంది. దీనికి సర్వర్ ప్రవేశం, నిర్వాహక హక్కులు అవసరం; మీ క్లౌడ్ API ఆధారాలు కాదు. మాన్యువల్‌గా సృష్టించిన VMను కూడా ఇక్కడ వాడవచ్చు.

ప్లగిన్‌ల మధ్య ఇచ్చే వివరాల్లో సేవ్ చేసిన సర్వర్ సూచన, పబ్లిక్ చిరునామా, SSH పోర్ట్, వినియోగదారు పేరు, SSH ఆధారాల సూచన, అమలు/వనరుల IDలు ఉండాలి. క్లౌడ్ రహస్యాలు, SSH ప్రైవేట్ కీలను ప్లగిన్ అవుట్‌పుట్‌లోకి లేదా VMపైకి కాపీ చేయకూడదు. VPN తొలగించడం, క్లౌడ్ VM తొలగించడం వేర్వేరు చర్యలు.

## ఖాతా మరియు సర్వర్ సెట్టింగ్‌లను సిద్ధం చేయండి

1. క్లౌడ్ ఖాతా, బిల్లింగ్‌ను ప్రారంభించి, ప్రాంతాన్ని ఎంచుకుని, VM, డిస్క్, పబ్లిక్ IP కోటాలను తనిఖీ చేయండి. VM, IPv4, నిల్వ, ట్రాఫిక్‌కు ప్రొవైడర్ ప్రస్తుత ఛార్జీలను చూడండి; ఉచిత స్థాయి లభిస్తుందని ఊహించవద్దు.
2. ఈ సూచనల కోసం కనీసం **1 GB RAM, 20 GB డిస్క్**, **amd64 లేదా arm64**తో ప్రత్యేక **Ubuntu 24.04 LTS** VM ఎంచుకోండి. ఇవి ఈ సెటప్‌కు ప్రాథమిక ఎంపికలు; wg-easyకి సార్వత్రిక కనీస అవసరాలు కావు. root లేదా sudo ప్రవేశం ఉన్న లాగిన్ వాడండి; పర్యవేక్షణలేని ఇన్‌స్టాలేషన్‌కు ఇంటరాక్టివ్ ఇన్‌పుట్ లేకుండానే హక్కులు పెంచగలగాలి.
3. SSH కీని ఎంచుకోండి లేదా సృష్టించండి; ప్రైవేట్ కీని Mobile SSHలోనే ఉంచండి. పబ్లిక్ కీని మాత్రమే క్లౌడ్‌కు అప్‌లోడ్ చేయండి. Lightsail దిగుమతి మార్గానికి RSA SSH కీ అవసరం. ఇతర ప్రొవైడర్లు, ఇమేజ్‌లు అంగీకరించే కీ రకాలు వేర్వేరుగా ఉంటాయి. ప్రస్తుత iOS SSH క్లయింట్ RSA ప్రైవేట్ కీలకు బదులుగా Ed25519/ECDSAకు మద్దతిస్తుంది. iOSలో Lightsail కోసం ముందుగా ప్రొవైడర్ బ్రౌజర్ SSH కన్సోల్ ద్వారా యాప్ మద్దతిచ్చే పబ్లిక్ కీని `authorized_keys`లో జోడించి, తర్వాత ఆ కీతో కనెక్ట్ అవ్వండి.
4. **పబ్లిక్ IPv4** ఎంచుకోండి; ప్రొవైడర్ అందిస్తే రిజర్వ్ చేసిన/స్థిర చిరునామాను తీసుకోండి. ప్రైవేట్ చిరునామా, IPv6 మాత్రమే ఉన్న ఇన్‌స్టాన్స్, బయటకు వెళ్లే కనెక్షన్‌లకు మాత్రమే ఉన్న NAT గేట్‌వే ఈ సూచనల్లోని ఎండ్‌పాయింట్ అవసరాన్ని తీర్చవు.
5. SSH మూల CIDRను స్పష్టంగా సెట్ చేయండి; ఉదాహరణకు మీ ప్రస్తుత పబ్లిక్ IPv4 తర్వాత `/32`. ప్లగిన్ డిఫాల్ట్ ప్రవేశాన్ని పరిమితం చేస్తుందని అనుకోకండి. మొబైల్ డేటా, Wi-Fi మారినప్పుడు క్లౌడ్ కన్సోల్‌లో ఆ నియమాన్ని మార్చాల్సి రావచ్చు.

క్లౌడ్ API ఆధారాలు వనరుల నిర్వహణకు అనుమతిస్తాయి; SSH కీలు సర్వర్ లాగిన్‌కు అనుమతిస్తాయి. ఇవి వేర్వేరు ఆధారాలు. API రహస్యాలను ప్రొవైడర్ రక్షిత ఆధారాల ఫారమ్‌లో మాత్రమే నమోదు చేయండి; వాయిస్ సూచనలు, టర్మినల్ ఆదేశాలు, సోర్స్ ఫైళ్లలో ఎప్పుడూ పెట్టవద్దు. స్థానిక Android ప్రక్రియలో నేటివ్ కోడ్ ప్రొవైడర్ ధృవీకరణను, ఆధారాల గుప్తీకరించిన నిల్వను నిర్వహిస్తుంది. అవసరమైనప్పుడు ఆధారాలు వాటి ప్రొవైడర్‌కు వెళ్తాయి; VMకు లేదా ప్లగిన్ వర్కర్‌కు కాదు. ఆఫ్‌లైన్ వాయిస్ మోడల్ ఉన్నంత మాత్రాన ఇంటర్నెట్ లేకుండా క్లౌడ్ API కాల్స్, డౌన్‌లోడ్‌లు లేదా SSH పనిచేయవు.

## క్లౌడ్ ఎంచుకుని పబ్లిక్ చిరునామా పొందండి

**కన్సోల్ సెటప్** కోసం ప్రొవైడర్‌లో మీరే సైన్ ఇన్ చేయండి; Mobile SSHకి దాని API ఆధారాలు అవసరం లేదు. భవిష్యత్తులో **ప్లగిన్ ద్వారా వనరుల సృష్టి** కోసం కింద చూపిన ఆధారాలను, అవసరమైన సృష్టి, చదవడం, నెట్‌వర్క్, తొలగింపు అనుమతులతో సిద్ధం చేయండి. మద్దతున్న చోట ప్రత్యేక ప్రాజెక్టు లేదా అమలుకే ప్రవేశాన్ని పరిమితం చేయండి. రెండు పద్ధతులకూ ఖాతా విధానాలు వర్తిస్తాయి.

మీ SSH పబ్లిక్ కీతో ఎంచుకున్న Ubuntu VM సృష్టించి, తర్వాతి విభాగంలోని SSH నియమాన్ని అమలు చేయండి. లింకులు ప్రతి ప్రొవైడర్ చిరునామా, ధృవీకరణ దశలను వివరిస్తాయి.

## VM సృష్టించి SSH కనెక్షన్‌ను సేవ్ చేయండి

ఉద్దేశించిన విడి ప్రక్రియలో **ప్లగిన్‌లు** తెరిచి, విశ్వసనీయ కేటలాగ్ నుంచి ప్రొవైడర్ వనరుల సృష్టి ప్లగిన్ ఇన్‌స్టాల్ చేయండి. ఖాతా, ప్రాంతం, VM పరిమాణం, ఇమేజ్, పబ్లిక్ చిరునామా, SSH కీ ఎంచుకోండి. సృష్టిని నిర్ధారించే ముందు వనరులు, ఖర్చులను సమీక్షించండి. సృష్టించే చర్య లేని నిర్వహణ ప్లగిన్ ఈ దశను చేయలేదు; బదులుగా ప్రొవైడర్ కన్సోల్ వాడండి.

VM నడుస్తోందని ప్రొవైడర్ తెలిపే వరకు, SSH చేరుకోగలిగే వరకు వేచి ఉండండి. VM, డిస్క్, చిరునామా, ఫైర్‌వాల్ వనరుల IDలను ఉంచండి. అభ్యర్థన సమయం ముగిస్తే, మళ్లీ సృష్టించడానికి ప్రయత్నించే ముందు ఇప్పటికే ఉన్న చర్యను పరిశీలించండి లేదా కొనసాగించండి; రెండో చెల్లించాల్సిన VM సృష్టించకుండా జాగ్రత్తపడండి.

వచ్చిన కనెక్షన్‌ను Mobile SSHలో సేవ్ చేయండి లేదా **సర్వర్లు**లో మాన్యువల్‌గా జోడించండి: పబ్లిక్ IPv4, SSH పోర్ట్ `22`, ఇమేజ్ వినియోగదారు పేరు, సరిపోయే ప్రైవేట్ కీ ఆధారం. కనెక్ట్ అయ్యే ముందు ప్రొవైడర్ విశ్వసనీయ కన్సోల్ ద్వారా SSH హోస్ట్ కీ వేలిముద్రను పోల్చండి. గుర్తింపు తనిఖీలు, సేవ్ చేసిన ఆధారాల కోసం [ప్రారంభించడం](../getting-started/) చూడండి.

## రెండు నెట్‌వర్క్ స్థాయిలను అమర్చండి

పబ్లిక్ చిరునామాకు రూట్, క్లౌడ్ ఫైర్‌వాల్ అనుమతి, గెస్ట్ ఫైర్‌వాల్ అనుమతి, కనెక్షన్లను స్వీకరించే సేవ అవసరం. ప్రొవైడర్ ఫైర్‌వాల్/security groupలో ఈ నియమాలు వాడండి; అవసరమైన ఇప్పటికే ఉన్న గెస్ట్ నియమాలను ఉంచండి.

- **TCP 22:** SSH కోసం ఎంచుకున్న నిర్వహణ CIDR నుంచి అనుమతించండి. VM సృష్టించేటప్పుడే అమర్చండి.
- **UDP 51820:** VPN వాడే నెట్‌వర్క్‌ల నుంచి అనుమతించండి. మారే నెట్‌వర్క్‌లపై ఉన్న క్లయింట్లకు ఇది `0.0.0.0/0` కావచ్చు. WireGuard సెటప్ చేసేటప్పుడు క్లౌడ్ ప్లగిన్ లేదా కన్సోల్ ద్వారా జోడించండి.
- **TCP 51821:** పబ్లిక్‌గా మూసి ఉంచండి. wg-easy నిర్వాహక UIని సర్వర్ loopbackపై మాత్రమే అందించి, SSH టన్నెల్ ద్వారా చేరుకోండి.
- **బయటకు వెళ్లే ట్రాఫిక్:** ప్యాకేజ్/కంటైనర్ డౌన్‌లోడ్‌లు, DNS, VPN తీసుకెళ్లాల్సిన ఇంటర్నెట్ ట్రాఫిక్‌ను అనుమతించండి.

Docker [ఫైర్‌వాల్ ప్రవర్తనను](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations) చూడండి: బయటకు అందించిన కంటైనర్ పోర్టులు UFW నియమాలను దాటవచ్చు. నిర్వాహక UIని దాచడానికి UFWపైనే ఆధారపడవద్దు. ప్రొవైడర్ ఫైర్‌వాల్ గొలుసులను, ముఖ్యంగా OCI నిల్వ/iSCSI నియమాలను తొలగించవద్దు.

## ఎంచుకున్న VMలో wg-easy ఇన్‌స్టాల్ చేయండి

ప్రత్యేక ఇన్‌స్టాలర్ సేవ్ చేసిన SSH సర్వర్‌ను స్వీకరించి, సర్వర్ మార్పులకు అనుమతి అడగాలి. OS, హక్కులు, ఇప్పటికే ఉన్న Docker/VPN ఇన్‌స్టాలేషన్, పోర్ట్ ఘర్షణలను తనిఖీ చేయాలి, శాశ్వత డేటాను కాపాడాలి, ఇన్‌స్టాల్ చేసిన వెర్షన్‌ను తెలియజేయాలి. దీనికి క్లౌడ్ ఖాతా రహస్యం అవసరం లేదు; క్లౌడ్ ఫైర్‌వాల్ మార్పులకు వనరుల సృష్టి ప్లగిన్ లేదా కన్సోల్ వాడండి.

పాత **WireGuard (wg-easy)** కేటలాగ్ ప్లగిన్‌కు క్రియాశీల SSH సెషన్, Docker అవసరం. ఇది కొత్త ఆటోమేటిక్ ఇన్‌స్టాలర్ కాదు; నేటివ్ క్లయింట్ దిగుమతిని హామీ ఇవ్వదు. అనుకూల నవీకరించిన ఇన్‌స్టాలర్ వాడండి లేదా కొత్త ప్రత్యేక VMపై Mobile SSH టర్మినల్ నుంచి కింది మాన్యువల్ పద్ధతిని అనుసరించండి.

### SSH ద్వారా మాన్యువల్ ఇన్‌స్టాలేషన్

అధికారిక [Ubuntu సూచనలతో](https://docs.docker.com/engine/install/ubuntu/) Docker Engine, దాని Compose ప్లగిన్ ఇన్‌స్టాల్ చేయండి. తర్వాత వెర్షన్‌కు చెందిన అసలు ప్రాజెక్టు కాన్ఫిగరేషన్‌ను డౌన్‌లోడ్ చేయండి:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.4.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

ప్రారంభించే ముందు హక్కులున్న టర్మినల్ ఎడిటర్‌తో `/opt/wg-easy/compose.yaml` సవరించండి. `services.wg-easy` కింద ఇమేజ్‌ను మార్చి, environment బ్లాక్‌ను అన్‌కామెంట్ చేసి లేదా సెట్ చేసి, పోర్ట్ మ్యాపింగ్‌లను కింది విలువలతో మార్చండి. అసలు ఫైల్‌లోని మిగతా భాగాలను అలాగే ఉంచండి: శాశ్వత వాల్యూమ్, module mount, capabilities, నెట్‌వర్క్‌లు, sysctls సహా:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.4.0@sha256:0e7bc9d34e86ddcaa92bc700d4d7dc9b33291dbc07ac8d13382f7c2095f949ec
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

ఇది మార్చాల్సిన భాగం మాత్రమే; పూర్తి Compose ఫైల్ కాదు. సేవ కింద YAML ఇండెంటేషన్‌ను ఉంచండి. `INSECURE=true` loopback SSH టన్నెల్ కోసం మాత్రమే HTTP అనుమతిస్తుంది. నిర్వాహక పోర్టును ఇంటర్నెట్‌కు అందించవద్దు. కంటైనర్ స్వీకరించే చిరునామా, హోస్ట్ వైపు loopback మ్యాపింగ్ వేర్వేరు. అసలు ప్రాజెక్టు [HTTP కాన్ఫిగరేషన్](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) చూడండి.

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

కంటైనర్ `/etc/wireguard` డేటాను దాని శాశ్వత వాల్యూమ్‌లో ఉంచండి. పాత `PASSWORD`, `PASSWORD_HASH`, `WG_HOST` విధానాలను v15కు వర్తింపజేయవద్దు; దాని సెటప్ విజార్డ్ వాడండి. ఇమేజ్‌ను ఉద్దేశపూర్వకంగా నిర్దిష్ట వెర్షన్‌కు కట్టిపెట్టాం. అప్‌గ్రేడ్‌కు కొత్త వెర్షన్‌ను సమీక్షించి ఆ పిన్‌ను మార్చాలి; `pull` నడిపితే సరిపోదు.

## నిర్వాహక UI తెరిచి క్లయింట్ జోడించండి

Mobile SSHలో స్థానిక పోర్ట్ `51821`, రిమోట్ హోస్ట్ `127.0.0.1`, రిమోట్ పోర్ట్ `51821`తో [స్థానిక పోర్ట్ ఫార్వార్డ్](../port-forwarding/) సృష్టించండి. SSH కనెక్షన్‌ను క్రియాశీలంగా ఉంచి, అదే ఫోన్‌లో `http://127.0.0.1:51821` తెరవండి. స్థానిక పోర్ట్ వాడుకలో ఉంటే, మరో స్థానిక పోర్ట్ ఎంచుకుని బ్రౌజర్ URLలో దానిని వాడండి.

wg-easy [మొదటి ప్రారంభ సెటప్ విజార్డ్‌లో](https://wg-easy.github.io/wg-easy/latest/guides/setup/) నిర్వాహక ఖాతా సృష్టించి, కొత్త ఇన్‌స్టాలేషన్ ఎంచుకుని, VPN ఎండ్‌పాయింట్‌ను VM పబ్లిక్ IPv4 లేదా DNS పేరుతో, పోర్ట్ `51820`గా సెట్ చేయండి. VPN ఎండ్‌పాయింట్ వెబ్ UI loopback చిరునామా లేదా `51821` పోర్ట్ కాదు.

ప్రతి పరికరానికి ఒక క్లయింట్ సృష్టించి, దాని WireGuard `.conf` డౌన్‌లోడ్ చేయండి. మీ Mobile SSH బిల్డ్ అందిస్తే **VPN → WireGuard** తెరిచి, ప్రొఫైల్ జోడించి, ఫైల్ దిగుమతి చేసి సేవ్ చేయండి. ప్రస్తుత Android, iOS సోర్స్‌లో ఫైల్ దిగుమతి ఉంది; మీ ఇన్‌స్టాల్ చేసిన బిల్డ్‌ను తనిఖీ చేయండి. స్థానిక Android కలిపిన ప్రక్రియ నేరుగా దిగుమతి చేయగలదు; కానీ పాత ప్లగిన్ లేదా iOS ఆటోమేషన్ గురించి అది హామీ కాదు. కాన్ఫిగరేషన్ ఫైళ్లు, QR కోడ్‌లలో ప్రైవేట్ కీలు ఉంటాయి; వాటిని గోప్యంగా ఉంచండి.

## VPN తనిఖీ చేసి వైఫల్యాలను పరిష్కరించండి

ప్రొఫైల్ ప్రారంభించి, ఆపరేటింగ్ సిస్టమ్ VPN అభ్యర్థనను ఆమోదించండి. ఇటీవలి పీర్ హ్యాండ్‌షేక్, పెరుగుతున్న ట్రాఫిక్ కౌంటర్లను చూసి, తర్వాత DNS, ఉద్దేశించిన ఇంటర్నెట్ లేదా ప్రైవేట్ నెట్‌వర్క్ రూట్లను పరీక్షించండి. ప్రొఫైల్ దిగుమతి కావడం లేదా కంటైనర్ నడవడం ఒక్కటే VPN పనిచేస్తోందని నిరూపించదు.

- **VM సృష్టి తిరస్కరించబడింది:** బిల్లింగ్, కోటా, ప్రాంతీయ సామర్థ్యం, ఆధారాల గడువు, ఖచ్చితమైన IAM అనుమతులను తనిఖీ చేయండి. Google Cloud ఫైర్‌వాల్ మార్పులకు Network Admin కంటే అదనపు అనుమతులు అవసరం.
- **SSH సమయం ముగిసింది:** పబ్లిక్ చిరునామా, సబ్‌నెట్ రూటింగ్, TCP 22 నియమాలు, ఫోన్ ప్రస్తుత మూల IPను తనిఖీ చేయండి. ధృవీకరణ వైఫల్యాలకు సాధారణంగా సరైన ఇమేజ్ వినియోగదారు పేరు, SSH కీ అవసరం.
- **నిర్వాహక UI అందుబాటులో లేదు:** SSH ఫార్వార్డింగ్‌ను కనెక్ట్‌గా ఉంచి, కంటైనర్ స్థితి, loopback పోర్ట్ మ్యాపింగ్‌ను తనిఖీ చేసి, టన్నెల్ కోసమే HTTP ప్రారంభించబడిందని నిర్ధారించండి.
- **WireGuard హ్యాండ్‌షేక్ లేదు:** క్లయింట్ ఎండ్‌పాయింట్, రెండు ఫైర్‌వాల్ స్థాయిల్లో UDP 51820, క్లయింట్ కీలు, సర్వర్ కనెక్షన్లను స్వీకరిస్తోందో తనిఖీ చేయండి.
- **హ్యాండ్‌షేక్ ఉంది, ట్రాఫిక్ లేదు:** forwarding/NAT, DNS, రూట్ల అతివ్యాప్తి, `AllowedIPs` పరిశీలించండి. పూర్తి టన్నెల్ IPv4 `0.0.0.0/0` వాడుతుంది; IPv6ను విడిగా పరీక్షించండి. బయటకు వెళ్లే IPv6 లేని VM IPv6 ఇంటర్నెట్ ప్రవేశాన్ని అందించలేదు; IPv4 రూట్లు మాత్రమే ఉంటే IPv6 VPN బయట ఉండవచ్చు.

## క్లయింట్లను తొలగించి క్లౌడ్ ఛార్జీలను ఆపండి

స్థానిక ప్రొఫైల్‌ను తీసివేసే ముందు wg-easyలో క్లయింట్ అనుమతిని రద్దు చేయండి. Mobile SSHలో ప్రొఫైల్ తొలగించడం సర్వర్ పీర్ కీని రద్దు చేయదు. VPN కంటైనర్ లేదా దాని శాశ్వత డేటాను తొలగించే ముందు అవసరమైన కాన్ఫిగరేషన్‌ను సురక్షితంగా బ్యాకప్ చేయండి.

ఇక అవసరం లేని VMను దాని నిర్వహణ ప్లగిన్ లేదా ప్రొవైడర్ కన్సోల్ ద్వారా తొలగించి, తర్వాత మిగిలిన డిస్కులు, స్నాప్‌షాట్‌లు, రిజర్వ్/పబ్లిక్ చిరునామాలు, నెట్‌వర్క్ వనరులను తనిఖీ చేయండి. ప్రత్యేక Azure రిసోర్స్ గ్రూప్‌ను తొలగించే ముందు దానిలోని విషయాలను సమీక్షించండి. ప్లగిన్ నిర్వహించే అమలులో సంబంధంలేని వనరులను చేర్చవద్దు.

VM ఆపడం, సెటప్ పనిని రద్దు చేయడం లేదా ప్లగిన్ తొలగించడం వల్ల వనరులు తొలగిపోతాయని, ఛార్జీలు ఆగుతాయని హామీ లేదు. కన్సోల్ ద్వారా సృష్టించిన వనరులను శుభ్రం చేయాల్సిన బాధ్యత మీదే; తొలగింపు నిర్ధారించే వరకు ప్రొవైడర్ వనరుల IDలను ఉంచండి.
