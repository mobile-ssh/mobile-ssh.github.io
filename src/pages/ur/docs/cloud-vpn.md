# کلاؤڈ VMs اور wg-easy

اپنے کلاؤڈ اکاؤنٹ میں Linux VM بنائیں اور wg-easy کے ساتھ WireGuard VPN چلائیں۔ موافق Android بلڈز پر شائع شدہ **VPN Setup** پلگ اِن ایک رہنمائی والے عمل میں VM بنا سکتا، wg-easy نصب کر سکتا اور کلائنٹ درآمد کر سکتا ہے۔ آپ فراہم کنندہ کے کنسول میں VM بنا کر Mobile SSH کے ذریعے تنصیب بھی کر سکتے ہیں، یا موجودہ عوامی سرور استعمال کر سکتے ہیں۔

**دستیابی — 19 نومبر 2026:** **VPN Setup 1.0.7**، [پہلے سے مقرر پلگ اِن کیٹلاگ](https://github.com/mobile-ssh/mobile-ssh-plugins/tree/main/plugins/vpnsetup) میں شائع ہے۔ بنیادی ترتیب کے لیے پلگ اِن برج **1.3.0**، سرور اپ ڈیٹس کے لیے **1.4.0** اور اہل مکمل اندراجات ہٹانے کے لیے **1.5.0** چاہیے۔ دستیابی آپ کے نصب شدہ Android بلڈ اور ریلیز چینل پر منحصر ہے؛ پلگ اِن کی اشاعت یہ ثابت نہیں کرتی کہ مخصوص ایپ ریلیز آپ کو دستیاب ہے۔ مساوی iOS خودکاری کی تصدیق نہیں ہوئی۔ پلگ اِن دستیاب نہ ہو تو نیچے کنسول اور دستی ہدایات استعمال کریں۔

## رہنمائی والا یا دستی طریقہ منتخب کریں

- **کلاؤڈ API سے بنائیں:** VPN Setup آپ کے فراہم کنندہ اکاؤنٹ سے VM اور نیٹ ورک وسائل بناتا، SSH کنکشن محفوظ کرتا، wg-easy نصب کرتا اور کلائنٹ درآمد کرتا ہے۔ بعد میں صفائی کے لیے وسائل کی IDs اور ملکیت کے ریکارڈ رکھتا ہے۔
- **کلاؤڈ کنسول میں بنائیں یا موجودہ سرور استعمال کریں:** VM خود بنائیں، پھر VPN Setup کو اس کا عوامی IPv4، SSH صارف نام اور کلید دیں، یا نیچے دستی تنصیب کریں۔ آپ کے سرور پر تنصیب کے لیے پلگ اِن کو کلاؤڈ API اسناد نہیں چاہییں۔

شائع شدہ پلگ اِن وسائل کی فراہمی اور تنصیب یکجا کرتا ہے؛ الگ فراہم کنندہ اور انسٹالر پلگ اِن ابھی منصوبہ بند ساخت ہیں۔ API سے بنے وسائل اور آپ کے فراہم کردہ سروروں کا حذف کرنے کا طریقہ مختلف ہے، جس کی وضاحت نیچے ہے۔ ریکارڈ شدہ براہِ راست Hetzner ٹیسٹ نے Android ایمولیٹر پر ترتیب، VPN ٹریفک، کلائنٹ انتظام، نجی انتظامی رسائی اور صفائی کامیابی سے جانچی۔ اس سے ہر فراہم کنندہ، اکاؤنٹ پالیسی یا حقیقی فون کے لیے براہِ راست قبولیت ثابت نہیں ہوتی۔

## اکاؤنٹ اور سرور کی ترتیبات تیار کریں

1. کلاؤڈ اکاؤنٹ اور بلنگ فعال کریں، خطہ منتخب کریں، اور VM، ڈسک اور عوامی IP کے کوٹے جانچیں۔ فراہم کنندہ کے موجودہ VM، IPv4، اسٹوریج اور ٹریفک اخراجات دیکھیں؛ مفت درجے کی دستیابی فرض نہیں کی جاتی۔
2. اس گائیڈ کے لیے مخصوص **Ubuntu 24.04 LTS** VM منتخب کریں جس میں کم از کم **1 GB RAM اور 20 GB ڈسک** ہو، اور **amd64 یا arm64** استعمال ہو۔ یہ اس سیٹ اپ کے بنیادی انتخاب ہیں، wg-easy کی ہر جگہ لاگو کم از کم ضروریات نہیں۔ root یا sudo رسائی والا لاگ اِن استعمال کریں؛ بغیر نگرانی تنصیب کے لیے غیر تعاملی اختیارات میں اضافہ درکار ہے۔
3. SSH کلید منتخب یا بنائیں، اور نجی کلید Mobile SSH میں رکھیں۔ کلاؤڈ پر صرف عوامی کلید اپ لوڈ کریں۔ Lightsail کے درآمدی راستے کے لیے RSA SSH کلید ضروری ہے۔ دوسرے فراہم کنندگان اور امیجز کی قبول کردہ کلیدی اقسام اپنی ہوتی ہیں۔ موجودہ iOS SSH کلائنٹ RSA کے بجائے Ed25519/ECDSA نجی کلیدوں کی حمایت کرتا ہے۔ iOS پر Lightsail کے لیے پہلے فراہم کنندہ کے براؤزر SSH کنسول سے ایپ کی معاون عوامی کلید `authorized_keys` میں شامل کریں، پھر اسی کلید سے جڑیں۔
4. **عوامی IPv4** منتخب کریں، اور فراہم کنندہ دے تو ترجیحاً محفوظ شدہ یا مستقل پتہ لیں۔ نجی پتہ، صرف IPv6 والا انسٹنس یا صرف باہر جانے کا NAT گیٹ وے اس گائیڈ کی اینڈپوائنٹ ضرورت پوری نہیں کرتا۔
5. SSH کا ماخذ CIDR واضح طور پر مقرر کریں، مثلاً موجودہ عوامی IPv4 کے بعد `/32`۔ یہ فرض نہ کریں کہ پلگ ان کی طے شدہ قدر رسائی محدود کرتی ہے۔ موبائل ڈیٹا اور Wi-Fi بدلنے پر کلاؤڈ کنسول سے یہ قاعدہ بدلنا پڑ سکتا ہے۔

دستی طریقہ اوپر دی گئی ساختوں کی حمایت کرتا ہے۔ VPN Setup فی الحال **amd64/x86-64 پر Ubuntu 24.04** چنتا، **SSH پورٹ 22** سے جڑتا اور **Ed25519 یا RSA** SSH کلیدیں قبول کرتا ہے؛ Lightsail کے لیے RSA چاہیے۔ اس عمل میں ECDSA کلیدیں، صرف نجی میزبان اور صرف IPv6 اینڈپوائنٹس معاون نہیں۔ موجودہ سرور کے پاس عوامی IPv4 اور بغیر تعاملی سوالات کے انتظامی رسائی ہونی چاہیے۔

کلاؤڈ API اسناد وسائل کے انتظام کی اجازت دیتی ہیں؛ SSH کلیدیں سرور لاگ اِن کی۔ API راز صرف محفوظ مقامی اسناد فارم میں درج کریں، کبھی صوتی پرامپٹس، ٹرمینل احکامات یا سورس فائلوں میں نہیں۔ مقامی کوڈ منظور شدہ فراہم کنندہ اینڈپوائنٹس سے تصدیق کرتا ہے؛ راز VM یا پلگ اِن ورکر کو نہیں جاتے۔ یاد رکھی گئی اسناد Android Keystore سے رمز بند ہوتی ہیں؛ یاد نہ رکھنے پر وہ میموری میں رہتی ہیں اور ایپ کا عمل ختم ہونے کے بعد دوبارہ درج کرنا پڑ سکتی ہیں۔

صوتی کنٹرول معاون غیرخفیہ سوالات کے جواب اور پیش رفت بتا سکتا ہے، مگر اسناد درج کرنے اور منظوریوں کے لیے اسکرین چاہیے۔ محفوظ اسناد فارموں پر مائیکروفون ریکارڈنگ رک جاتی ہے اور اسے دوبارہ جاری کرنے کے لیے واضح کارروائی ضروری ہے۔ صوتی ترتیب کے لیے اختیاری فعال کرنا، ڈاؤن لوڈ شدہ مقامی ماڈل اور مائیکروفون اجازت چاہیے۔ آف لائن صوتی ماڈل کلاؤڈ API کالیں، ڈاؤن لوڈ یا SSH کو انٹرنیٹ کے بغیر نہیں چلاتا۔

## کلاؤڈ منتخب کریں اور عوامی پتہ حاصل کریں

**کنسول ترتیب** کے لیے خود فراہم کنندہ میں سائن اِن کریں؛ Mobile SSH کو اس کی API اسناد نہیں چاہییں۔ **VPN Setup API سے وسائل بنانے** کے لیے نیچے دی گئی اسناد مطلوبہ تخلیق، پڑھنے، نیٹ ورک اور حذف کی اجازتوں کے ساتھ تیار کریں۔ پلگ اِن اس جدول کے دس فراہم کنندگان نافذ کرتا ہے؛ AWS EC2 صرف کنسول کا الگ اختیار ہے۔ جہاں ممکن ہو رسائی الگ پروجیکٹ یا ڈیپلائمنٹ تک محدود کریں۔ اکاؤنٹ پالیسیاں دونوں طریقوں پر لاگو رہتی ہیں۔

منتخب Ubuntu VM اپنی SSH عوامی کلید کے ساتھ بنائیں، اور اگلے حصے کا SSH قاعدہ لگائیں۔ روابط فراہم کنندہ کے مخصوص پتے اور توثیق کے مراحل سمجھاتے ہیں۔

**[AWS EC2](./aws-ec2/) متبادل:** [انٹرنیٹ گیٹ وے اور `0.0.0.0/0` گیٹ وے روٹ](https://docs.aws.amazon.com/vpc/latest/userguide/VPC_Internet_Gateway.html) والے عوامی سب نیٹ میں Ubuntu چلائیں، SSH کلید اور سکیورٹی گروپ چنیں، پھر [Elastic IP](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/working-with-eips.html) منسلک کریں۔ `ubuntu` استعمال کریں۔ VPN Setup کا خودکار AWS اڈاپٹر Lightsail کو استعمال کرتا ہے؛ EC2 کنسول کا راستہ ہے۔ صرف Elastic IP نجی سب نیٹ کو قابلِ رسائی نہیں بناتا۔

اگر ادارہ سروس اکاؤنٹ کلیدیں، بیرونی IPs یا آپ کا منتخب SSH توثیقی طریقہ منع کرتا ہے، تو منتظم سے منظور شدہ ترتیب حاصل کریں۔ کنسول سیٹ اپ ان پابندیوں سے نہیں بچاتا۔

## وسائل بنائیں اور SSH کنکشن محفوظ کریں

**پلگ اِنز** کھولیں، پہلے سے مقرر کیٹلاگ سے **VPN Setup** نصب کریں اور اس کا الگ صفحہ کھولیں۔ **VPN ترتیب دیں**، فراہم کنندہ، پھر **کلاؤڈ API سے بنائیں** یا **کلاؤڈ کنسول میں بنائیں** منتخب کریں۔ اپنے پہلے سے موجود سرور کے لیے موجودہ عوامی سرور کا اختیار چنیں۔ مقامی فارم میں اسناد درج کریں، SSH کلید چنیں یا بنائیں، اور مقام، سائز، امیج اور SSH ماخذ CIDR کا جائزہ لیں۔ اکاؤنٹ پر مبنی اختیارات اور ابتدائی جانچ معاون پیشکشیں چننے میں مدد دیتے ہیں؛ وہ گنجائش محفوظ یا کوٹے کی ضمانت نہیں دیتے۔ فراہم کنندہ کی موجودہ قیمتیں دیکھ کر اسکرین پر تخلیق منظور کریں۔

VM اور SSH تیار ہونے تک موجودہ عمل کو دیکھتے رہیں۔ درخواست کا وقت ختم ہو یا Android پس منظر کا کام روکے تو دوسری قابلِ بل VM بنانے کے بجائے اسی عمل کو جاری کریں یا جانچیں۔ تخلیق کا جواب کھو جانے پر کلاؤڈ تلاش یا کنسول جانچ ضروری ہو سکتی ہے۔ VM، ڈسک، پتے اور فائر وال وسائل کی IDs رکھیں؛ رکا ہوا عمل بھی وسائل بنا چکا ہو سکتا ہے۔

VPN Setup، SSH میزبان کلید کی منظوری مانگتا، کنکشن محفوظ کرتا، wg-easy نصب کرتا اور پہلا کلائنٹ درآمد کرتا ہے۔ فنگرپرنٹ فراہم کنندہ کے معتبر کنسول سے ملائیں۔ دستی ترتیب میں **سرورز** کے تحت عوامی IPv4، SSH پورٹ `22`، امیج صارف نام اور متعلقہ نجی کلید سے سرور شامل کریں۔ خودکار Google Cloud اور Azure اڈاپٹر `ubuntu` استعمال کرتے ہیں؛ کنسول گائیڈ وہاں مقرر کردہ نام استعمال کرتے ہیں۔ شناخت کی جانچ اور محفوظ اسناد کے لیے [آغاز](../getting-started/) دیکھیں۔

## نیٹ ورک کی دو تہیں ترتیب دیں

عوامی پتے کو روٹ، کلاؤڈ فائر وال کی اجازت، مہمان نظام کی فائر وال اجازت اور سننے والی خدمت چاہیے۔ فراہم کنندہ کی فائر وال/سیکیورٹی گروپ میں یہ قواعد استعمال کریں؛ مہمان نظام کے ضروری موجودہ قواعد برقرار رکھیں۔

- **TCP 22:** SSH کے لیے اپنے منتخب انتظامی CIDR سے اجازت دیں۔ وسائل بناتے وقت ترتیب دیں۔
- **UDP 51820:** VPN استعمال کرنے والے نیٹ ورکس کو اجازت دیں۔ گھومنے والے کلائنٹس کے لیے یہ `0.0.0.0/0` ہو سکتا ہے۔ VPN Setup اسے API سے بنے ڈیپلائمنٹس کے لیے ترتیب دیتا ہے؛ اپنے فراہم کردہ سرور کے لیے کلاؤڈ کنسول استعمال کریں۔
- **TCP 51821:** عوامی رسائی بند رکھیں۔ wg-easy انتظامی انٹرفیس صرف سرور loopback پر شائع کریں اور SSH سرنگ سے کھولیں۔
- **باہر جانے والی ٹریفک:** پیکیج/کنٹینر ڈاؤن لوڈ، DNS اور VPN کی مطلوبہ انٹرنیٹ ٹریفک کو اجازت دیں۔

Docker کا [فائر وال رویہ](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations) دیکھیں: شائع کردہ کنٹینر پورٹس UFW قواعد کو نظرانداز کر سکتی ہیں۔ انتظامی UI چھپانے کے لیے صرف UFW پر انحصار نہ کریں، اور فراہم کنندہ کی فائر وال چینز، خصوصاً OCI کے اسٹوریج/iSCSI قواعد، صاف نہ کریں۔

## منتخب VM پر wg-easy نصب کریں

منظوری کے بعد VPN Setup اپنی digest سے مقرر wg-easy ریلیز SSH کے ذریعے نصب کرتا، Ubuntu 24.04 پر ضرورت ہو تو Docker لگاتا اور پہلا کلائنٹ بناتا ہے۔ انتظامی انٹرفیس سرور loopback پر رکھتا اور فراہم کنندہ کی فائر وال چینز محفوظ رکھتا ہے۔ کنسول سے بنے یا موجودہ سرور کے لیے کلاؤڈ فائر وال خود ترتیب دیں؛ انسٹالر کو SSH رسائی اور انتظامی اختیارات چاہییں، کلاؤڈ API راز نہیں۔ یہ فرض کرنے کے بجائے نیا مخصوص سرور استعمال کریں کہ وہ غیرمتعلق VPN تنصیب اپنا لے گا۔

پرانے **WireGuard (wg-easy)** کیٹلاگ پلگ اِن کو فعال SSH سیشن اور Docker چاہیے۔ یہ **VPN Setup** سے الگ ہے اور مقامی کلائنٹ درآمد کا وعدہ نہیں کرتا۔ موافق Android بلڈ پر VPN Setup استعمال کریں یا نئی مخصوص VM پر Mobile SSH ٹرمینل سے نیچے دیا دستی طریقہ اپنائیں۔

### SSH کے ذریعے دستی تنصیب

سرکاری [Ubuntu ہدایات](https://docs.docker.com/engine/install/ubuntu/) سے Docker Engine اور اس کا Compose پلگ ان نصب کریں۔ پھر اصل منصوبے کی مخصوص ورژن والی تشکیل ڈاؤن لوڈ کریں:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.5.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

شروع کرنے سے پہلے بااختیار ٹرمینل ایڈیٹر سے `/opt/wg-easy/compose.yaml` بدلیں۔ `services.wg-easy` کے تحت امیج بدلیں، ماحول کے بلاک سے تبصرے کا نشان ہٹائیں یا اسے مقرر کریں، اور پورٹ میپنگز ان قدروں سے بدلیں۔ اصل فائل کا باقی حصہ برقرار رکھیں، بشمول مستقل والیوم، ماڈیول ماؤنٹ، صلاحیتیں، نیٹ ورکس اور sysctls:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.5.0@sha256:071f79a639e9361123a5e57733107320207b844ddbbd92dfa6962f541fe8aac8
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

یہ بدلنے کا ایک حصہ ہے، مکمل Compose فائل نہیں؛ خدمت کے تحت YAML کا اندرونی فاصلہ برقرار رکھیں۔ `INSECURE=true` صرف لوپ بیک SSH سرنگ کے لیے HTTP کی اجازت دیتا ہے۔ انتظامی پورٹ انٹرنیٹ پر شائع نہ کریں۔ کنٹینر کا سننے والا حصہ میزبان کی لوپ بیک میپنگ سے مختلف ہے۔ اصل منصوبے کی [HTTP ترتیب](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) دیکھیں۔

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

کنٹینر کا `/etc/wireguard` ڈیٹا مستقل والیوم میں رکھیں۔ پرانی `PASSWORD`، `PASSWORD_HASH` یا `WG_HOST` ترکیبیں v15 پر نہ لگائیں؛ اس کا سیٹ اپ وزرڈ استعمال کریں۔ امیج جان بوجھ کر ایک ورژن پر مقرر ہے: اپ گریڈ کے لیے نئے ورژن کا جائزہ اور مقرر حوالہ بدلنا لازم ہے، محض `pull` چلانا نہیں۔

## انتظامی UI کھولیں اور کلائنٹ شامل کریں

Mobile SSH میں [مقامی پورٹ فارورڈ](../port-forwarding/) بنائیں، جس کا مقامی پورٹ `51821`، دور کا میزبان `127.0.0.1` اور دور کا پورٹ `51821` ہو۔ SSH کنکشن فعال رکھیں اور اسی فون پر `http://127.0.0.1:51821` کھولیں۔ اگر مقامی پورٹ مصروف ہو تو دوسرا منتخب کریں اور براؤزر URL میں بھی وہی استعمال کریں۔

wg-easy کے [پہلی بار چلنے کے وزرڈ](https://wg-easy.github.io/wg-easy/latest/guides/setup/) میں منتظم اکاؤنٹ بنائیں، نئی تنصیب منتخب کریں، اور VPN اینڈپوائنٹ VM کے عوامی IPv4 یا DNS نام اور پورٹ `51820` پر مقرر کریں۔ VPN اینڈپوائنٹ ویب UI کا لوپ بیک پتہ یا پورٹ `51821` نہیں۔

ہر آلے کے لیے الگ کلائنٹ بنائیں اور اس کی WireGuard `.conf` ڈاؤن لوڈ کریں۔ اگر آپ کا Mobile SSH بلڈ یہ فراہم کرتا ہے تو **VPN → WireGuard** کھولیں، پروفائل شامل کریں، فائل درآمد کر کے محفوظ کریں۔ موجودہ Android اور iOS سورس فائل درآمد کی حمایت کرتے ہیں؛ اپنا نصب بلڈ دیکھیں۔ VPN Setup موافق Android بلڈز پر پہلا کلائنٹ براہِ راست درآمد کرتا ہے۔ اس کے صفحے پر **کلائنٹ شامل کریں**، **کلائنٹ منسوخ کریں**، **کلائنٹ/QR برآمد کریں** اور نجی SSH سرنگ کے ذریعے **انتظام کھولیں** بھی ہیں۔ اس سے پرانے پلگ اِن میں یہ صلاحیتیں یا مساوی iOS خودکاری ثابت نہیں ہوتی۔ ترتیب فائلیں اور QR کوڈ نجی کلیدیں رکھتے ہیں؛ انہیں خفیہ رکھیں۔

## VPN کی تصدیق کریں اور ناکامیاں سنبھالیں

پروفائل شروع کریں اور آپریٹنگ سسٹم کی VPN درخواست منظور کریں۔ پیئر کے حالیہ ہینڈشیک اور بڑھتے ٹریفک شمار دیکھیں، پھر DNS اور مطلوبہ انٹرنیٹ یا نجی نیٹ ورک روٹس آزمائیں۔ درآمد شدہ پروفائل یا چلتا کنٹینر اکیلا فعال VPN کا ثبوت نہیں۔

- **VM تخلیق مسترد:** بلنگ، کوٹا، علاقائی گنجائش، اسناد کی میعاد اور درست IAM اجازتیں دیکھیں۔ Google Cloud فائر وال لکھنے کے لیے Compute Network Admin سے زائد اجازتیں چاہییں؛ ادارے کا لازمی OS Login منظور شدہ کنسول ترتیب چاہتا ہے۔
- **SSH وقت ختم:** عوامی پتہ، سب نیٹ روٹنگ، TCP 22 قواعد اور فون کا موجودہ ماخذ IP دیکھیں۔ تصدیق کی ناکامی عموماً درست امیج صارف نام اور SSH کلید چاہتی ہے۔
- **انتظامی انٹرفیس دستیاب نہیں:** SSH فارورڈنگ متصل رکھیں، کنٹینر کی حالت اور loopback پورٹ میپنگ دیکھیں، اور تصدیق کریں کہ HTTP صرف سرنگ کے لیے فعال ہے۔
- **WireGuard ہینڈشیک نہیں:** کلائنٹ اینڈپوائنٹ، دونوں فائر وال تہوں میں UDP 51820، کلائنٹ کلیدیں اور سرور کے سننے کی حالت دیکھیں۔
- **ہینڈشیک ہے مگر ٹریفک نہیں:** forwarding/NAT، DNS، باہم متصادم روٹس اور `AllowedIPs` دیکھیں۔ مکمل IPv4 سرنگ `0.0.0.0/0` استعمال کرتی ہے؛ IPv6 کو الگ پرکھیں۔ upstream IPv6 کے بغیر VM، IPv6 انٹرنیٹ اخراج نہیں دے سکتی، اور صرف IPv4 روٹس IPv6 کو VPN سے باہر چھوڑ سکتے ہیں۔

## پلگ اِن اور VPN سرور اپ ڈیٹ کریں

**پلگ اِنز** میں اسی کیٹلاگ کے نئے موافق ورژن کے لیے دستیاب **اپ ڈیٹ** کارروائی استعمال کریں۔ نئی مطلوبہ صلاحیتیں دیکھیں۔ ترتیبات، اسناد اور ڈیپلائمنٹ ریکارڈ محفوظ رہتے ہیں؛ نامکمل عمل اسے شروع کرنے والے پلگ اِن ورژن سے جاری رہتا ہے۔ صرف پلگ اِن اپ ڈیٹ سرور کا wg-easy کنٹینر اپ ڈیٹ نہیں کرتا۔

پلگ اِن برج 1.4.0 یا جدید پر **سرور جانچیں** چلتا ہوا wg-easy ورژن بتاتا اور **WireGuard اپ ڈیٹ کریں** پلگ اِن کی مقرر ریلیز پیش کرتا ہے۔ اسکرین پر اپ ڈیٹ منظور کریں۔ سروس بدلنے سے پہلے امیج ڈاؤن لوڈ ہوتا ہے؛ سرور کلیدیں، کلائنٹس اور مقامی پروفائل محفوظ رہتے ہیں۔ اگر یہ فون اسی VPN کو استعمال کرتا ہے تو ایپ اپ ڈیٹ سے پہلے اسے منقطع کرتی ہے؛ بعد میں دوبارہ جڑیں۔ یہ زیرِ انتظام کنٹینر اپ ڈیٹ کرتا ہے، میزبان آپریٹنگ سسٹم نہیں۔

ناکام اپ ڈیٹ امیج ڈاؤن لوڈ کی ناکامی، کامیاب واپسی اور ناکام واپسی جس سے VPN بند رہ جائے، میں فرق دکھاتا ہے۔ سروس بحال فرض کرنے کے بجائے اس کی بحالی جانچ کریں یا دوبارہ کوشش کریں۔ دستی تنصیبوں کے لیے الگ جائزہ شدہ مقرر امیج کی تبدیلی اور بیک اپ چاہیے؛ اوپر نئی تنصیب کی ترکیب منتقلی کی گائیڈ نہیں۔

## کلائنٹس ہٹائیں اور کلاؤڈ اخراجات روکیں

مقامی پروفائل چھوڑنے سے پہلے wg-easy میں کلائنٹ منسوخ کریں۔ Mobile SSH میں پروفائل حذف کرنے سے سرور کی پیئر کلید منسوخ نہیں ہوتی۔ VPN کنٹینر یا اس کا مستقل ڈیٹا ہٹانے سے پہلے ضروری تشکیل کی محفوظ بیک اپ کاپی بنائیں۔

API سے بنے ڈیپلائمنٹ کے لیے **ڈیپلائمنٹ حذف کریں** اس کے اپنے کلاؤڈ وسائل کا جائزہ لے کر فراہم کنندہ API سے حذف کرتا ہے، چاہے SSH دستیاب نہ ہو۔ حذف رکنے یا ناکام ہونے پر بتائے گئے باقی وسائل دیکھیں؛ صفائی جاری کریں یا کنسول جانچیں۔ غیرمتعلق وسائل پلگ اِن کے زیرِ انتظام ڈیپلائمنٹ، خاص طور پر اس کے الگ Azure ریسورس گروپ، سے باہر رکھیں۔

کنسول سے بنے یا موجودہ سرور کے لیے پلگ اِن کی حذف کارروائی اس کی زیرِ انتظام VPN تنصیب ہٹاتی ہے؛ یہ آپ کی VM یا عوامی IP کو **حذف نہیں کرتی**۔ ضرورت ختم ہونے پر انہیں فراہم کنندہ کنسول میں حذف کریں، پھر بچے ہوئے ڈسک، سنیپ شاٹ، پتے اور نیٹ ورک وسائل دیکھیں۔ بحالی کے دوران اکاؤنٹ یا مقام بدلا ہو تو پہلے والے اکاؤنٹ اور مقام بھی دیکھیں، بشمول پہلے کا Scaleway پروجیکٹ یا Oracle Cloud compartment۔

**عمل روکیں** کارروائی کو روکتا ہے، وسائل حذف نہیں کرتا۔ برج 1.5.0 یا جدید پر **فہرست سے ہٹائیں** صرف تب ملتا ہے جب ایپ تصدیق کر سکے کہ اندراج بھلانے کے قابل ہے اور کوئی نامکمل عمل یا باقی زیرِ انتظام وسائل نہیں۔ یہ مقامی تاریخ صاف کرتا ہے، کلاؤڈ وسائل نہیں۔ VM روکنا یا پلگ اِن ہٹانا بھی اخراجات رکنے کی ضمانت نہیں۔ حذف کی تصدیق تک وسائل کی IDs محفوظ رکھیں۔
