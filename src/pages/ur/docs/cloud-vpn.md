# کلاؤڈ VMs اور wg-easy

اپنے کلاؤڈ اکاؤنٹ میں Linux VM بنائیں، Mobile SSH سے اس سے جڑیں، پھر WireGuard VPN چلانے کے لیے wg-easy نصب کریں۔ وسائل بنانے اور تنصیب کو الگ رکھنے سے اسی VM کو دوسری خدمت کے لیے استعمال کیا جا سکتا ہے، یا VPN پہلے سے موجود سرور پر نصب کیا جا سکتا ہے۔

**دستیابی — 8 نومبر 2026:** ذیل میں الگ VM بنانے والے پلگ انز کا مطلوبہ طریقۂ کار بیان کیا گیا ہے۔ جائزہ لیے گئے مقامی Android **VPN Setup** عمل درآمد میں وسائل بنانا، تنصیب اور کلائنٹ درآمد یکجا ہیں؛ اس کے پلگ ان اور کیٹلاگ کی تبدیلیاں غیر شائع شدہ ہیں، اور حقیقی کلاؤڈ تعیناتیاں ابھی آزمائی نہیں گئیں۔ الگ AWS، Google Cloud اور Azure اندراجات فی الحال صرف مینی فیسٹ اور ترتیبات کے ابتدائی خاکے ہیں؛ VM فہرست اور کنٹرول کی کارروائیاں نافذ نہیں، اور یہ VMs نہیں بناتے۔ اگر آپ کے کیٹلاگ میں بنانے کا طریقہ نہیں تو نیچے کنسول اور دستی تنصیب کی ہدایات استعمال کریں۔ نئے مقامی طریقۂ کار کے لیے مطابقت رکھنے والا Android بلڈ درکار ہے؛ iOS پر مساوی خودکاری ثابت نہیں۔

## دو پلگ انز، الگ ذمہ داریاں

- **کلاؤڈ وسائل بنانے والا پلگ ان:** فراہم کنندہ کی API سے VM، عوامی پتہ اور ضروری نیٹ ورک وسائل بناتا ہے، پھر SSH کنکشن محفوظ کرتا ہے۔ بعد میں انتظام یا حذف کے لیے ضروری کلاؤڈ وسائل کے IDs رکھتا ہے۔
- **wg-easy انسٹالر:** منتخب محفوظ شدہ سرور سے SSH کے ذریعے جڑتا ہے، VPN خدمت نصب کرتا ہے اور کلائنٹ کی تشکیل بنانے میں مدد دیتا ہے۔ اسے سرور تک رسائی اور انتظامی اختیارات چاہیے، آپ کی کلاؤڈ API اسناد نہیں۔ ہاتھ سے بنائی گئی VM بھی یہاں استعمال ہو سکتی ہے۔

حوالگی میں محفوظ شدہ سرور کا حوالہ، عوامی پتہ، SSH پورٹ، صارف نام، SSH اسناد کا حوالہ اور تعیناتی و وسائل کے IDs ہونے چاہئیں۔ کلاؤڈ کے راز اور SSH نجی کلیدیں پلگ ان کے آؤٹ پٹ یا VM پر نقل نہیں ہونی چاہئیں۔ VPN ہٹانا اور کلاؤڈ VM حذف کرنا الگ کارروائیاں ہیں۔

## اکاؤنٹ اور سرور کی ترتیبات تیار کریں

1. کلاؤڈ اکاؤنٹ اور بلنگ فعال کریں، خطہ منتخب کریں، اور VM، ڈسک اور عوامی IP کے کوٹے جانچیں۔ فراہم کنندہ کے موجودہ VM، IPv4، اسٹوریج اور ٹریفک اخراجات دیکھیں؛ مفت درجے کی دستیابی فرض نہیں کی جاتی۔
2. اس گائیڈ کے لیے مخصوص **Ubuntu 24.04 LTS** VM منتخب کریں جس میں کم از کم **1 GB RAM اور 20 GB ڈسک** ہو، اور **amd64 یا arm64** استعمال ہو۔ یہ اس سیٹ اپ کے بنیادی انتخاب ہیں، wg-easy کی ہر جگہ لاگو کم از کم ضروریات نہیں۔ root یا sudo رسائی والا لاگ اِن استعمال کریں؛ بغیر نگرانی تنصیب کے لیے غیر تعاملی اختیارات میں اضافہ درکار ہے۔
3. SSH کلید منتخب یا بنائیں، اور نجی کلید Mobile SSH میں رکھیں۔ کلاؤڈ پر صرف عوامی کلید اپ لوڈ کریں۔ Lightsail کے درآمدی راستے کے لیے RSA SSH کلید ضروری ہے۔ دوسرے فراہم کنندگان اور امیجز کی قبول کردہ کلیدی اقسام اپنی ہوتی ہیں۔ موجودہ iOS SSH کلائنٹ RSA کے بجائے Ed25519/ECDSA نجی کلیدوں کی حمایت کرتا ہے۔ iOS پر Lightsail کے لیے پہلے فراہم کنندہ کے براؤزر SSH کنسول سے ایپ کی معاون عوامی کلید `authorized_keys` میں شامل کریں، پھر اسی کلید سے جڑیں۔
4. **عوامی IPv4** منتخب کریں، اور فراہم کنندہ دے تو ترجیحاً محفوظ شدہ یا مستقل پتہ لیں۔ نجی پتہ، صرف IPv6 والا انسٹنس یا صرف باہر جانے کا NAT گیٹ وے اس گائیڈ کی اینڈپوائنٹ ضرورت پوری نہیں کرتا۔
5. SSH کا ماخذ CIDR واضح طور پر مقرر کریں، مثلاً موجودہ عوامی IPv4 کے بعد `/32`۔ یہ فرض نہ کریں کہ پلگ ان کی طے شدہ قدر رسائی محدود کرتی ہے۔ موبائل ڈیٹا اور Wi-Fi بدلنے پر کلاؤڈ کنسول سے یہ قاعدہ بدلنا پڑ سکتا ہے۔

کلاؤڈ API اسناد وسائل کے انتظام کی اجازت دیتی ہیں؛ SSH کلیدیں سرور میں لاگ اِن کی۔ یہ الگ اسناد ہیں۔ API راز صرف فراہم کنندہ کے محفوظ اسناد فارم میں درج کریں، صوتی درخواستوں، ٹرمینل کمانڈز یا سورس فائلوں میں کبھی نہیں۔ مقامی Android طریقۂ کار میں نیٹو کوڈ فراہم کنندہ کی توثیق اور اسناد کی خفیہ ذخیرہ کاری سنبھالتا ہے؛ ضرورت کے مطابق اسناد متعلقہ فراہم کنندہ کو بھیجی جاتی ہیں، VM یا پلگ ان ورکر کو نہیں۔ آف لائن صوتی ماڈل کلاؤڈ API کالز، ڈاؤن لوڈ یا SSH کو انٹرنیٹ کے بغیر نہیں چلاتا۔

## کلاؤڈ منتخب کریں اور عوامی پتہ حاصل کریں

**کنسول سیٹ اپ** میں خود فراہم کنندہ میں سائن اِن کریں؛ Mobile SSH کو اس کی API اسناد نہیں چاہئیں۔ مستقبل کی **پلگ ان کے ذریعے وسائل سازی** کے لیے نیچے دی گئی اسناد تیار کریں، جن کے پاس مطلوبہ تخلیق، پڑھنے، نیٹ ورک اور حذف کی اجازتیں ہوں۔ جہاں ممکن ہو رسائی مخصوص پروجیکٹ یا تعیناتی تک محدود کریں۔ دونوں طریقوں پر اکاؤنٹ کی پالیسیاں لاگو رہتی ہیں۔

منتخب Ubuntu VM اپنی SSH عوامی کلید کے ساتھ بنائیں، اور اگلے حصے کا SSH قاعدہ لگائیں۔ روابط فراہم کنندہ کے مخصوص پتے اور توثیق کے مراحل سمجھاتے ہیں۔

## وسائل بنائیں اور SSH کنکشن محفوظ کریں

مطلوبہ الگ طریقۂ کار میں **پلگ انز** کھولیں، قابلِ اعتماد کیٹلاگ سے فراہم کنندہ کا وسائل بنانے والا پلگ ان نصب کریں، اکاؤنٹ اور خطہ منتخب کریں، پھر VM سائز، امیج، عوامی پتہ اور SSH کلید چنیں۔ تخلیق کی تصدیق سے پہلے وسائل اور لاگت کا جائزہ لیں۔ صرف انتظام والا پلگ ان جس میں بنانے کی کارروائی نہ ہو یہ مرحلہ نہیں کر سکتا؛ اس کے بجائے فراہم کنندہ کا کنسول استعمال کریں۔

انتظار کریں کہ فراہم کنندہ VM چلنے کی اطلاع دے اور SSH قابلِ رسائی ہو۔ VM، ڈسک، پتے اور فائر وال کے وسائل IDs رکھیں۔ درخواست کا وقت ختم ہو جائے تو دوبارہ تخلیق سے پہلے موجودہ کارروائی دیکھیں یا بحال کریں، تاکہ دوسری قابلِ بل VM نہ بن جائے۔

موصولہ کنکشن Mobile SSH میں محفوظ کریں، یا **سرورز** میں ہاتھ سے شامل کریں: عوامی IPv4، SSH پورٹ `22`، امیج کا صارف نام اور مماثل نجی کلید کی اسناد۔ جڑنے سے پہلے فراہم کنندہ کے قابلِ اعتماد کنسول سے SSH میزبان کلید کا فنگرپرنٹ ملائیں۔ شناخت کی جانچ اور محفوظ اسناد کے لیے [شروع کریں](../getting-started/) دیکھیں۔

## نیٹ ورک کی دو تہیں ترتیب دیں

عوامی پتے کو روٹ، کلاؤڈ فائر وال کی اجازت، مہمان نظام کی فائر وال اجازت اور سننے والی خدمت چاہیے۔ فراہم کنندہ کی فائر وال/سیکیورٹی گروپ میں یہ قواعد استعمال کریں؛ مہمان نظام کے ضروری موجودہ قواعد برقرار رکھیں۔

- **TCP 22:** SSH کے لیے منتخب انتظامی CIDR سے اجازت دیں۔ اسے وسائل بناتے وقت ترتیب دیں۔
- **UDP 51820:** ان نیٹ ورکس سے اجازت دیں جو VPN استعمال کریں گے۔ گھومتے کلائنٹس کے لیے یہ `0.0.0.0/0` ہو سکتا ہے۔ WireGuard ترتیب دیتے وقت کلاؤڈ پلگ ان یا کنسول سے شامل کریں۔
- **TCP 51821:** اسے عوام کے لیے بند رکھیں۔ wg-easy انتظامی UI صرف سرور لوپ بیک پر شائع کریں اور SSH سرنگ سے پہنچیں۔
- **باہر جانے والی ٹریفک:** پیکیج/کنٹینر ڈاؤن لوڈ، DNS اور وہ انٹرنیٹ ٹریفک اجازت دیں جو VPN کو لے جانی ہے۔

Docker کا [فائر وال رویہ](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations) دیکھیں: شائع کردہ کنٹینر پورٹس UFW قواعد کو نظرانداز کر سکتی ہیں۔ انتظامی UI چھپانے کے لیے صرف UFW پر انحصار نہ کریں، اور فراہم کنندہ کی فائر وال چینز، خصوصاً OCI کے اسٹوریج/iSCSI قواعد، صاف نہ کریں۔

## منتخب VM پر wg-easy نصب کریں

الگ انسٹالر کو محفوظ شدہ SSH سرور قبول کرنا اور سرور تبدیلیوں کی منظوری مانگنی چاہیے۔ اسے OS، اختیارات، موجودہ Docker/VPN تنصیب اور پورٹ ٹکراؤ جانچنے، مستقل ڈیٹا بچانے اور نصب ورژن بتانے چاہئیں۔ اسے کلاؤڈ اکاؤنٹ کا راز نہیں چاہیے؛ کلاؤڈ فائر وال بدلنے کے لیے وسائل بنانے والا پلگ ان یا کنسول استعمال کریں۔

پرانے **WireGuard (wg-easy)** کیٹلاگ پلگ ان کو فعال SSH سیشن اور Docker چاہیے۔ یہ نیا خودکار انسٹالر نہیں اور مقامی کلائنٹ درآمد کا وعدہ نہیں کرتا۔ مطابقت رکھنے والا تازہ انسٹالر، یا نئی مخصوص VM پر Mobile SSH ٹرمینل سے یہ دستی راستہ استعمال کریں۔

### SSH کے ذریعے دستی تنصیب

سرکاری [Ubuntu ہدایات](https://docs.docker.com/engine/install/ubuntu/) سے Docker Engine اور اس کا Compose پلگ ان نصب کریں۔ پھر اصل منصوبے کی مخصوص ورژن والی تشکیل ڈاؤن لوڈ کریں:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.4.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

شروع کرنے سے پہلے بااختیار ٹرمینل ایڈیٹر سے `/opt/wg-easy/compose.yaml` بدلیں۔ `services.wg-easy` کے تحت امیج بدلیں، ماحول کے بلاک سے تبصرے کا نشان ہٹائیں یا اسے مقرر کریں، اور پورٹ میپنگز ان قدروں سے بدلیں۔ اصل فائل کا باقی حصہ برقرار رکھیں، بشمول مستقل والیوم، ماڈیول ماؤنٹ، صلاحیتیں، نیٹ ورکس اور sysctls:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.4.0@sha256:0e7bc9d34e86ddcaa92bc700d4d7dc9b33291dbc07ac8d13382f7c2095f949ec
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

یہ بدلنے کا ایک حصہ ہے، مکمل Compose فائل نہیں؛ خدمت کے تحت YAML کا اندرونی فاصلہ برقرار رکھیں۔ `INSECURE=true` صرف لوپ بیک SSH سرنگ کے لیے HTTP کی اجازت دیتا ہے۔ انتظامی پورٹ انٹرنیٹ پر شائع نہ کریں۔ کنٹینر کا سننے والا حصہ میزبان کی لوپ بیک میپنگ سے مختلف ہے۔ اصل منصوبے کی [HTTP ترتیب](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) دیکھیں۔

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

کنٹینر کا `/etc/wireguard` ڈیٹا مستقل والیوم میں رکھیں۔ پرانی `PASSWORD`، `PASSWORD_HASH` یا `WG_HOST` ترکیبیں v15 پر نہ لگائیں؛ اس کا سیٹ اپ وزرڈ استعمال کریں۔ امیج جان بوجھ کر ایک ورژن پر مقرر ہے: اپ گریڈ کے لیے نئے ورژن کا جائزہ اور مقرر حوالہ بدلنا لازم ہے، محض `pull` چلانا نہیں۔

## انتظامی UI کھولیں اور کلائنٹ شامل کریں

Mobile SSH میں [مقامی پورٹ فارورڈ](../port-forwarding/) بنائیں، جس کا مقامی پورٹ `51821`، دور کا میزبان `127.0.0.1` اور دور کا پورٹ `51821` ہو۔ SSH کنکشن فعال رکھیں اور اسی فون پر `http://127.0.0.1:51821` کھولیں۔ اگر مقامی پورٹ مصروف ہو تو دوسرا منتخب کریں اور براؤزر URL میں بھی وہی استعمال کریں۔

wg-easy کے [پہلی بار چلنے کے وزرڈ](https://wg-easy.github.io/wg-easy/latest/guides/setup/) میں منتظم اکاؤنٹ بنائیں، نئی تنصیب منتخب کریں، اور VPN اینڈپوائنٹ VM کے عوامی IPv4 یا DNS نام اور پورٹ `51820` پر مقرر کریں۔ VPN اینڈپوائنٹ ویب UI کا لوپ بیک پتہ یا پورٹ `51821` نہیں۔

ہر آلے کے لیے ایک کلائنٹ بنائیں اور اس کی WireGuard `.conf` ڈاؤن لوڈ کریں۔ جہاں آپ کا Mobile SSH بلڈ یہ سہولت دے، **VPN → WireGuard** کھولیں، پروفائل شامل کریں، فائل درآمد کر کے محفوظ کریں۔ موجودہ Android اور iOS سورس فائل درآمد کی حمایت کرتا ہے؛ اپنا نصب بلڈ جانچیں۔ مقامی Android کا مشترکہ طریقۂ کار براہِ راست درآمد کر سکتا ہے، مگر یہ پرانے پلگ ان یا iOS خودکاری کا وعدہ نہیں۔ تشکیل کی فائلوں اور QR کوڈز میں نجی کلیدیں ہوتی ہیں؛ انہیں خفیہ رکھیں۔

## VPN کی تصدیق کریں اور ناکامیاں سنبھالیں

پروفائل شروع کریں اور آپریٹنگ سسٹم کی VPN درخواست منظور کریں۔ پیئر کے حالیہ ہینڈشیک اور بڑھتے ٹریفک شمار دیکھیں، پھر DNS اور مطلوبہ انٹرنیٹ یا نجی نیٹ ورک روٹس آزمائیں۔ درآمد شدہ پروفائل یا چلتا کنٹینر اکیلا فعال VPN کا ثبوت نہیں۔

- **VM بنانا مسترد ہو:** بلنگ، کوٹا، خطے کی گنجائش، اسناد کی میعاد اور درست IAM اجازتیں جانچیں۔ Google Cloud فائر وال لکھنے کے لیے Network Admin سے زیادہ اجازتیں چاہیے۔
- **SSH کا وقت ختم ہو:** عوامی پتہ، سب نیٹ روٹنگ، TCP 22 قواعد اور فون کا موجودہ ماخذ IP جانچیں۔ توثیق کی ناکامی عموماً امیج کا درست صارف نام اور SSH کلید مانگتی ہے۔
- **انتظامی UI دستیاب نہ ہو:** SSH فارورڈنگ جڑی رکھیں، کنٹینر کی حالت اور لوپ بیک پورٹ میپنگ جانچیں، اور تصدیق کریں کہ HTTP صرف سرنگ کے لیے فعال ہے۔
- **WireGuard ہینڈشیک نہ ہو:** کلائنٹ اینڈپوائنٹ، دونوں فائر وال تہوں میں UDP 51820، کلائنٹ کلیدیں اور سرور کے سننے کی حالت جانچیں۔
- **ہینڈشیک ہو مگر ٹریفک نہ ہو:** فارورڈنگ/NAT، DNS، روٹس کا تداخل اور `AllowedIPs` دیکھیں۔ مکمل IPv4 سرنگ `0.0.0.0/0` استعمال کرتی ہے؛ IPv6 الگ جانچیں۔ اوپری نیٹ ورک سے IPv6 نہ رکھنے والی VM، IPv6 انٹرنیٹ خروج نہیں دے سکتی، اور صرف IPv4 روٹس IPv6 کو VPN سے باہر چھوڑ سکتے ہیں۔

## کلائنٹس ہٹائیں اور کلاؤڈ اخراجات روکیں

مقامی پروفائل چھوڑنے سے پہلے wg-easy میں کلائنٹ منسوخ کریں۔ Mobile SSH میں پروفائل حذف کرنے سے سرور کی پیئر کلید منسوخ نہیں ہوتی۔ VPN کنٹینر یا اس کا مستقل ڈیٹا ہٹانے سے پہلے ضروری تشکیل کی محفوظ بیک اپ کاپی بنائیں۔

وسائل کے مالک پلگ ان یا فراہم کنندہ کے کنسول سے غیر ضروری VM حذف کریں، پھر باقی ڈسکیں، اسنیپ شاٹس، محفوظ/عوامی پتے اور نیٹ ورک وسائل جانچیں۔ مخصوص Azure ریسورس گروپ حذف کرنے سے پہلے اس کے مواد کا جائزہ لیں۔ غیر متعلقہ وسائل پلگ ان کی زیرِ انتظام تعیناتی سے باہر رکھیں۔

VM روکنا، سیٹ اپ کام منسوخ کرنا یا پلگ ان ہٹانا اس بات کی ضمانت نہیں کہ وسائل حذف یا اخراجات بند ہو گئے۔ کنسول سے بنائے وسائل صاف کرنا آپ کی ذمہ داری رہتا ہے؛ حذف کی تصدیق تک فراہم کنندہ کے وسائل IDs رکھیں۔
