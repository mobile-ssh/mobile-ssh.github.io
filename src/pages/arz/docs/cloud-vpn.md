# الأجهزة الافتراضية في السحابة وwg-easy

اعمل جهاز Linux افتراضي في حسابك السحابي، واتصل بيه بـMobile SSH، وبعدين ثبّت wg-easy عشان تشغّل WireGuard VPN. فصل إنشاء الموارد عن التثبيت بيخلّيك تستخدم نفس الجهاز لخدمة تانية، أو تثبّت VPN على سيرفر عندك أصلًا.

**المتاح — 8 نوفمبر 2026:** اللي موصوف تحت هو سير الشغل المقصود بإضافات مستقلة لإنشاء الأجهزة الافتراضية. تنفيذ Android المحلي اللي راجعناه، **VPN Setup**، بيجمع إنشاء الموارد والتثبيت واستيراد العميل؛ تغييرات الإضافة والكتالوج لسه ماتنشرتش، والنشر الحقيقي على السحابة لسه ماتجرّبش. إدخالات AWS وGoogle Cloud وAzure المنفصلة حاليًا مجرد هياكل لملفات التعريف والإعدادات؛ عرض الأجهزة الافتراضية والتحكم فيها لسه ماتنفذوش، ومش بتنشئ أجهزة. لو كتالوجك مفيهوش مسار إنشاء، استخدم تعليمات لوحة التحكم والتثبيت اليدوي تحت. سير الشغل الأصلي الجديد محتاج نسخة Android متوافقة؛ أتمتة مماثلة على iOS لسه مش مثبتة.

## إضافتين، كل واحدة ليها مسؤوليتها

- **إضافة إنشاء موارد السحابة:** بتستخدم API المزوّد عشان تعمل الجهاز الافتراضي والعنوان العام وموارد الشبكة المطلوبة، وبعدين تحفظ اتصال SSH. بتحتفظ بمعرّفات موارد السحابة عشان الإدارة أو الحذف بعدين.
- **مثبّت wg-easy:** بيتصل بسيرفر محفوظ إنت بتختاره عن طريق SSH، وبيثبّت خدمة VPN وبيساعدك تعمل إعداد للعميل. محتاج دخول للسيرفر وصلاحيات إدارة، مش بيانات اعتماد API السحابة. ينفع تستخدم جهاز افتراضي عملته يدويًا برضه.

بيانات التسليم المفروض تشمل مرجع السيرفر المحفوظ والعنوان العام ومنفذ SSH واسم المستخدم ومرجع بيانات اعتماد SSH ومعرّفات النشر والموارد. أسرار السحابة ومفاتيح SSH الخاصة ماتتنسخش في خرج الإضافة ولا على الجهاز الافتراضي. إزالة VPN وحذف الجهاز السحابي عمليتين منفصلتين.

## جهّز حسابك وإعدادات السيرفر

1. فعّل حساب سحابي والفوترة، واختار منطقة، وراجع حصص الأجهزة والأقراص وعناوين IP العامة. راجع أسعار المزوّد الحالية للأجهزة وIPv4 والتخزين وحركة البيانات؛ مش بنفترض إن فيه باقة مجانية متاحة.
2. للدليل ده، اختار جهاز مخصص بنظام **Ubuntu 24.04 LTS** وفيه على الأقل **1 GB ذاكرة و20 GB قرص**، بمعمارية **amd64 أو arm64**. دي الاختيارات الأساسية للإعداد ده، مش أقل متطلبات عامة لـwg-easy. استخدم حساب دخول بصلاحية root أو sudo؛ التثبيت من غير تدخل محتاج رفع صلاحيات من غير تفاعل.
3. اختار مفتاح SSH أو اعمل واحد، وخلي المفتاح الخاص في Mobile SSH. ارفع المفتاح العام بس للسحابة. مسار الاستيراد في Lightsail محتاج مفتاح RSA SSH. باقي المزوّدين والصور ليهم أنواع مفاتيح مقبولة مختلفة. عميل SSH الحالي على iOS بيدعم مفاتيح Ed25519/ECDSA الخاصة، مش RSA. لو هتستخدم Lightsail على iOS، استخدم الأول طرفية SSH في متصفح المزوّد عشان تضيف مفتاح عام يدعمه التطبيق إلى `authorized_keys`، وبعدين اتصل بالمفتاح ده.
4. اختار **IPv4 عام**، والأفضل يكون محجوز أو ثابت لو المزوّد بيوفره. عنوان خاص، أو جهاز IPv6 بس، أو بوابة NAT للخروج بس، مش بيحققوا متطلبات نقطة الاتصال في الدليل ده.
5. حدد CIDR مصدر SSH صراحة، زي IPv4 العام الحالي وبعده `/32`. ماتفترضش إن إعداد الإضافة الافتراضي بيقيد الدخول. التبديل بين بيانات الموبايل وWi-Fi ممكن يحتاج تحديث القاعدة من لوحة السحابة.

بيانات اعتماد API السحابة بتسمح بإدارة الموارد؛ مفاتيح SSH بتسمح بدخول السيرفر. دول حاجتين مختلفتين. دخّل أسرار API في نموذج بيانات الاعتماد المحمي بتاع المزوّد بس، مش في طلبات صوتية أو أوامر طرفية أو ملفات كود. في سير شغل Android المحلي، الكود الأصلي بيتولى مصادقة المزوّد وتخزين بيانات الاعتماد مشفرة؛ البيانات بتروح لمزوّدها لو مطلوبة، مش للجهاز الافتراضي ولا عامل الإضافة. نموذج صوت أوفلاين مش بيخلّي طلبات API السحابة أو التنزيلات أو SSH تشتغل من غير إنترنت.

## اختار سحابة وهات عنوان عام

في **الإعداد من لوحة التحكم**، سجّل الدخول للمزوّد بنفسك؛ Mobile SSH مش محتاج بيانات API بتاعته. ولـ**إنشاء الموارد بالإضافات مستقبلًا**، جهّز بيانات الاعتماد اللي تحت بصلاحيات الإنشاء والقراءة والشبكة والحذف المطلوبة. ضيّق الوصول لمشروع أو نشر مخصص لو ده مدعوم. سياسات الحساب لسه سارية في الطريقتين.

**بديل AWS EC2:** شغّل Ubuntu في شبكة فرعية عامة فيها [بوابة إنترنت ومسار بوابة `0.0.0.0/0`](https://docs.aws.amazon.com/vpc/latest/userguide/VPC_Internet_Gateway.html)، واختار مفتاح SSH ومجموعة أمان، وبعدين اربط [Elastic IP](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/working-with-eips.html). استخدم `ubuntu`. المحوّل التلقائي المحلي بيستهدف Lightsail؛ EC2 مساره لوحة التحكم. Elastic IP لوحده مش بيخلّي الشبكة الفرعية الخاصة قابلة للوصول.

لو المؤسسة بتمنع مفاتيح حسابات الخدمة، أو عناوين IP خارجية، أو طريقة مصادقة SSH اللي اخترتها، هات إعداد موافق عليه من المسؤول. الإعداد من لوحة التحكم مش بيتخطى القيود دي.

## اعمل الموارد واحفظ اتصال SSH

في سير الشغل المنفصل المقصود، افتح **الإضافات**، وثبّت إضافة الإنشاء بتاعة المزوّد من كتالوج موثوق، واختار الحساب والمنطقة، وبعدين حجم الجهاز والصورة والعنوان العام ومفتاح SSH. راجع الموارد والتكلفة قبل تأكيد الإنشاء. إضافة إدارة بس مفيهاش إجراء إنشاء مش هتعمل الخطوة دي؛ استخدم لوحة المزوّد بدلها.

استنى لحد ما المزوّد يقول إن الجهاز شغال وSSH بقى قابل للوصول. احتفظ بمعرّفات الجهاز والقرص والعنوان والجدار الناري. لو الطلب انتهت مهلته، افحص أو استأنف العملية الموجودة قبل ما تعيد الإنشاء، عشان ماتعملش جهاز تاني بيتحاسب عليك.

احفظ الاتصال الناتج في Mobile SSH، أو ضيفه يدويًا تحت **السيرفرات**: IPv4 العام، ومنفذ SSH `22`، واسم مستخدم الصورة، وبيانات المفتاح الخاص المطابق. قارن بصمة مفتاح مضيف SSH من لوحة المزوّد الموثوقة قبل الاتصال. شوف [البداية](../getting-started/) لفحص الهوية وبيانات الاعتماد المحفوظة.

## ظبّط طبقتين الشبكة

العنوان العام محتاج مسار، وسماح في الجدار الناري بتاع السحابة وبتاع النظام الضيف، وخدمة بتستمع. استخدم القواعد دي في جدار المزوّد/مجموعة الأمان، وحافظ على قواعد النظام الضيف الموجودة والمطلوبة.

- **TCP 22:** اسمح بـSSH من CIDR الإدارة اللي اخترته. ظبّطه وقت إنشاء الموارد.
- **UDP 51820:** اسمح من الشبكات اللي هتستخدم VPN. للعملاء اللي بيتنقلوا ده ممكن يعني `0.0.0.0/0`. ضيفه وقت إعداد WireGuard، من إضافة الإنشاء أو لوحة التحكم.
- **TCP 51821:** خليه مقفول للعامة. انشر واجهة إدارة wg-easy على عنوان الرجوع المحلي للسيرفر بس، وادخل عليها من نفق SSH.
- **حركة الخروج:** اسمح بتنزيل الحزم والحاويات وDNS وحركة الإنترنت اللي VPN المفروض ينقلها.

راجع [سلوك الجدار الناري في Docker](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations): منافذ الحاويات المنشورة ممكن تتخطى قواعد UFW. ماتعتمدش على UFW لوحده عشان تخفي واجهة الإدارة، وماتمسحش سلاسل الجدار الناري بتاعة المزوّد، بالذات قواعد التخزين/iSCSI في OCI.

## ثبّت wg-easy على الجهاز المختار

المثبّت المنفصل المفروض ياخد سيرفر SSH المحفوظ ويطلب موافقة على تغييرات السيرفر. لازم يفحص النظام والصلاحيات وDocker/VPN الموجود وتعارض المنافذ، ويحافظ على البيانات الدائمة، ويقول الإصدار اللي اتثبّت. مش محتاج سر حساب السحابة؛ استخدم إضافة الإنشاء أو لوحة التحكم لتغييرات الجدار الناري السحابي.

إضافة الكتالوج الأقدم **WireGuard (wg-easy)** محتاجة جلسة SSH نشطة وDocker. مش هي المثبّت التلقائي الجديد، ومش بتوعد باستيراد عميل أصلي. استخدم مثبّت محدّث ومتوافق، أو المسار اليدوي اللي جاي من طرفية Mobile SSH على جهاز جديد مخصص.

### تثبيت يدوي عن طريق SSH

ثبّت Docker Engine وإضافة Compose حسب [تعليمات Ubuntu](https://docs.docker.com/engine/install/ubuntu/) الرسمية. وبعدين نزّل إعداد المشروع الأصلي للإصدار المحدد:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.4.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

عدّل `/opt/wg-easy/compose.yaml` بمحرر طرفية عنده صلاحيات قبل التشغيل. تحت `services.wg-easy`، غيّر الصورة، وشيل التعليق عن كتلة البيئة أو ظبّطها، وبدّل تعيينات المنافذ بالقيم دي. سيب باقي الملف الأصلي، بما فيه وحدة التخزين الدائمة وربط الوحدات والقدرات والشبكات وإعدادات sysctls:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.4.0@sha256:0e7bc9d34e86ddcaa92bc700d4d7dc9b33291dbc07ac8d13382f7c2095f949ec
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

ده جزء للاستبدال، مش ملف Compose كامل؛ حافظ على مسافات YAML تحت الخدمة. `INSECURE=true` بيسمح بـHTTP لنفق SSH على عنوان الرجوع المحلي بس. ماتنشرش منفذ الإدارة على الإنترنت. مستمع الحاوية غير تعيين الرجوع المحلي على المضيف. شوف [إعداد HTTP](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) بتاع المشروع الأصلي.

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

خلي بيانات `/etc/wireguard` بتاعة الحاوية في وحدة التخزين الدائمة. ماتطبقش وصفات `PASSWORD` أو `PASSWORD_HASH` أو `WG_HOST` القديمة على v15؛ استخدم معالج الإعداد. الصورة متثبتة عمدًا: الترقية محتاجة مراجعة إصدار جديد وتغيير المرجع المثبت، مش مجرد تشغيل `pull`.

## افتح واجهة الإدارة وضيف عميل

اعمل [إعادة توجيه منفذ محلي](../port-forwarding/) في Mobile SSH بمنفذ محلي `51821`، ومضيف بعيد `127.0.0.1`، ومنفذ بعيد `51821`. خلي اتصال SSH شغال وافتح `http://127.0.0.1:51821` على نفس الموبايل. لو المنفذ المحلي مشغول، اختار واحد تاني واستخدمه في URL المتصفح.

في [معالج أول تشغيل](https://wg-easy.github.io/wg-easy/latest/guides/setup/) بتاع wg-easy، اعمل حساب مسؤول، واختار تثبيت جديد، وظبّط نقطة اتصال VPN على IPv4 العام للجهاز أو اسم DNS مع المنفذ `51820`. نقطة VPN مش عنوان الرجوع المحلي بتاع واجهة الويب ولا المنفذ `51821`.

اعمل عميل لكل جهاز ونزّل ملف WireGuard `.conf` بتاعه. لو نسخة Mobile SSH عندك بتوفر ده، افتح **VPN → WireGuard**، وضيف بروفايل واستورد الملف واحفظه. كود Android وiOS الحالي بيدعم استيراد الملفات؛ راجع نسختك المثبتة. سير شغل Android المحلي المجمّع يقدر يستورد مباشرة، بس ده مش وعد عن الإضافة الأقدم أو أتمتة iOS. ملفات الإعداد ورموز QR فيها مفاتيح خاصة؛ حافظ على سريتها.

## اتأكد من VPN وتعامل مع الأعطال

شغّل البروفايل ووافق على طلب VPN من نظام التشغيل. راجع مصافحة حديثة مع الطرف التاني وزيادة عدادات المرور، وبعدين جرّب DNS ومسارات الإنترنت أو الشبكة الخاصة المطلوبة. استيراد بروفايل أو حاوية شغالة لوحده مش دليل إن VPN شغال.

- **إنشاء الجهاز اترفض:** راجع الفوترة والحصة وسعة المنطقة وانتهاء بيانات الاعتماد وصلاحيات IAM بالظبط. كتابة جدار Google Cloud الناري محتاجة صلاحيات زيادة عن Network Admin.
- **مهلة SSH خلصت:** راجع العنوان العام ومسار الشبكة الفرعية وقواعد TCP 22 وعنوان مصدر الموبايل الحالي. فشل المصادقة غالبًا محتاج اسم المستخدم الصحيح للصورة ومفتاح SSH الصحيح.
- **واجهة الإدارة مش متاحة:** خلي توجيه SSH متصل، وراجع حالة الحاوية وتعيين منفذ الرجوع المحلي، واتأكد إن HTTP متفعّل للنفق بس.
- **مفيش مصافحة WireGuard:** راجع نقطة العميل، وUDP 51820 في طبقتين الجدار الناري، ومفاتيح العميل، وهل السيرفر بيستمع.
- **فيه مصافحة بس مفيش حركة:** افحص التوجيه/NAT وDNS وتداخل المسارات و`AllowedIPs`. نفق IPv4 الكامل بيستخدم `0.0.0.0/0`؛ قيّم IPv6 لوحده. جهاز من غير IPv6 صاعد مش هيوفر خروج IPv6 للإنترنت، ومسارات IPv4 بس ممكن تسيب IPv6 برّه VPN.

## شيل العملاء ووقّف رسوم السحابة

الغِ العميل في wg-easy قبل ما تتخلص من بروفايله المحلي. حذف بروفايل في Mobile SSH مش بيلغي مفتاح الطرف التاني على السيرفر. اعمل نسخة احتياطية آمنة للإعدادات المطلوبة قبل ما تشيل حاوية VPN أو بياناتها الدائمة.

استخدم إضافة الإنشاء المالكة أو لوحة المزوّد عشان تحذف جهاز مش محتاجه، وبعدين راجع الأقراص واللقطات والعناوين المحجوزة/العامة وموارد الشبكة اللي فضلت. راجع محتويات مجموعة موارد Azure المخصصة قبل حذفها. خلي الموارد اللي ملهاش علاقة برّه النشر اللي الإضافة بتديره.

إيقاف جهاز، أو إلغاء شغل إعداد، أو إزالة الإضافة، مش بيضمن إن الموارد اتحذفت أو الرسوم وقفت. الموارد اللي عملتها من لوحة التحكم لسه مسؤوليتك تنضفها؛ احتفظ بمعرّفات المزوّد لحد ما الحذف يتأكد.
