# ক্লাউড VM ও wg-easy

নিজের ক্লাউড অ্যাকাউন্টে Linux VM তৈরি করে Mobile SSH দিয়ে যুক্ত হোন, তারপর WireGuard VPN চালাতে wg-easy ইনস্টল করুন। সম্পদ তৈরি আর ইনস্টল আলাদা রাখলে একই VM অন্য সেবায় ব্যবহার করা যায়, বা আগে থেকেই থাকা সার্ভারে VPN বসানো যায়।

**প্রাপ্যতা — 8 নভেম্বর 2026:** নিচের নির্ধারিত কাজের ধারায় VM তৈরির জন্য আলাদা প্লাগইন আছে। পর্যালোচিত স্থানীয় Android **VPN Setup** বাস্তবায়নে সম্পদ তৈরি, ইনস্টল ও ক্লায়েন্ট আমদানি একসঙ্গে হয়; এর প্লাগইন/ক্যাটালগ পরিবর্তন অপ্রকাশিত এবং বাস্তব ক্লাউডে স্থাপন এখনো পরীক্ষিত নয়। আলাদা AWS, Google Cloud ও Azure এন্ট্রিগুলো বর্তমানে শুধু ম্যানিফেস্ট/সেটিংসের অসম্পূর্ণ কাঠামো; VM তালিকা দেখানো ও নিয়ন্ত্রণের কাজ বাস্তবায়িত হয়নি, আর এগুলো VM-ও তৈরি করে না। আপনার ক্যাটালগে তৈরির ব্যবস্থা না থাকলে নিচের কনসোল ও নিজে ইনস্টল করার নির্দেশনা ব্যবহার করুন। নতুন নেটিভ পদ্ধতির জন্য সামঞ্জস্যপূর্ণ Android বিল্ড দরকার; সমতুল্য iOS স্বয়ংক্রিয় ব্যবস্থা প্রতিষ্ঠিত নয়।

## আলাদা দায়িত্বের দুটি প্লাগইন

- **ক্লাউড প্রভিশনার:** প্রদানকারীর API দিয়ে VM, সর্বজনীন ঠিকানা ও প্রয়োজনীয় নেটওয়ার্ক সম্পদ তৈরি করে, তারপর SSH সংযোগ সংরক্ষণ করে। পরবর্তী ব্যবস্থাপনা বা মোছার জন্য ক্লাউড সম্পদের ID রাখে।
- **wg-easy ইনস্টলার:** নির্বাচিত সংরক্ষিত সার্ভারে SSH দিয়ে যুক্ত হয়, VPN সেবা ইনস্টল করে এবং ক্লায়েন্ট কনফিগারেশন তৈরিতে সাহায্য করে। এর সার্ভার প্রবেশাধিকার ও প্রশাসনিক ক্ষমতা দরকার, আপনার ক্লাউড API পরিচয়পত্র নয়। নিজে তৈরি করা VM-ও এখানে ব্যবহার করা যায়।

হস্তান্তরে সংরক্ষিত সার্ভারের রেফারেন্স, সর্বজনীন ঠিকানা, SSH পোর্ট, ব্যবহারকারীর নাম, SSH পরিচয়পত্রের রেফারেন্স এবং স্থাপন/সম্পদের ID থাকা উচিত। ক্লাউডের গোপন তথ্য বা SSH ব্যক্তিগত কী প্লাগইনের আউটপুটে বা VM-এ কপি করা উচিত নয়। VPN সরানো আর ক্লাউড VM মোছা আলাদা কাজ।

## অ্যাকাউন্ট ও সার্ভারের সেটিং প্রস্তুত করুন

1. ক্লাউড অ্যাকাউন্ট ও বিলিং চালু করুন, অঞ্চল বাছুন এবং VM, ডিস্ক ও সর্বজনীন IP-এর কোটা দেখুন। প্রদানকারীর বর্তমান VM, IPv4, স্টোরেজ ও ট্র্যাফিকের খরচ পর্যালোচনা করুন; বিনামূল্যের স্তর পাওয়া যাবে ধরে নেওয়া হচ্ছে না।
2. এই নির্দেশিকার জন্য **amd64 বা arm64**-এ অন্তত **1 GB RAM ও 20 GB ডিস্ক**-সহ আলাদা **Ubuntu 24.04 LTS** VM বাছুন। এগুলো এই ব্যবস্থার প্রাথমিক পছন্দ, wg-easy-এর সর্বজনীন ন্যূনতম চাহিদা নয়। root বা sudo প্রবেশাধিকারসহ লগইন ব্যবহার করুন; ব্যবহারকারীর হস্তক্ষেপ ছাড়া ইনস্টলে প্রশ্ন না করেই প্রশাসনিক ক্ষমতা পাওয়া দরকার।
3. SSH কী বাছুন বা তৈরি করুন; ব্যক্তিগত কী Mobile SSH-এ রাখুন। ক্লাউডে শুধু সর্বজনীন কী আপলোড করুন। Lightsail-এর আমদানি পথে RSA SSH কী লাগে। অন্য প্রদানকারী ও ইমেজের গ্রহণযোগ্য কীর ধরন আলাদা। বর্তমান iOS SSH ক্লায়েন্ট RSA ব্যক্তিগত কীর বদলে Ed25519/ECDSA সমর্থন করে। iOS-এ Lightsail-এর জন্য আগে প্রদানকারীর ব্রাউজার SSH কনসোল দিয়ে অ্যাপ-সমর্থিত সর্বজনীন কী `authorized_keys`-এ যোগ করুন, তারপর সেই কী দিয়ে যুক্ত হোন।
4. **সর্বজনীন IPv4** বাছুন; প্রদানকারী দিলে সংরক্ষিত/স্থির ঠিকানা অগ্রাধিকার দিন। ব্যক্তিগত ঠিকানা, শুধু IPv6-এর ইনস্ট্যান্স বা শুধু বহির্গামী NAT গেটওয়ে এই নির্দেশিকার এন্ডপয়েন্টের চাহিদা মেটায় না।
5. SSH উৎস CIDR স্পষ্ট করে দিন, যেমন আপনার বর্তমান সর্বজনীন IPv4-এর পরে `/32`। প্লাগইনের ডিফল্ট প্রবেশ সীমিত করে ধরে নেবেন না। মোবাইল ডেটা ও Wi-Fi বদলালে ক্লাউড কনসোল থেকে নিয়ম বদলাতে হতে পারে।

ক্লাউড API পরিচয়পত্র সম্পদ ব্যবস্থাপনার অনুমতি দেয়; SSH কী দেয় সার্ভারে লগইনের। এগুলো আলাদা পরিচয়পত্র। API গোপন তথ্য শুধু প্রদানকারীর সুরক্ষিত পরিচয়পত্রের ফর্মে দিন, কখনো কণ্ঠের নির্দেশ, টার্মিনাল কমান্ড বা সোর্স ফাইলে নয়। স্থানীয় Android পদ্ধতিতে নেটিভ কোড প্রদানকারীর প্রমাণীকরণ ও এনক্রিপ্ট করা পরিচয়পত্রের সংরক্ষণ সামলায়; প্রয়োজনে পরিচয়পত্র তাদের প্রদানকারীর কাছে যায়, VM বা প্লাগইন ওয়ার্কারের কাছে নয়। অফলাইন ভয়েস মডেল থাকলেই ক্লাউড API কল, ডাউনলোড বা SSH ইন্টারনেট ছাড়া চলে না।

## ক্লাউড বাছুন ও সর্বজনীন ঠিকানা নিন

**কনসোল সেটআপের** জন্য প্রদানকারীর কাছে নিজে সাইন ইন করুন; Mobile SSH-এর তার API পরিচয়পত্র দরকার নেই। ভবিষ্যতের **প্লাগইন দিয়ে সম্পদ তৈরির** জন্য নিচের পরিচয়পত্র প্রস্তুত করুন, প্রয়োজনীয় তৈরি, পড়া, নেটওয়ার্ক ও মোছার অনুমতিসহ। যেখানে সম্ভব প্রবেশাধিকার আলাদা প্রকল্প বা স্থাপনে সীমিত রাখুন। অ্যাকাউন্টের নীতি দুই পদ্ধতিতেই প্রযোজ্য।

আপনার SSH সর্বজনীন কী দিয়ে নির্বাচিত Ubuntu VM তৈরি করুন এবং পরের অংশের SSH নিয়ম দিন। লিংকগুলো প্রদানকারীভেদে ঠিকানা ও প্রমাণীকরণের ধাপ ব্যাখ্যা করে।

## সম্পদ তৈরি ও SSH সংযোগ সংরক্ষণ

নির্ধারিত আলাদা পদ্ধতিতে **প্লাগইন** খুলুন, বিশ্বস্ত ক্যাটালগ থেকে প্রদানকারীর প্রভিশনিং প্লাগইন ইনস্টল করুন, অ্যাকাউন্ট ও অঞ্চল বাছুন, তারপর VM-এর আকার, ইমেজ, সর্বজনীন ঠিকানা ও SSH কী বেছে নিন। তৈরির নিশ্চয়তা দেওয়ার আগে সম্পদ ও খরচ দেখুন। তৈরির কাজ নেই এমন ব্যবস্থাপনামাত্র প্লাগইন এই ধাপ করতে পারে না; প্রদানকারীর কনসোল ব্যবহার করুন।

প্রদানকারী VM চালু দেখানো এবং SSH-এ পৌঁছানো সম্ভব হওয়া পর্যন্ত অপেক্ষা করুন। VM, ডিস্ক, ঠিকানা ও ফায়ারওয়াল সম্পদের ID রাখুন। অনুরোধের সময় ফুরোলে আবার তৈরির আগে বিদ্যমান কাজ দেখুন বা চালিয়ে যান, যাতে দ্বিতীয় বিলযোগ্য VM না হয়।

ফেরত পাওয়া সংযোগ Mobile SSH-এ রাখুন বা **সার্ভার**-এ নিজে যোগ করুন: সর্বজনীন IPv4, SSH পোর্ট `22`, ইমেজের ব্যবহারকারীর নাম এবং মিলযুক্ত ব্যক্তিগত-কী পরিচয়পত্র। সংযোগের আগে প্রদানকারীর বিশ্বস্ত কনসোলে SSH হোস্ট-কীর ফিঙ্গারপ্রিন্ট মিলিয়ে নিন। পরিচয় যাচাই ও সংরক্ষিত পরিচয়পত্রের জন্য [শুরু করা](../getting-started/) দেখুন।

## নেটওয়ার্কের দুই স্তর কনফিগার করুন

সর্বজনীন ঠিকানার জন্য রুট, ক্লাউড ফায়ারওয়াল অনুমতি, গেস্ট ফায়ারওয়াল অনুমতি এবং শুনছে এমন সেবা দরকার। প্রদানকারীর ফায়ারওয়াল/সিকিউরিটি গ্রুপে এই নিয়ম দিন; প্রয়োজনীয় বিদ্যমান গেস্ট নিয়ম রাখুন।

- **TCP 22:** SSH-এর জন্য নির্বাচিত ব্যবস্থাপনা CIDR থেকে অনুমতি দিন। সম্পদ তৈরির সময় সেট করুন।
- **UDP 51820:** VPN ব্যবহার করবে এমন নেটওয়ার্ক থেকে অনুমতি দিন। চলমান ক্লায়েন্টের জন্য এটি `0.0.0.0/0` হতে পারে। WireGuard সেটআপের সময় ক্লাউড প্রভিশনার বা কনসোল থেকে যোগ করুন।
- **TCP 51821:** সর্বজনীনভাবে বন্ধ রাখুন। wg-easy প্রশাসক UI শুধু সার্ভারের লুপব্যাকে প্রকাশ করে SSH টানেল দিয়ে খুলুন।
- **বহির্গামী ট্র্যাফিক:** প্যাকেজ/কনটেইনার ডাউনলোড, DNS ও VPN দিয়ে চলবে এমন ইন্টারনেট ট্র্যাফিকের অনুমতি দিন।

Docker-এর [ফায়ারওয়াল আচরণ](https://docs.docker.com/engine/install/ubuntu/#firewall-limitations) দেখুন: প্রকাশিত কনটেইনার পোর্ট UFW নিয়ম এড়িয়ে যেতে পারে। প্রশাসক UI আড়াল করতে শুধু UFW-এর ওপর ভরসা করবেন না এবং প্রদানকারীর ফায়ারওয়াল চেইন মুছবেন না, বিশেষত OCI-এর স্টোরেজ/iSCSI নিয়ম।

## নির্বাচিত VM-এ wg-easy ইনস্টল করুন

আলাদা ইনস্টলারের সংরক্ষিত SSH সার্ভার নেওয়া এবং সার্ভারে পরিবর্তনের অনুমোদন চাওয়া উচিত। OS, ক্ষমতা, বিদ্যমান Docker/VPN ইনস্টল ও পোর্টের সংঘর্ষ পরীক্ষা, স্থায়ী ডেটা সংরক্ষণ এবং ইনস্টল করা সংস্করণ জানানো উচিত। তার ক্লাউড অ্যাকাউন্টের গোপন তথ্য লাগে না; ক্লাউড ফায়ারওয়াল বদলাতে প্রভিশনার বা কনসোল ব্যবহার করুন।

পুরোনো **WireGuard (wg-easy)** ক্যাটালগ প্লাগইনের সক্রিয় SSH সেশন ও Docker লাগে। এটি নতুন স্বয়ংক্রিয় ইনস্টলার নয় এবং নেটিভ ক্লায়েন্ট আমদানির প্রতিশ্রুতি দেয় না। সামঞ্জস্যপূর্ণ হালনাগাদ ইনস্টলার ব্যবহার করুন, অথবা নতুন আলাদা VM-এ Mobile SSH-এর টার্মিনাল থেকে নিচের নিজে করার পথ নিন।

### SSH দিয়ে নিজে ইনস্টল করা

সরকারি [Ubuntu নির্দেশনা](https://docs.docker.com/engine/install/ubuntu/) মেনে Docker Engine ও তার Compose প্লাগইন ইনস্টল করুন। তারপর সংস্করণনির্দিষ্ট আপস্ট্রিম কনফিগারেশন ডাউনলোড করুন:

```sh
sudo mkdir -p /opt/wg-easy
sudo curl -fL https://raw.githubusercontent.com/wg-easy/wg-easy/v15.4.0/docker-compose.yml -o /opt/wg-easy/compose.yaml
```

চালুর আগে প্রশাসনিক ক্ষমতাসহ টার্মিনাল সম্পাদক দিয়ে `/opt/wg-easy/compose.yaml` সম্পাদনা করুন। `services.wg-easy`-এর নিচে ইমেজ বদলান, environment ব্লক আনকমেন্ট/সেট করুন এবং পোর্ট ম্যাপিং নিচের মান দিয়ে প্রতিস্থাপন করুন। স্থায়ী ভলিউম, মডিউল মাউন্ট, ক্ষমতা, নেটওয়ার্ক ও sysctls-সহ আপস্ট্রিম ফাইলের বাকি অংশ রাখুন:

```yaml
image: ghcr.io/wg-easy/wg-easy:15.4.0@sha256:0e7bc9d34e86ddcaa92bc700d4d7dc9b33291dbc07ac8d13382f7c2095f949ec
environment:
  - INSECURE=true
ports:
  - "51820:51820/udp"
  - "127.0.0.1:51821:51821/tcp"
```

এটি প্রতিস্থাপনের অংশ, সম্পূর্ণ Compose ফাইল নয়; সেবার নিচে YAML ইন্ডেন্ট ঠিক রাখুন। `INSECURE=true` শুধু লুপব্যাক SSH টানেলের জন্য HTTP অনুমোদন করে। প্রশাসক পোর্ট ইন্টারনেটে প্রকাশ করবেন না। কনটেইনারের লিসেনার হোস্টের লুপব্যাক ম্যাপিং থেকে আলাদা। আপস্ট্রিমের [HTTP কনফিগারেশন](https://wg-easy.github.io/wg-easy/latest/examples/tutorials/reverse-proxyless/) দেখুন।

```sh
cd /opt/wg-easy
sudo docker compose -f compose.yaml config --quiet
sudo docker compose -f compose.yaml up -d
sudo docker compose -f compose.yaml ps
```

কনটেইনারের `/etc/wireguard` ডেটা স্থায়ী ভলিউমে রাখুন। পুরোনো `PASSWORD`, `PASSWORD_HASH` বা `WG_HOST` নির্দেশনা v15-এ প্রয়োগ করবেন না; তার সেটআপ উইজার্ড ব্যবহার করুন। ইমেজ ইচ্ছাকৃতভাবে পিন করা: আপগ্রেডে নতুন সংস্করণ পর্যালোচনা করে পিন বদলাতে হবে, শুধু `pull` চালালেই হবে না।

## প্রশাসক UI খুলে ক্লায়েন্ট যোগ করুন

Mobile SSH-এ স্থানীয় পোর্ট `51821`, দূরের হোস্ট `127.0.0.1` ও দূরের পোর্ট `51821` দিয়ে [স্থানীয় পোর্ট ফরওয়ার্ড](../port-forwarding/) তৈরি করুন। SSH সংযোগ চালু রেখে একই ফোনে `http://127.0.0.1:51821` খুলুন। স্থানীয় পোর্ট ব্যস্ত থাকলে অন্য পোর্ট বেছে ব্রাউজারের URL-এ সেটি দিন।

wg-easy-এর [প্রথমবারের উইজার্ডে](https://wg-easy.github.io/wg-easy/latest/guides/setup/) প্রশাসক অ্যাকাউন্ট তৈরি করুন, নতুন ইনস্টল বেছে VPN এন্ডপয়েন্টে VM-এর সর্বজনীন IPv4 বা DNS নাম এবং পোর্ট `51820` দিন। VPN এন্ডপয়েন্ট ওয়েব UI-এর লুপব্যাক ঠিকানা বা পোর্ট `51821` নয়।

প্রতি ডিভাইসের জন্য একটি ক্লায়েন্ট তৈরি করে তার WireGuard `.conf` ডাউনলোড করুন। আপনার Mobile SSH বিল্ডে সুবিধাটি থাকলে **VPN → WireGuard** খুলুন, প্রোফাইল যোগ করুন, ফাইল আমদানি করে সেভ করুন। বর্তমান Android ও iOS সোর্সে ফাইল আমদানি আছে; নিজের ইনস্টল করা বিল্ড দেখুন। স্থানীয় Android-এর সম্মিলিত পদ্ধতি সরাসরি আমদানি করতে পারে, কিন্তু পুরোনো প্লাগইন বা iOS স্বয়ংক্রিয় ব্যবস্থার জন্য এটি প্রতিশ্রুতি নয়। কনফিগারেশন ফাইল ও QR কোডে ব্যক্তিগত কী থাকে; গোপন রাখুন।

## VPN যাচাই ও ব্যর্থতা সামলানো

প্রোফাইল চালু করে অপারেটিং সিস্টেমের VPN অনুরোধ অনুমোদন করুন। সাম্প্রতিক পিয়ার হ্যান্ডশেক ও বাড়তে থাকা ট্র্যাফিক কাউন্টার দেখুন, তারপর DNS এবং কাঙ্ক্ষিত ইন্টারনেট বা ব্যক্তিগত নেটওয়ার্ক রুট পরীক্ষা করুন। আমদানি করা প্রোফাইল বা চলা কনটেইনার একাই কার্যকর VPN-এর প্রমাণ নয়।

- **VM তৈরি অস্বীকৃত:** বিলিং, কোটা, অঞ্চলের ক্ষমতা, পরিচয়পত্রের মেয়াদ ও সুনির্দিষ্ট IAM অনুমতি দেখুন। Google Cloud ফায়ারওয়াল লেখার জন্য Network Admin-এর বাইরে অনুমতি দরকার।
- **SSH সময় শেষ:** সর্বজনীন ঠিকানা, সাবনেট রাউটিং, TCP 22 নিয়ম ও ফোনের বর্তমান উৎস IP দেখুন। প্রমাণীকরণ ব্যর্থ হলে সাধারণত সঠিক ইমেজ ব্যবহারকারীর নাম ও SSH কী লাগে।
- **প্রশাসক UI অনুপলব্ধ:** SSH ফরওয়ার্ডিং সংযুক্ত রাখুন, কনটেইনারের অবস্থা ও লুপব্যাক পোর্ট ম্যাপিং দেখুন এবং HTTP শুধু টানেলের জন্য চালু আছে নিশ্চিত করুন।
- **WireGuard হ্যান্ডশেক নেই:** ক্লায়েন্ট এন্ডপয়েন্ট, দুই ফায়ারওয়াল স্তরে UDP 51820, ক্লায়েন্ট কী এবং সার্ভার শুনছে কি না দেখুন।
- **হ্যান্ডশেক আছে, ট্র্যাফিক নেই:** ফরওয়ার্ডিং/NAT, DNS, রুটের সংঘর্ষ ও `AllowedIPs` দেখুন। সম্পূর্ণ টানেলের IPv4-এ `0.0.0.0/0` লাগে; IPv6 আলাদাভাবে যাচাই করুন। আপস্ট্রিম IPv6 ছাড়া VM IPv6 ইন্টারনেট বহির্গমন দিতে পারে না এবং শুধু IPv4 রুট IPv6-কে VPN-এর বাইরে রাখতে পারে।

## ক্লায়েন্ট সরান ও ক্লাউডের খরচ বন্ধ করুন

স্থানীয় প্রোফাইল ফেলার আগে wg-easy-তে ক্লায়েন্ট বাতিল করুন। Mobile SSH-এ প্রোফাইল মুছলে সার্ভারের পিয়ার কী বাতিল হয় না। VPN কনটেইনার বা স্থায়ী ডেটা সরানোর আগে দরকারি কনফিগারেশনের নিরাপদ ব্যাকআপ রাখুন।

অপ্রয়োজনীয় VM তার মালিকানা রাখা প্রভিশনার বা প্রদানকারীর কনসোলে মুছুন, তারপর থেকে যাওয়া ডিস্ক, স্ন্যাপশট, সংরক্ষিত/সর্বজনীন ঠিকানা ও নেটওয়ার্ক সম্পদ দেখুন। আলাদা Azure রিসোর্স গ্রুপ মোছার আগে তার ভেতরের সব দেখুন। সম্পর্কহীন সম্পদ প্লাগইন-পরিচালিত স্থাপনের বাইরে রাখুন।

VM বন্ধ করা, সেটআপ কাজ বাতিল বা প্লাগইন আনইনস্টল করা মানেই সম্পদ মুছে গেছে বা খরচ বন্ধ হয়েছে এমন নিশ্চয়তা নেই। কনসোলে তৈরি সম্পদ পরিষ্কার করার দায়িত্ব আপনার; মোছা নিশ্চিত হওয়া পর্যন্ত প্রদানকারীর সম্পদ ID রাখুন।
